# TURTLE GOOSE · 개발 회차 03

2026-11-12 · 테라스에서 경비의 방향을 읽는 봄

## 쟁점과 가상 토론

모와 봄을 구한 뒤 테라스 출구까지 가려면 마지막으로 경비 앞을 지나야 한다. 기존 검사에서 같은 길도 출발 시점에 따라 포획됐다. 봄의 구출이 탈출에 도움이 되고, 플레이어가 엄폐 안에서 출발할 때를 판단할 수 있는지 검토했다.

| 역할 | 제안 | 구체적 반론에 대한 응답 |
| --- | --- | --- |
| A · Unity 개발 | 경비가 테라스 순찰점을 떠나 주방 쪽을 보는 순간을 경비 상태에서 읽자. 추적이나 소리 조사에 들어가면 방향 안내를 거둔다. | B는 새 대기 시간이 두 진입로의 순찰 타이밍을 흔들 수 있다고 했다. 경비의 정지나 속도 조절 없이 현재 순찰 목표와 실제 몸 방향을 읽고, 기존 동선에서 기다리거나 바로 나갈 수 있게 한다. |
| B · 레벨·동선 | 테라스 입구의 기존 엄폐 공간을 출구로 나서기 전 판단 지점으로 삼자. 모와 봄이 모두 풀려난 뒤 이용한다. | C는 프리팹을 바꾸면 표식이 판정에서 어긋날 수 있다고 했다. 기존 엄폐 판정과 같은 박스 중심을 표식으로 쓰고, 엄폐에 접근해도 출구는 계속 주 목표로 표시한다. |
| C · 테크 아트·가독성 | 봄의 안내를 ‘경비를 보고 가요 → 돌아서려 해요 → 주방을 보고 있어요’로 표시하자. | D는 초록색을 안전 보장으로 읽을 수 있다고 했다. 방향을 문장으로 알려 주고, 발소리나 시야에 잡히면 방향 안내를 거둔다. 소음과 경계 상태는 기존 패널에 그대로 표시한다. |
| D · 사운드·서사 리듬 | 갇혀 있을 때 순찰을 지켜본 봄이 탈출 길에서 먼저 알려 준다. 경비가 몸을 돌리는 순간 기존 발소리를 한 번 사용하자. | A는 순찰을 오래 지켜보거나 음성 범위를 들락거리면 효과음이 겹칠 수 있다고 했다. 봄과 플레이어가 엄폐 근처에 있을 때 실제 회전에만 소리를 연결하고, 같은 회전에 중복 재생하지 않는다. |

## 결정과 적용

- 식당에서 두 친구를 구한 뒤 테라스 은신 표식에 가까이 가면 봄의 안내가 나온다. 경비가 회전 지점에 접근할 때와 실제로 주방 방향을 볼 때를 구분한다. 경비를 유인하면 방향 안내가 사라진다. 시야와 발소리 판정은 계속 작동한다.
- `JourneyLayout.cs`에서 기존 엄폐 공간과 경비 회전 순찰점을 참조한다. `JourneyRules.cs`는 회전 상태와 한 번의 이벤트를, `JourneyPlay.cs`는 경비 위치의 기존 발소리를 담당한다. `JourneyText.cs`와 `MarshHud.cs`에 양언어 안내와 엄폐 표식을 연결했다. 저장 형식과 순찰 경로는 이전과 같다.

## 실행한 검증

- .NET 8에서 `dotnet run --project Tools/JourneyChecks` 실행. 기존 56개를 먼저 통과했고, 변경 뒤 **67개 검사**가 통과했다. 회전 예고와 실제 방향 및 효과음 이벤트의 위치, 근처 엄폐물 판정, 중복 이벤트 차단, 울음으로 경비를 유인했을 때 안내 철회를 검사했다. 회전에 맞춰 일반 걸음으로 출구에 도달해 네 동료를 수로로 데려갔다. 봄만 구했을 때와 체크포인트를 불러온 뒤의 상태도 확인했다.
- 화물장과 식당의 배식종·환기구 두 경로, 수로의 수문 및 전원 승선, 실제 포획 후 재시도, 완료 저장 재개, 로컬 4인 LAN 루프백을 재검증했다. 한국어 안내에 쓰인 음절이 동봉 폰트에 있는지 확인했다. 효과음은 이벤트와 기존 클립 연결까지 확인했다.
- Unity 6 Play Mode, 실제 음량·표식 타이밍, Windows 빌드, 에디터 재시작 후 PlayerPrefs, 외부 플레이테스트, 실제 교체 프리팹은 실행하지 못했다.
