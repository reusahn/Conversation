# TURTLE GOOSE · 개발 회차 01
2026-11-10 · Unity 프로토타입 0.3 · 등불 식당 구출 작전

## A–D 토론 요약

아래는 가상 역할 네 명의 실제 검토 흐름을 정리한 기록이다.

| 역할 | 제안과 응답 |
| --- | --- |
| A · Unity 개발 | 호숫가 탈출 뒤 화물장, 식당, 수로를 한 캠페인으로 연결한다. 구조한 친구가 다음 구역에서도 따라오고, 모두 모여야 탈출이 가능해야 한다. B가 지적한 좁은 길에서의 동료 걸림을 피하도록 경비와 동료가 같은 장애물 좌표를 읽게 한다. |
| B · 3D 및 레벨 | 화물장은 움직이는 엄폐물, 식당은 두 진입로, 수로는 합류와 승선으로 구별한다. 공간 전환을 위해 수집품을 반복해서 요구하면 구출의 긴장이 끊긴다. C의 제안대로 수레는 판정까지 이동시키고, 프리팹을 교체해도 동선 좌표를 공유한다. |
| C · 테크니컬 아트 | 아트 교체 전에도 벽, 엄폐물, 경비 시야와 구조 진행을 알아볼 수 있게 한다. D가 제안한 소음 창은 화면 밖에서도 읽을 수 있어야 한다. 종의 청록색 파동과 경비의 주황색 시야를 구분하고, 소음 상태와 남은 시간을 HUD에 표시한다. |
| D · 사운드 및 서사 | 호숫가를 빠져나온 직후 새 친구의 울음으로 이야기를 이어 간다. 식당에서는 종소리, 구출, 수로의 잠깐의 정적으로 리듬을 바꾼다. C의 지적을 반영해 종은 보통 발소리만 가리고 시야는 유지한다. 아구스의 환기구 통과는 옆문을 한 번 여는 행동으로 정리한다. |

## 적용한 결정

- 화물장에서 보리를 구하면 보리가 식당으로 갈 이유를 전한다. 식당에서는 아구스를 환기구로 보내 옆문을 열거나 배식종이 울릴 때 북쪽 통로로 들어가 모와 봄을 구한다. 수로에서는 수문을 열고 구한 친구들을 함께 배까지 데려간다.
- 구출, 선택한 옆문, 열린 수문, 캠페인 완료는 체크포인트에 남긴다. 포획 후 재시도 시 경비의 경계, 소음과 기술 대기시간은 초기화한다.
- `JourneyRules`와 `JourneyNavigation`은 Unity 없이 입력과 상태를 검증할 수 있다. `JourneyLayout`에 동선 좌표를 모았다. `JourneyPlay`와 `JourneyStage`는 기존 캐릭터와 음원을 연결하고, 세 구역의 배경 프리팹을 Inspector에서 교체할 수 있게 했다.

## 검증

- Unity API 참조를 사용한 런타임 C# 컴파일에서 오류와 경고가 없었다.
- .NET 8의 30Hz 입력 시뮬레이션에서 식당 두 경로 각각 화물장 이후의 수로 승선까지 확인했다. 짧게 E를 놓으면 구출 작업이 초기화되는지, 소음 창 안에서도 시야에 포착되는지, 실제 포획 뒤 재시도에 구조 결과가 보존되는지도 확인했다.
- 호스트와 클라이언트 셋이 한 PC의 루프백으로 접속해 역할 슬롯을 할당받고, 원격 입력에 따른 위치를 공유했다.
- Unity 6 에디터 실기동, 별도 세션에서 PlayerPrefs 읽기, 외부 플레이테스트, 실제 아트 프리팹 교체는 미검증이다. 시뮬레이션에서 배식종 경로의 마지막 통과는 경비 타이밍에 민감했다.

## 다음 회차의 쟁점

배식종 경로의 첫 안전 지점과 출구 직전의 경비 회전이 화면에서 얼마나 잘 읽히는지 확인한다. 구출한 보리가 다음 구역에서 길을 알려주는 순간을 플레이 행동으로 연결하는 방안도 검토한다.
