# TURTLE GOOSE · 개발 회차 08 · 2026-11-17

## 쟁점과 가상 토론

식당에서 모와 봄은 어느 순서로든 구할 수 있다. 그런데 한 친구를 구하고 테라스 출구에 먼저 닿으면, 출구 안내는 두 친구를 구하기 전과 똑같이 모두를 구하라고만 했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| A · Unity 개발 | 기존 우리 해제 상태로 아직 남은 친구를 구분한다. | B는 구조 순서를 강제할 수 있다고 했다. 두 순서 모두 같은 방식으로 읽고 출구 잠금과 목표는 기존 규칙을 사용한다. |
| B · 레벨·동선 | 잠긴 출구에 도착한 순간, 되돌아가 구할 친구의 이름을 보여준다. | C는 새 표식이 기존 구조 목표와 겹친다고 했다. 출구의 한 줄 안내만 바꾸고 우리 목표 표식을 유지한다. |
| C · 테크 아트·가독성 | 식당은 모와 봄, 화물장은 보리를 구체적으로 적자. | D는 수로에서도 친구 구출 문구를 쓰면 다음 행동이 헷갈린다고 했다. 수로는 기존 수문 안내를 쓴다. |
| D · 사운드·서사 리듬 | 이름을 먼저 보여 구출을 기억할 계기를 주자. | A는 출구를 반복해서 오가면 음성이 겹친다고 했다. 기존 텍스트 안내에만 적용한다. |

## 결정과 코드

`JourneyText.cs`가 현재 구역과 실제 구조 상태에 맞는 한영 문구를 고르고 `MarshHud.cs`가 잠긴 출구의 기존 안내에 연결한다. 보리는 화물장에서, 모와 봄은 식당에서 안내한다. 두 친구를 구조하고 모이면 기존 흐름으로 수로에 진입한다. `Tools/JourneyChecks/Program.cs`에 두 구조 순서와 구역별 문구 회귀 검사를 추가했다.

## 실행한 검증

- .NET 8 JourneyChecks 84개 통과. 보리, 모와 봄 모두 미구조, 모만 구조, 봄만 구조, 수문 안내를 검사했다. 화물장과 식당 두 경로, 테라스 안내, 수로 승선, 포획 후 재시도, 완료 상태 재개, 로컬 4인 LAN 루프백도 다시 통과했다.
