# TURTLE GOOSE · 개발 회차 02
2026-11-11 · 보리가 알려주는 식당 첫 은신 위치

## 쟁점과 가상 토론

화물장에서 구한 보리가 식당의 단서를 전해도, 배식종을 누른 직후에는 목적지가 모의 우리로 바로 표시된다. 첫 통과 지점을 알려주면 보리의 구출이 다음 잠입 행동으로 이어진다.

| 역할 | 제안 | 구체적 반론에 대한 응답 |
| --- | --- | --- |
| A · Unity 개발 | 플레이어가 배식종을 누르면 보리의 안내를 켠다. 표식에 닿으면 구조 목표로 돌아온다. | B가 지적한 두 경로의 자유를 위해 은신 위치는 선택 사항으로 둔다. 환기구를 열거나 먼저 모를 구해도 진행되고 체크포인트 형식은 그대로 쓴다. |
| B · 레벨·동선 | 북쪽 문을 건너자마자 주방 벽을 끼고 꺾는 자리에 기존 엄폐 판정을 쓰는 공간을 둔다. | C가 지적한 표식과 판정의 불일치를 피하려고 엄폐 범위와 표식이 같은 좌표를 쓰게 한다. 표식의 좌표에 닿는 동선을 닫힌 옆문 상태에서도 검사한다. |
| C · 테크 아트·가독성 | 기존 목표 표시를 민트색 은신 표식으로 잠깐 바꾸고, 종이 울리는 동안 남은 소음 시간을 보여준다. | D가 지적한 시간 초과 오해를 피하려고 종이 멎어도 은신 표식은 유지한다. HUD에 경비 시야가 유효하다는 문구를 함께 둔다. |
| D · 사운드·서사 리듬 | 안내를 보리의 짧은 대사로 제시해 화물장에서 구한 친구가 식당에서 길을 알려주게 한다. 기존 종소리가 통과 타이밍을 맡는다. | A가 우려한 반복 안내를 피하려고 수동으로 종을 눌렀을 때만 표시한다. 주기적으로 울리는 종이나 은신 위치에 도착한 뒤 다시 울리는 종은 구조 목표를 바꾸지 않는다. |

## 결정과 적용

- 식당 입구에서 E로 배식종을 울리면 보리가 북쪽 문 안의 첫 엄폐 위치를 가리킨다. 엄폐에 들어가면 우리 위치가 다시 표시된다. 소음은 평소 발소리를 가리고 시야 판정은 계속 작동한다.
- `JourneyLayout.cs`에 엄폐 중심과 범위를 추가하고 `JourneyRules.cs`에서 표식의 활성화와 도착을 처리한다. `JourneyText.cs`와 `MarshHud.cs`에 두 언어의 안내, 은신 표식과 남은 소음 시간을 연결했다.
- `Tools/JourneyChecks/Program.cs`에 재현 검사를 추가했다. 식당 프리팹을 제작할 때는 `KitchenShelter`와 북쪽 통로를 비워 두도록 인계 문서에 적었다.

## 실행한 검증

- .NET 8에서 `dotnet run --project Tools/JourneyChecks`를 실행했다. 30Hz 규칙 검사 **56개 통과**. 수동·자동 종의 구분, 소음이 끝난 뒤 표식 유지, 실제 엄폐 진입과 목표 복귀, 체크포인트 형식 유지, 환기구 경로를 확인했다.
- 화물장에서 시작해 식당의 두 경로에서 모와 봄을 구하고 수로에서 모두 승선했다. 실제 포획 후 재시도와 완료 상태 재개, 로컬 호스트와 클라이언트 셋의 역할 배정 및 위치 동기화도 통과했다. 소음 중 경비가 시야로 플레이어를 감지하는 조건을 다시 확인했다.
- 추가한 한국어 대사와 표식의 글자는 포함된 폰트의 문자표에서 확인했다. Unity 6 Play Mode, Windows 빌드, 에디터 재시작 후 PlayerPrefs, 외부 플레이테스트, 실제 프리팹 교체는 이번에 실행하지 못했다.
