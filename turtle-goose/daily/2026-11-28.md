# TURTLE GOOSE · 개발 회차 19 · 2026-11-28

## 쟁점과 가상 토론

첫 Windows 실행본의 목표일이다. 최신 계획·지원 초안·QA와 Fellowship 빌드 도구를 확인했다. Unity가 없어 첫 단계가 미완료이며, 기존 실행 도구는 경로를 반드시 직접 입력해야 했다. 프로젝트 버전과 Hub 설치를 자동으로 연결하는 선행 작업을 진행했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| A · Unity 개발 | 프로젝트 버전 파일을 읽어 Hub의 해당 에디터를 찾자. | C는 다른 버전으로 프로젝트가 바뀔 수 있다고 했다. 정확한 버전의 후보만 선택하고 직접 경로 지정도 허용한다. |
| B · 레벨·동선 | 첫 실행본을 만들 환경을 찾는 데 필요한 단계를 줄이자. | A는 에디터 발견 자체가 씬 컴파일이나 Windows 지원 모듈 확인은 아니라고 했다. 실제 빌드 호출과 결과 검사는 기존 도구에서 계속 수행한다. |
| C · 테크 아트·가독성 | 버전 정보가 없으면 추정하지 말고 이유를 기록한다. | D는 실패가 조용히 끝나면 작업 인계가 어렵다고 했다. 검색한 경로와 요청 버전을 차단 보고서에 담는다. |
| D · 사운드·서사 리듬 | 실제 영상 이전의 첫 기동 근거를 우선한다. | B는 탐색 통과가 영상이나 기동 증거처럼 보일 수 있다고 했다. launchVerified와 QA를 미검증으로 유지한다. |

## 결정과 실제 변경

`Tools/Fellowship/build_windows.py`에서 --unity를 생략하면 ProjectVersion의 정확한 버전을 Hub 기본 경로에서 찾는다. 다른 위치의 실제 에디터는 기존 옵션으로 지정한다. `test_build_windows.py`에 버전 불일치, 정확한 버전 발견, Mac 경로 형태와 버전 파일 누락 검사를 추가했다. 계획과 비공개 차단 결과를 갱신했다.

## 실행한 검증과 막힌 단계

- Python unittest 24개 통과. 도구 모의 검사 10개와 기존 패키지 구조 검사 14개다. 에디터 탐색 검사의 파일은 실행하지 않는 임시 표식이다. 실제 Unity나 실행 가능한 게임을 만든 검사가 아니다.
- 실제 탐색은 Unity 6000.0.58f2를 찾지 못해 blocked였다. Unity 프로세스·컴파일·Windows 플레이어 빌드·새 압축 해제 후 기동은 실행되지 않았다.
- QA 전 항목 PENDING과 launchVerified=false를 확인했다. 오늘의 첫 실행본 목표는 현재 미완료다. 다음 실제 작업에는 Unity 에디터와 Windows Build Support가 있는 환경이 필요하다.
- ZIP 무결성과 지정 파일만 변경됨을 확인했다. 게임 규칙·아트·비공개 지원 자료를 보존했고 게임 시뮬레이션과 LAN 루프백은 이번 도구 변경에서 재실행하지 않았다.
