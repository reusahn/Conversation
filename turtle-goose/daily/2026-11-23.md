# TURTLE GOOSE · 개발 회차 14 · 2026-11-23

## 쟁점과 가상 토론

이전 회차의 우리 개방 소리도 사용하는 공통 소리 처리에서, 높은 경계도가 새 소리 때문에 0.78로 내려갈 수 있었다. 근처에서 울거나 우리를 열어 경비의 경계도를 낮추는 결과가 생긴다. Unity 실기동 과제는 에디터를 찾을 수 없어 보류하고 이 잠입 규칙을 수정했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| A · Unity 개발 | 새 소리는 기존 경계도를 낮추지 못하게 하자. | B는 평소 작은 소리가 바로 최대 경계를 만들 수 있다고 했다. 기존 작은 증가량과 소리로만 도달하는 상한을 사용하고 이미 높은 경계도만 보존한다. |
| B · 레벨·동선 | 종·울음·우리 개방이 같은 경계 원칙을 따르게 한다. | C는 모든 경비가 동시에 반응할 수 있다고 했다. 기존 소리 반경과 벽 감쇠는 그대로 적용한다. |
| C · 테크 아트·가독성 | 기존 경계도 막대와 실제 상태가 일치하게 하자. | D는 새로운 경고음이 구조 장면과 겹칠 수 있다고 했다. 기존 막대와 효과음만 사용한다. |
| D · 사운드·서사 리듬 | 경비 앞에서 소음을 내는 선택의 위험을 일관되게 만들자. | A는 경계도가 영구히 고정될 수 있다고 했다. 자연 감소와 시야 감지 로직은 계속 동작하고 새 소리 순간에만 감소를 막는다. |

## 결정과 검증

`JourneyRules.cs`에서 소리로 경계도를 갱신할 때 기존 값 이상을 유지한다. `Tools/JourneyChecks/Program.cs`에서 테라스의 순찰에 실제로 노출돼 높은 경계도를 만든 뒤 울음 입력을 넣어 검사했다.

- .NET 8 JourneyChecks 108개 통과. 실제 시야 감지와 높은 경계 상태를 확인한 뒤, 울음 이벤트 순간 경계도가 이전보다 낮아지지 않음을 검사했다. 기존 규칙에서는 같은 검사가 실패했다.
- 우리 개방 소리와 배식종 차폐, 엄폐 구르기, 화물장과 식당 두 경로, 수로·구조·재시도·완료 저장 재개 및 로컬 4인 LAN 회귀도 통과했다.
- ZIP 무결성과 C# 두 파일 및 이 기록만 바뀜을 확인했다. Unity 화면·음향·실제 난이도, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트 및 프리팹 교체는 미검증이다.
