# TURTLE GOOSE · 개발 회차 16 · 2026-11-25

## 쟁점과 가상 토론

모를 구한 체크포인트를 불러와도 새 식당 진입 때의 이야기가 나왔다. 플레이어는 이미 안에 있고 모가 동행하는데, 다시 환기구 너머의 친구들을 찾는 설명을 듣게 됐다. Unity의 새 빗장 화면 검사는 에디터가 없어 미검증으로 남겼다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| A · Unity 개발 | 진입 자막이 현재 구조와 문 개방 상태를 읽게 하자. | B는 저장 형식을 바꾸면 이전 파일과 충돌한다고 했다. 기존 체크포인트 플래그만 사용한다. |
| B · 레벨·동선 | 모가 동행하면 빗장 단서와 봄의 구조를 이어주자. | C는 이미 옆문을 열었어도 빗장을 다시 열라고 할 수 있다고 했다. 열린 문에서는 남은 친구의 우리를 안내한다. |
| C · 테크 아트·가독성 | 기존 진입 자막 위치에 맞는 한영 문장을 사용한다. | D는 반복 설명이 길면 재시도 리듬을 해친다고 했다. 진행한 상태에서는 현재 행동만 짧게 설명한다. |
| D · 사운드·서사 리듬 | 구출한 친구와 동행을 이어가는 감각을 재시도 때도 남기자. | A는 음향까지 새로 추가하면 검증 범위가 커진다고 했다. 기존 진입 음향과 자막 시간을 사용한다. |

## 결정과 코드

`JourneyText.cs`에 현재 규칙 상태를 받는 진입 안내를 추가하고 `JourneyPlay.cs`의 진입 자막에 연결했다. 보리를 구한 화물장에서는 출구를, 모가 동행하고 옆문이 닫힌 식당에서는 모의 빗장 단서와 봄을, 문이 열렸거나 다른 친구를 먼저 구한 상태에서는 남은 목표를 안내한다. 모두 구했으면 테라스, 수문이 열렸으면 배를 안내한다.

## 실행한 검증

- .NET 8 JourneyChecks 122개 통과. `Tools/JourneyChecks/Program.cs`에서 저장값을 실제로 해석해 규칙을 생성하고, 보리 구조·모 구조와 닫힌 문·열린 문·봄 우선 구조·전원 구조·수문 개방 상태의 안내를 검사했다.
- 기존 진입 안내를 사용하는 비교 코드에서는 구조한 화물장의 출구 안내 검사가 실패했다. 빗장 개방·퇴각·재진입, 식당 두 경로, 구조·수로·포획 후 재시도·완료 저장 재개 및 4인 LAN 루프백도 회귀 검사를 통과했다.
- 새 한글 문구의 동봉 글꼴과 ZIP 무결성을 검사했다. C# 세 파일과 이 기록만 바뀌었다. Unity 화면·음향, PC 빌드, 에디터 재시작 후 실제 PlayerPrefs 저장, 외부 플레이테스트, 실제 프리팹 교체는 미검증이다.
