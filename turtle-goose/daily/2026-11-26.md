# TURTLE GOOSE · 개발 회차 17 · 2026-11-26

## 쟁점과 가상 토론

Fellowship 우선순위의 첫 미완료 단계는 Unity 컴파일과 실제 Windows 플레이어 빌드·새 압축 해제본 기동이다. 최신 제출 준비 파일과 에디터 빌드 코드, 패키지 도구를 읽었다. 이 환경에서는 Unity 실행파일을 찾지 못했다. 기존 빌드 메뉴에 연결해 실제 에디터 호출 실패와 빌드 결과를 기록하는 실행 도구를 선행 작업으로 만들었다.

## 결정과 실제 변경

- `Tools/Fellowship/build_windows.py`는 실제 Unity 에디터에 기존 `FellowshipBuild.WindowsBatch`를 호출한다. 에디터 누락, 비정상 종료, 시간 초과, 종료 코드 0이지만 실행본·영수증이 없는 경우를 구분한다. 실제 출력의 빌드 ID와 Windows 대상을 확인하고 기동 검증은 추가하지 않는다.
- `test_build_windows.py`에 모의 프로세스 경계 검사 6개를 추가했다. `Submission/Fellowship/PLAN_KO.md`에 실행 방법과 현재 미완료 상태를 기록했다. 비공개 프로젝트 안에 차단 결과 JSON을 보존했다. 게임 규칙과 아트는 수정하지 않았다.

## 실행한 검증과 막힌 단계

- Python unittest 20개 통과. 새 실행 도구 6개와 기존 패키지 검사 14개다. 모의 프로세스와 임시 구조 검사이며 Unity 빌드나 플레이 근거가 아니다. 새 도구 검사는 실행 가능한 가짜 플레이어를 만들지 않는다.
- 실제 명령행 도구 실행은 지정한 에디터 파일을 찾지 못해 blocked로 끝났다. 실제 Unity 프로세스가 시작되지 않았고 컴파일·Windows 플레이어 생성·새 압축 해제 후 기동은 모두 미검증이다.
- launchVerified=false와 QA_CHECKLIST.csv의 전 항목 PENDING을 확인했다. 11월 28일 첫 실행본은 목표 일정이다. 기동·빌드 완료 실적은 없다.
- ZIP 무결성과 변경 대상만 교체된 것을 검사했다. 최신 입력 ZIP의 지원 초안·PDF·아트·소스와 다른 변경을 보존했다. 기존 .NET 게임 규칙과 4인 루프백은 이번 도구 변경에서 재실행하지 않았다.
