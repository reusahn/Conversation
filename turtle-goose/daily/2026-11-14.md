# TURTLE GOOSE · 개발 회차 05

2026-11-14 · 배에서 마지막 친구를 기다리기

## 쟁점과 가상 토론

식당에서 구한 친구를 배에 데려가는 수로 마지막 구간에서, 3 / 4라는 숫자만으로는 누가 아직 오지 않았는지 알기 어렵다. 이전 회차의 테라스 표식·음향과 승선 표시의 Unity 실기동 확인은 에디터를 사용할 수 없어 보류했다.

| 역할 | 제안 | 반론에 대한 응답 |
| --- | --- | --- |
| A · Unity 개발 | 실제 승선 반경 밖에 남은 동료를 찾아 이름을 넘기자. | C는 승선 조건과 이름이 다른 거리 기준을 쓸 수 있다고 지적했다. 두 계산이 같은 반경 판정을 호출하게 한다. |
| B · 레벨·동선 | 배 앞에서 마지막 한 명일 때만 이름을 보여주자. | D는 멀리 떨어진 동료의 이름을 보면 돌아가서 데려오라는 강제 목표로 읽힐 수 있다고 했다. 이동 표식이나 별도 목표 없이 기존 승선 안내에 대기 상태만 적는다. |
| C · 테크 아트·가독성 | 기존 숫자 옆에 동료 이름을 같은 줄로 붙이자. | B는 여러 이름이 동시에 나오면 숫자보다 읽기 어렵다고 했다. 두 명 이상 늦으면 숫자만 표시하고, 이름은 기존 양언어 캐릭터 표기를 재사용한다. |
| D · 사운드·서사 리듬 | 마지막에 모이는 친구의 이름으로 구조 장면을 떠올리게 하자. | A는 출입 경계에서 안내음이 반복될 수 있다고 했다. 기존 대기 문구만 갱신하고 새 음향이나 대기 시간을 두지 않는다. |

## 결정과 변경

- 수문을 열고 배 앞에 도착했을 때 한 명만 반경 밖이면 인원 수와 함께 그 친구 이름을 표시한다. 여러 명이면 숫자만 나온다. 마지막 친구가 들어오면 기존 승선 안내로 전환한다.
- `JourneyRules.cs`의 승선 반경을 이름 판정에도 사용하고, `JourneyText.cs`와 `MarshHud.cs`에 안내를 연결했다. `Tools/JourneyChecks/Program.cs`에 회귀 검사 네 개를 추가했다.

## 실행한 검증

- .NET 8 JourneyChecks에서 기준본 71개, 수정본 75개 통과. 둘이 늦을 때 숫자만 표시, 마지막 한 명의 한영 이름, 도착 뒤 이름 해제, 구조 전 캐릭터 제외를 검사했다. 화물장, 배식종·환기구 두 경로와 수문·승선, 포획 후 재시도, 완료 저장 재개, 로컬 4인 LAN 루프백도 통과했다.
- 동봉 한글 글꼴의 안내 글자와 ZIP 무결성을 확인했다. 변경은 C# 파일 네 개와 이 개발 기록이다. Unity Play Mode, 화면·소리 타이밍, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 교체 프리팹은 미검증이다.
