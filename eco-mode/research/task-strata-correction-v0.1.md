# 독립 벤치마크의 과제 분류 보완 v0.1

2026-10-28. 이번 A–E 공개 검토에서 채택한 설계 보완이다. 실제 과제의 난도·성능·에너지는 측정하지 않았으며 최종 과제집·p_min·반복 수는 확정하지 않았다. protocol-v3의 RQ3 해석에서 ‘low 불충분’을 ‘high 필요/유효’와 동일시하지 않도록 한다. 기존 활성 참가자 분석 코드는 변경하지 않는다.

## 발견한 문제

낮은 추론 예산의 성공률이 부족하다는 근거만으로 높은 예산이 문제를 해결한다고 결론낼 수 없다. 두 모드가 모두 실패하는 과제, 차이가 불확실한 과제가 있다. 구조적 복잡성, 사람이 느끼는 난도, low 단독 성능, high 단독 성능은 서로 다른 변수이다.

이 보완은 동일 모델의 고정된 두 모드를 비교한다. 모든 가능한 모델·프롬프트·수동 방법 중 high가 필수라는 결론은 목표가 아니다.

## 동일한 성공기준과 독립 자료

모델 단독 벤치마크는 사람이 상호작용하는 본실험과 독립된 반복 자료를 사용한다. 정한 태스크 계약·최종 응답 추출·채점 버전·허용된 모드 차이·입력·샘플링 정책을 고정한다. 모드별 특정 성공 실행만 남기거나, 정답을 얻을 때까지 재시도한 결과를 단독 성공률로 세지 않는다. 정해진 실행 수와 모든 시도의 결과·unknown을 보존한다.

각 고정 task j에 대해 low와 high의 단독 성공확률을 p_lj, p_hj로 정의한다. 이 값은 참가자가 여러 번 질문하고 직접 편집한 최종 산출물 성공률과 다르다. 동일한 ‘과제 성공’ 계약을 사용해도 실행 정책·모집단이 다르므로 서로 대체할 수 없다.

사전 성공기준 p_min은 사용 맥락과 실패 비용에 근거해 명칭 효과를 보기 전에 정한다. 지금 임의 숫자로 채우지 않는다. 벤치마크 실행 수·정지 규칙·interval 방법·오류 수준도 데이터를 유리하게 분류하기 전에 고정한다. 모집 가능한 표본이나 관측 결과에 맞춰 p_min을 바꾸지 않는다.

## 분류 규칙

각 task-mode의 성공확률 구간을 [L_lj,U_lj], [L_hj,U_hj]라고 한다. 아래 규칙을 위에서부터 적용한다.

| 분류 | 조건 | 허용되는 표현 |
|---|---|---|
| low 기준 충족 | L_lj >= p_min | 고정한 low 단독 정책이 사전 성공기준을 충족한다는 근거가 있음 |
| high에서 기준 충족 확인 | U_lj < p_min 이고 L_hj >= p_min | low는 기준 미달, high는 기준 충족이라는 근거가 함께 있음 |
| 두 모드 모두 기준 미달 | U_lj < p_min 이고 U_hj < p_min | 비교한 두 고정 모드 모두 사전기준 미달이라는 근거가 있음 |
| 미분류 | 위 조건을 충족하지 못함 | 현재 자료로 분류를 확정하지 못함 |

네 범주는 서로 배타적이다. low가 기준을 충족하면 high가 얼마나 잘하는지와 무관하게 첫 범주다. high가 항상 low 이상이라는 단조성을 가정하지 않는다. high 성과가 더 낮은 관측도 그대로 보고한다. 임계값과 맞닿은 U_lj=p_min을 기준 미달로 단정하지 않는다.

두 모드 모두 기준 미달인 task에서 high가 조금 개선될 가능성을 부정하는 것은 아니다. 반대로 low 기준 충족 범주에서도 high의 성능 이득이 있을 수 있다. 이 분류는 임계값 충족을 구분하며 모든 성능 차이를 요약하지 않는다. ‘의미 있는 향상폭’을 추가 주장하려면 별도로 근거 있는 차이 기준과 분석을 사전에 정해야 한다.

## 구간의 공동 보장과 누락

K_b개의 고정 벤치 task 전체에서 모드 두 개를 분류한다면, 전체 2K_b개 구간이 함께 참값을 포함하는 사건을 대상으로 오류를 통제한다. 예를 들어 각 양측 구간의 실패확률을 beta/(2K_b) 이하로 두면 union bound에 의해 전체 포함확률은 1-beta 이상이다. 양측 CP를 사용한다면 각 꼬리는 beta/(4K_b)이며, 이는 이항 iid 모형과 고정 표본/정지 규칙의 유효성에 조건부다. task나 모드 간 독립성은 union bound 자체에 필요하지 않다. 실제 자료의 이항 모형·실행 간 독립성은 설정 파일만으로 인증되지 않는다.

동시 포함 사건에서 ‘high에서 기준 충족 확인’이면 p_hj-p_lj >= L_hj-U_lj > 0도 따른다. 그러나 이것을 별도의 효과크기 검정 p값, 임상적·실용적으로 중요한 이득, 인간 최종 과제 성과의 향상 또는 high의 보편적 필요성으로 부르지 않는다. 이 문서가 본실험의 기존 네 확증 주장에 새 성공 경로를 더하는 것도 아니다.

유효한 응답의 틀림·잘림·귀속 가능한 실패와 인프라/채점 unknown을 구분한다. 성공확률 구간을 만든다면 unknown을 성공수 0 또는 전부성공으로 극단 완료한 단조적 외측 경계 등, 타당한 방법을 사전에 정한다. unknown이 있는데 완전 사례만으로 편의상 좁은 구간을 만들지 않는다. 적용 모형·누락 처리·동시성 근거가 없으면 해당 분류를 보류한다.

## 본실험과의 연결

독립 벤치 자료에서 분류를 정한 뒤 본실험의 명칭 효과를 보기 전에 task ID·분류·필수 strata를 고정한다. 본실험에서 Eco에 유리하게 보였다는 이유로 분류·과제·품질 허용폭을 바꾸지 않는다. 분류에 사용한 모델 벤치 반복을 사람 참가자 수로 세지 않는다.

두 모드 모두 기준 미달·미분류인 과제도 배정되었다면 전체 품질 분모에 남긴다. 어느 task를 실제 배정할지는 독립 과제 선정/타당화 단계에서 이유와 함께 결정하며, 이 문서는 네 개발 예제를 최종 bank로 채택하지 않는다.

RQ3는 다음처럼 구체화한다: **명칭의 선택·최종 성과·세션 에너지 효과가, low가 기준을 충족하는 과제와 high에서 기준 충족이 확인된 과제에서 어떻게 다른가?** 두 모드 모두 미달·미분류는 별도로 보존·보고한다. 충분한 독립 분류·사용자 표본 근거가 없으면 RQ3는 탐색적이며 상호작용 효과를 확증했다고 하지 않는다.

## 이번 결정의 상태

실제 p_min, beta, 반복 수, 분류 결과, 최종 K·과제 bank와 사용자 품질 허용폭은 미정이다. 수정된 것은 분류의 논리와 해석 범위다. 실제 모델 실행·센서 계측·사람 연구·새 통계 코드 검사는 수행하지 않았다. `confirmatory_allowed=false`이다.
