# LLM 연산 수준의 Eco 명칭 효과 연구계획서

이름이 환경적 기대 모드 선택과 동일 답변의 수용에 미치는 영향

안종훈 Jonghoon Ahn  |  2026년 10월 30일  |  한국어 2차 계획

## 연구 개요

본 연구는 LLM 서비스의 낮은 연산 선택지를 Light 대신 Eco라고 명명했을 때 사용자의 해석과 선택이 달라지는지 조사한다. 연구용 메뉴를 Light, Medium, High, Extra High, Max로 구성하고 낮은 설정의 이름만 바꾼 두 집단을 비교한다. 다른 설정의 이름·순서·설명과 응답 사례는 같게 유지한다.

## 중심 연구 질문

**LLM 서비스에서 동일한 낮은 연산 선택지를 Light 대신 Eco라고 명명하면 사용자의 환경적 기대, 모드 선택과 동일 답변의 수용이 어떻게 달라지는가?**

| 배정 집단 | 연구 화면의 모드 목록 |
| --- | --- |
| 중립 명칭 | Light / Medium / High / Extra High / Max |
| Eco 명칭 | Eco / Medium / High / Extra High / Max |

이 목록은 연구용 자극의 예시이며 특정 서비스의 현재 지원 설정이라고 설명하지 않는다. 첫 검증은 작성 응답을 사용하는 공개 모사 화면에서 진행하며 실제 추론이나 환경 절감이 발생한다고 안내하지 않는다.

## 측정할 세 가지 결과

- 낮은 연산 선택지를 고르는 비율
- 동일한 답과 조건 안내를 받은 뒤의 답변 수용
- 과제 후 보고하는 환경적 이익의 기대와 판단 유보

성능 양보와 확인·보완 계획은 명칭 효과를 해석하는 보조 자료로 둔다. 같은 기능 구상과 같은 응답에 붙은 이름이 핵심 비교이다. 효과가 없거나 Eco 선택이 줄어드는 결과도 보고한다.


# 1 배경과 차별화할 질문

## 연산 수준의 이름과 환경적 의미

Light 같은 이름은 처리 수준을 설명하는 표현으로 읽힐 수 있고 Eco는 환경을 고려한 선택이라는 의미를 만들 수 있다. 본 연구는 이 의미 차이가 동일한 설정의 선택과 평가에 관여하는지 검증한다. 기능의 실제 자원 효율과 명칭의 사용자 효과는 별도 질문으로 다룬다.

모드 선택, 친환경 정보와 성능 양보에는 선행연구가 있다. 이번에는 연산 수준 메뉴에서 기술적 수준명과 환경적 의미의 명칭을 비교하는 좁은 조작에 초점을 맞춘다. 이 비교가 기존 연구에 더하는 지식은 원문의 질문·자극·분석과 대조해 정리하며 최초 연구라고 단정하지 않는다. Kim 등 [7]의 지연·환경 교환과도 구분한다.

## 세부 연구 질문

- RQ1  낮은 선택지를 Eco로 명명하면 그 선택지를 고르는 비율은 Light 조건과 어떻게 다른가
- RQ2  같은 작성 답변과 조건 정보를 받은 뒤 수용·수정·전환·중단 판단은 어떻게 다른가
- RQ3  과제 후 환경적 이익의 기대와 판단 유보 및 이름의 의미 해석은 어떻게 다른가

Eco가 반드시 유리하다고 전제하지 않는다. 신뢰나 품질 기대가 낮아지거나 별 차이가 없을 가능성도 남긴다. 결과는 특정 메뉴·공통 설명·과제의 명칭 차이로 해석하고 모든 친환경 표현이나 실제 서비스 전체로 일반화하지 않는다.


# 2 비교 설계와 진행

## 두 집단 무작위 배정

참가자를 Light와 Eco 명칭 집단에 1 대 1로 무작위 배정한다. 한 참가자는 한 명칭만 본다. 기본 선택을 비워 두고 대응하는 설정의 설명, 목록 순서, 글꼴, 색과 선택 기회를 같게 유지한다. Eco 조건에만 자연 아이콘, 환경 수치나 별도 설명을 추가하지 않는다.

두 집단 모두 준비된 사례를 보는 연구이며 실제 연산·전력 절감은 검증하지 않았다고 안내한다. 이 공통 안내에 환경 정보가 포함되므로 추정하는 것은 그 안내 아래 특정 명칭이 더하는 차이이다.

## 모드 선택과 답변 평가의 분리

먼저 공통 상품 비교 작업에 사용할 모드를 선택하게 한다. 이후에는 그 선택과 별개로 모든 참가자가 낮은 설정의 같은 응답 사례를 검토한다고 명시한다. Max를 골랐더라도 낮은 설정의 평가에 참여하며 선택한 모드가 실제로 실행되었다고 안내하지 않는다.

| 단계 | 공통 절차와 기록 |
| --- | --- |
| 안내와 배정 | 동의와 기본 이용 경험 뒤 Light 또는 Eco 화면 배정 |
| 모드 선택 | 같은 작업 설명에서 다섯 모드 중 하나 또는 선택 보류 기록 |
| 동일 응답 검토 | 다른 세 과제에서 상세 정답 R 간결 정답 Q 조건 미충족 X를 하나씩 보고 초기 판단 |
| 조건 확인 | 세 초기 판단 후 공통 표와 자기 말 이해 설명 및 최종 답변 선택 |
| 환경 기대 | 과제 후 환경적 이익 기대와 판단 유보를 같은 질문으로 측정 |
| 후속 설명 | 선택 이유 이름 해석과 확인·보완 계획 탐색 |

각 명칭 집단 안에서 부록 2의 여섯 응답 순서를 가능한 한 고르게 배정한다. R·Q·X는 화면에 표시하지 않는다. 같은 순서 번호에는 같은 상품표·응답·확인표를 쓴다. 초기 낮은 모드 선택자나 사후 이해자만 골라 답변 수용을 비교하지 않는다.

약 20~30분의 운영안을 파일럿에서 조정한다. 개인의 일반적인 양보 경계와 맥락은 주된 선택 전에 길게 묻지 않고 보조 인터뷰로 둔다. 모든 참가자의 공통 응답 평가와 무작위 배정한 이름의 효과를 우선 측정한다.


# 3 측정과 분석 계획

## 주된 결과와 보조 결과

| 지표 | 기록과 비교 |
| --- | --- |
| 주된 결과 모드 선택 | 최초 선택에서 Light 또는 Eco라는 낮은 옵션을 고른 비율 차이 |
| 보조 결과 X 수용 | 조건 확인표 뒤 X 답을 고치지 않고 과제 최종 답으로 선택한 비율 |
| 보조 결과 환경 기대 | 과제 후 7점 척도와 판단 유보로 보고한 환경적 이익 기대의 전체 분포 |
| 탐색 자료 | R과 Q 수용 선택 이유 품질·신뢰 기대 이름 해석과 확인·보완 계획 |

답변 선택은 그대로 최종 답으로 선택, 직접 고친 뒤 사용하고 싶음, AI에 수정 요청하고 싶음, 다른 모드로 전환하고 싶음, 사용하지 않고 중단으로 나눈다. 수정과 전환은 실제 추가 호출을 실행하지 않는다. 간결한 정답의 수용을 품질 저하 감수로 자동 분류하지 않는다.

## 집단 비교와 결측

주된 분석은 낮은 옵션 선택 비율의 집단 간 차이와 95% 신뢰구간이다. 모든 배정자의 흐름, 결과·결측 수를 보고한다. 선택 보류는 관찰된 응답이며 미응답·철회·기록 실패는 결측으로 남긴다. 결측을 비선택이나 절감 0으로 자동 입력하지 않는다. 결측 처리·민감도 분석과 보조 결과의 다중 비교 규칙은 본 조사 전에 고정한다.

같은 결함 안내 뒤의 수용 효과와 실제 부족함 이해는 별도로 기록한다. 이해가 명확한 사람만 남긴 비교를 명칭의 인과효과로 보고하지 않는다. 이해와 수용이 함께 관찰된 비율도 필요하면 전체 배정 기준에서 제시한다.

## 측정 순서와 주장 범위

환경 기대는 모드 선택과 답변 수용 뒤에 물어 앞선 선택을 유도하는 일을 줄인다. 이는 과제 후 보고이며 초기 기대의 순수한 측정이나 환경 믿음이 선택을 매개했다는 증거로 해석하지 않는다. 사후 이유 역시 독립적인 원인 증거로 쓰지 않는다.

시나리오 버튼과 실제 서비스의 자발적 채택·장기 재시도는 구분한다. 두 번째 단계는 선택한 모드의 자연스러운 사용을 재현하지 않는다. 결과는 이 공통 설명과 순서 아래 연구용 인터페이스에 한정해 해석한다.


# 4 표본 실행 계획과 연구윤리

## 파일럿과 본 조사 표본

성인 LLM 사용자를 대상으로 한다. 소규모 파일럿에서 명칭·안내의 이해, 선택과 응답 평가의 분리, 기록 누락과 회기 부담을 점검한다. 효과가 원하는 방향인지 보고 조건을 고르거나 표본을 늘리지 않는다.

본 조사 표본은 주된 선택 비율 차이에서 의미 있게 검출할 차이 또는 원하는 신뢰구간 폭을 정한 뒤 산정한다. 완료 표본, 결측을 고려한 모집 수와 중단 규칙을 수집 전에 고정한다. 파일럿 규모와 본 조사의 효과 검정 표본은 각각 목적에 맞춰 정한다.

## 준비 순서와 예산

| 순서 | 준비할 결과 |
| --- | --- |
| 문헌과 자극 | 상세 선행 비교 Light와 Eco 메뉴 및 공통 안내 |
| 프로토타입과 파일럿 | 무작위 배정 단계 분리 같은 응답과 기록 점검 |
| 본 조사 계획 고정 | 표본 주된 지표 결측·보조 분석 보상 자료 관리 |
| 수집과 분석 | 배정 흐름과 집단 차이 반례·해석 적용 범위 |

예산은 확정한 참가자 수와 회기 시간에 맞춘 보상, 모집 플랫폼과 운영 비용으로 산정한다. 본 조사 전에 표본·회기 시간과 보상을 함께 고정한다. 첫 명칭 검증은 작성 응답을 사용하며 실시간 모델 호출은 기본 절차에 포함하지 않는다.

## 동의와 재현성

사람 대상 파일럿과 모집 전에 소속기관의 적용 절차를 확인하고 필요한 심의·동의와 자료 관리 계획을 준비한다. 실시간 AI가 아닌 사례이며 실제 환경 절감을 검증하지 않았음을 두 조건에 똑같이 안내한다. 보상은 선택이나 답변 내용과 연동하지 않는다.

배정·화면·응답·확인표·질문과 분석 규칙을 버전별로 보존한다. 기록 접근권한, 보관기간, 철회 가능 시점과 공개 범위를 모집 전에 확정한다. 식별정보와 분석자료를 분리하고 발언 공개는 동의·비식별화 검토를 따른다.

## 후속 검증

실제 Eco 기능의 사용량·전력·배출 효과는 재시도와 전환을 포함한 전체 이용 및 운영 자료로 다룬다 [5]. 개발 속도 변화는 수요·수익·투자의 별도 가설이며 경제모형 [6]을 Eco 이용의 개발 지연 실증으로 옮기지 않는다. 두 주장은 이번 명칭 효과의 성립 조건으로 두지 않는다.

## 두 집단의 공통 안내

이 연구는 LLM 채팅 서비스의 연산 수준 선택과 답변 평가를 다룹니다. 화면의 답은 준비된 사례이며 실시간 AI가 아닙니다. 실제 연산·전력·환경 차이는 측정하지 않았습니다. 먼저 사용할 모드를 고른 뒤 선택과 별개로 모두 낮은 설정의 같은 응답 사례를 검토합니다.

- 응답 판단  현재 답을 그대로 과제의 최종 답으로 선택하겠나요? 수정·전환·중단을 원하나요?
- 조건 확인  추천이 과제 조건을 어떻게 충족한다고 이해했나요? 이후 어떤 답변 선택을 하겠나요?
- 환경 기대  이 낮은 설정이 같은 작업의 환경 부담을 줄이는 데 기여할 것이라고 얼마나 예상하나요? 1 전혀 예상하지 않음부터 7 매우 예상함 또는 판단 유보.
- 자유 이유  선택한 이유는 무엇인가요? 이름에서 어떤 의미를 읽었나요? 확인·보완은 누가 맡을 계획인가요?

환경 기대는 과제 뒤 같은 문구로 묻고 전체 분포와 유보율을 보고한다. 판단 유보를 낮은 기대나 0으로 바꾸지 않는다. 추가 질문·재안내는 중립 문구와 한도로 운영하며 시점을 남긴다.


# 부록 2 집단 내 응답 순서와 기록

## 두 명칭 집단에 같은 여섯 순서

Light 또는 Eco 집단 안에서 아래 순서를 가능한 한 고르게 배정한다. 낮은 설정의 이름만 다르며 같은 번호에는 같은 상품표·응답·확인표를 쓴다. 세 초기 판단 후에 세 확인표를 제시한다.

| 번호 | T1 | T2 | T3 | 응답 제시 순서 |
| --- | --- | --- | --- | --- |
| 1 | R | Q | X | T1 → T2 → T3 |
| 2 | Q | X | R | T2 → T3 → T1 |
| 3 | X | R | Q | T3 → T1 → T2 |
| 4 | R | Q | X | T3 → T2 → T1 |
| 5 | Q | X | R | T1 → T3 → T2 |
| 6 | X | R | Q | T2 → T1 → T3 |

R은 상세 정답, Q는 간결 정답, X는 추천 하나가 조건 하나를 위반한 답이다. 유형명은 참가자에게 표시하지 않는다. X 오류의 발견 난이도가 과제마다 같다고 가정하지 않으며 응답 유형별 차이를 명칭 효과와 혼동하지 않는다.

## 필수 기록

- 참가자 코드 무작위 배정 화면·안내 버전과 응답 순서
- 최초 모드 선택 또는 보류와 미응답·철회 시점
- 세 사례의 초기 선택 확인표 뒤 이해와 최종 선택
- 과제 후 환경 기대 척도와 판단 유보
- 사후 이유 이름 해석 확인·보완 계획과 재안내
- 기록 실패 미수집 사유와 분석 처리

## 분석을 위한 원칙

자료는 최초 배정과 연결한다. 낮은 모드를 고른 사람이나 부족함을 이해한 사람만 추려 주된 인과 비교를 하지 않는다. 과제 규칙 위반은 수용해도 원래 판정을 유지한다. 자유 이유와 확인·보완 계획은 비교 결과의 의미를 해석하는 자료이며 실제 실행이나 환경적 절감의 기록으로 쓰지 않는다.
