# 운영상 피드백·사후 채점 경계 v0.1

2026-10-28. D 가상 운영 관점의 설계 보완이다. 실제 데이터센터·전력계·모델·사람 자료를 확인한 문서가 아니다. 기존 protocol-v3와 task-evaluation-spec의 경계를 구체화한다. 구현 완료·본실험 동결·실측 유효성을 인증하지 않는다.

## 1. 서로 다른 두 실행

| 실행 | 용도 | 수정·노출 | 에너지 처리 |
|---|---|---|---|
| 작업 중 공개 피드백 | 공개 예시에 대한 참가자의 디버깅 | 공통 정책 아래 참가자에게 표시하고 잠금 전 수정 가능 | 사전 정의한 서비스가 수행하는 운영 검증이면 해당 세션 측정 경계에 포함. 활성 합계를 세션 총량에 다시 더하지 않음 |
| 잠금 후 연구 채점 | 불변 최종 산출물의 연구용 품질 판정 | 숨김 연구 bank의 결과를 다음 수정 기회로 주지 않음 | 연구 비용으로 별도 기록. 주 세션 에너지를 대신하거나 토큰·시간으로 J를 채우지 않음 |

기존 개발 bank는 공개 개발 fixture이다. 현재 신규 개발 scorer의 실행을 숨김 최종 bank 평가, 참가자 성공률 또는 실제 모델 성능으로 표시하지 않는다. 개발용 함수 호출 시간은 에너지 측정이 아니다.

## 2. 잠금·drain·사후 채점 순서

1. 기존 세션 규칙에 따라 사용자 입력과 최종 산출물을 잠그고 immutable snapshot/hash를 남긴다.
2. 잠금 전에 수락된 모델 실행·취소 잔여·사전 운영상 검증을 실제 backend-drained까지 관측한다. 취소 클릭이나 스트림 종료만으로 drain을 선언하지 않는다.
3. 기존 측정 경계의 에너지 끝점을 확보한 뒤, 같은 측정 자원에 대한 연구용 사후 채점을 실행한다. 다른 자원에서 실행한다면 그 자원의 별도 식별자와 경계를 남긴다.
4. 사후 채점이 주 측정 자원·시간구간과 실제로 겹치면 단순히 예상 채점 비용을 빼지 않는다. raw counter 차이는 보존하고 서비스 비용 귀속의 프로토콜 위반·불확실성을 표시한다. 그 구간을 원래 서비스 전용 에너지로 자동 승인하지 않는다.

잠금 뒤 늦은 모델 응답이 도착해도 채점 snapshot을 교체하지 않는다. 사후 채점 오류 복구에서도 원래 snapshot은 유지하고 최초 오류와 재채점 이력을 연결한다. 허용 복구 이유·최대 횟수·scorer 수정 시 대칭 재검토는 별도 동결 대상이며 이번에 실행된 정책이 아니다.

## 3. 실패 귀속

| 관측 | 연구 품질 취급 |
|---|---|
| 건강한 동결 scorer에서 최종 산출물의 오답·입력 변이·출력 계약 위반 확인 | `observed_failure` |
| 건강한 실행 경로에서 산출물 함수에 귀속되는 예외·사전 자원 제한 위반을 확인 | `observed_failure`, 귀속 근거 보존 |
| runner/process timeout의 원인 미확정, scorer crash, oracle 오류, 손상된 bank·입력·스키마, 누락된 snapshot | `unknown`; 사용자 코드·모델 실패나 성공으로 치환하지 않음 |
| 빈/누락 bank 또는 채점 결과 부재 | `unknown`; 빈 배열의 전칭 조건으로 통과시키지 않음 |

무AI 수동 완성의 `mode=none`, 실제 미시작, 관측 실패, 자료 유실은 각각 다른 상태이다. 허용된 수동 완성은 최종 품질 성공일 수 있으며 전체 배정 과제와 할당 세션 에너지의 분모에 남는다. scorer의 실패 판정은 backend attempt 실패 횟수를 새로 생성하지 않는다.

현재 trusted-local 개발 함수 실행은 비신뢰 참가자 코드 격리·자원 제어의 인증이 아니다. 일반 예외를 사용자 귀속으로 믿어도 되는 범위는 현재 직접 작성한 신뢰 fixture에 한정한다.

## 4. 눈가림 채점 export 후보

구현 전 명세이다. export에는 모든 사전 배정 과제의 `scoring_case_id`, task/contract ID·버전, immutable snapshot 참조·해시 또는 명시적 부재 상태, scorer/runtime/bank 버전·해시, 허용된 채점 정책을 전달한다. 성공 사례나 완전한 snapshot만 선별하지 않는다. 부재 과제도 빈 레코드를 지우지 않고 해당 이유와 상태를 가진다.

채점 작업에 arm·Low/Fast/Eco 표시명·선택 모드·프롬프트/응답 대화·에너지·참가자 신원을 전달하지 않는다. 별도 접근 통제 mapping은 `scoring_case_id`를 원래 manifest의 participant/session/task/snapshot에 연결한다. 채점 결과를 고정한 뒤 mapping으로 원배정 분모에 결합한다. 결합 실패·중복·버전 불일치는 unknown과 감사 사유로 보존하며 정상 성공으로 만들지 않는다.

metadata 생략만으로 실제 눈가림이 보장되지는 않는다. 코드 주석·문자열 자체에 명칭이나 조건 정보가 남을 수 있다. 최종 산출물 바이트를 몰래 수정하거나 해시를 원본처럼 표시하지 않고, 유출 가능성을 별도 기록한다. 자동 판정인지 사람이 해석하는지에 따라 눈가림 수준을 보고한다. 이번에는 export·private mapping·사람 눈가림을 구현·검증하지 않았다.

## 5. 이번 관문의 한계

새 개발 scorer가 정답을 구분해도 세션 에너지 누락을 해결하지 못하며, 통과 검사 수가 실제 품질 비열등성이나 명칭 효과의 근거가 되지 않는다. D 고정 기준의 장비·센서·두 예산·불확실성·자원 항목은 미완료이다. 기존 D73을 유지하고 `confirmatory_allowed=false`를 변경하지 않는다.
