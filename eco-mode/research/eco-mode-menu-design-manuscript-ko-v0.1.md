# 대규모 언어 모델 서비스의 Eco 모드 메뉴 설계

공개 인터페이스 자료 비교와 두 메뉴 시안의 분석

안종훈 · 2026년 11월 8일

## 초록

대규모 언어 모델 서비스의 메뉴에는 모델 선택, 추론 수준 조절, 자동 선택처럼 서로 다른 종류의 제어가 공존한다. 이 연구는 그 구조에 Eco 모드를 추가할 때 환경 목표와 조절 규칙을 어떻게 표시할 수 있는지 살펴본다. Gemini Apps, ChatGPT Work, Claude 채팅의 공식 문서와 Gemini 화면 캡처 두 장을 조절 대상, 결정 방식, 표기된 목적, 근거의 네 기준으로 분석했다. 이를 바탕으로 Eco와 다섯 개의 고정 추론 수준을 한 목록에 놓은 시안과 기능별로 묶은 시안을 비교했다. 두 시안 모두 선택 전에 같은 기능 설명과 절감 검증 상태를 제시했다. 묶음형의 제목은 Eco를 별도의 조절 방식으로 표시했으며, 공통 설명을 확인하는 데 필요한 추가 메뉴 단계는 같았다. 결과를 토대로 선택한 정책과 과제별 적용 수준을 구분하고, 자원 절약 목표와 검증 상태를 함께 표시하는 설계 기준을 제안한다.

**주제어**  Eco 모드, 대규모 언어 모델, 메뉴 설계, 인터페이스 비교, 환경 정보

## 1 서론

한 메뉴에서 Light와 Eco를 나란히 보면 두 항목이 같은 종류의 설정처럼 보일 수 있다. Light는 사용자가 낮은 추론 수준을 직접 정하는 값으로 설계할 수 있고, Eco는 시스템에 과제별 수준 결정을 맡기는 방식으로 설계할 수 있다. 두 선택이 한 과제에서 같은 수준을 적용하더라도 다음 과제에서는 서로 다른 규칙을 따른다. 메뉴에는 이 차이를 드러낼 정보가 필요하다.

Eco라는 이름은 제어 방식에 환경 목표를 더한다. 사용자가 무엇을 맡기는지 이해하려면, 화면에서 조절하는 대상과 조절의 목적을 함께 확인할 수 있어야 한다. 자원 절약을 지향한다는 설명과 절감이 확인되었는지를 알려 주는 설명도 각각 필요하다. 이 연구에서는 공식 문서에 나타난 선택 구조를 비교하고, 그 관찰을 Eco 메뉴의 문구와 배치로 옮긴다.

**연구 질문 1**  세 서비스는 모델과 추론에 관한 선택의 대상, 결정 방식, 목적을 어디에 표시하는가?

**연구 질문 2**  같은 항목과 설명을 쓰는 두 Eco 시안에서 조절 규칙, 환경 목표, 절감 검증 상태는 선택 전에 어떻게 드러나는가?

## 2 관련 연구

GPTFootprint는 ChatGPT 확장 프로그램에서 Eco Score와 환경 이미지, 추정 사용량 정보를 함께 제공했다 [2]. EcoChat Probe는 추정 에너지와 탄소 정보를 표시하는 확장 프로그램을 52명에게 4주간 제공했으며, 공개 초록은 참가자의 인식과 성찰이 달라졌고 사용 패턴의 유의한 변화는 관찰되지 않았다고 보고한다 [3]. 두 연구는 사용자가 환경 정보를 받는 경험을 다룬다.

Klesel과 Messer는 에너지와 성능 정보를 제시한 선택 실험에서 두 선택지에 같은 모델을 사용했다 [4]. Kim 등은 응답 지연과 탄소 정보를 보여 주는 LLM 인터페이스를 대학생과 평가했다 [5]. 이 연구들이 제시한 정보와 선택 상황을 참고하여, 여기서는 환경 목표를 내건 항목이 기존 모델·추론 제어와 어떤 관계로 배치되는지를 분석한다.

## 3 자료와 분석 방법

2026년 11월 8일에 Gemini Apps의 컴퓨터용 도움말, ChatGPT Work의 웹 제품 문서, Claude 채팅의 모델 메뉴 도움말을 확인했다 [6–8]. 이 자료는 수동 선택, 프리셋, 자동 선택이 어떻게 문서화되는지 비교하기 위해 골랐다. Gemini에는 11월 5일에 제공된 한국어 메뉴 캡처 두 장을 추가로 대조했다. 캡처에서 체크 표시는 그 화면의 선택 상태로만 기록했다. 각 계정의 초기값과 배포 조건은 별도 확인이 필요하다.

분석 단위는 제품 문서가 개별 기능으로 구분한 제어 항목이다. 여러 설정을 한 번에 정하는 Power는 하나의 프리셋 제어로 기록하고, Advanced의 모델, 추론 수준, 속도는 각각 기록했다. Light 등의 워크스루 [1]에서 조작 단계와 화면 문구를 기록하는 방식을 가져와 메뉴에 한정해 적용했다. 서비스 비교는 공개 문서와 캡처를 읽고, 시안 비교는 같은 과제를 대입해 화면에 표시된 정보를 대조했다.

**표 1 자료에 적용한 비교 기준**

| 기준 | 기록한 내용 |
| --- | --- |
| 조절 대상 | 모델, 추론 수준, 속도, Thinking 토글 중 무엇이 바뀌는지 기록한다. |
| 결정 방식 | 직접 설정, 여러 값이 묶인 프리셋, 시스템에 맡기는 자동 선택을 구분한다. |
| 표기된 목적 | 속도, 답변의 깊이, 사용 한도, 비용, 자원 절약 등 자료에 적힌 목적을 기록한다. |
| 근거 | 공식 설명과 화면 관찰을 구분하고, 환경 효과에 관한 검증 정보가 제시되는 위치를 기록한다. |

## 4 서비스 메뉴 비교 결과

세 서비스의 자료에서 열 개의 제어 항목을 정리했다. 표의 목적은 제공자가 해당 조절 기능을 소개할 때 사용한 설명이다. 같은 이름을 쓰는 설정의 실제 처리량이나 성능을 비교하려면 별도의 실행 자료가 필요하다.

**표 2 공개 자료에서 확인한 제어 항목**

| 서비스와 항목 | 조절 대상과 결정 방식 | 문서에 나타난 목적 또는 설명 |
| --- | --- | --- |
| G1 Gemini 모델 | 모델 직접 선택 | 응답 속도와 과제 복잡도에 맞는 모델 |
| G2 Gemini 사고 수준 | 낮음·보통·높음 직접 선택 | 응답 속도와 사고 깊이 |
| G3 Gemini Auto | 모델과 사고 수준을 시스템에 위임 | 요청에 적합한 응답과 사용 한도 관리 |
| W1 Work Power | 모델과 추론 수준을 묶은 프리셋 선택 | 빠른 처리 또는 깊은 추론 |
| W2 Work Advanced 모델 | 지원되는 모델 직접 선택 | 모델을 지정하는 세부 설정 |
| W3 Work Advanced 추론 | 지원되는 추론 수준 직접 선택 | 과제에 맞는 추론 깊이 |
| W4 Work Advanced 속도 | 지원되는 속도 설정 직접 선택 | 처리 속도를 지정하는 세부 설정 |
| C1 Claude 모델 | 모델 직접 선택 | 현재 대화의 모델 변경 |
| C2 Claude Effort | 지원되는 effort 수준 직접 선택 | 답변의 깊이, 응답 시간, 사용량의 관계 |
| C3 Claude Thinking | 지원되는 경우 토글로 직접 설정 | Thinking 또는 Extended의 사용 설정 |

G1–G3은 Gemini Apps 도움말 [6], W1–W4는 ChatGPT Work 문서 [7], C1–C3은 Claude Help Center [8]에 근거한다. Gemini 캡처에서는 모델 목록과 ‘사고 수준’ 하위 메뉴가 구분되고, 낮음·보통·높음의 설명을 확인할 수 있었다. 인용한 선택 안내에서 전력·탄소 절감의 비교 기준과 측정 조건은 확인되지 않았다.

Gemini의 Auto는 모델과 사고 수준을 요청에 맞춰 시스템이 고르는 방식이다. Work의 Power는 사용자가 여러 값이 결합된 프리셋을 고르는 방식이고, Advanced에는 개별 선택이 있다. Claude는 하나의 모델 메뉴에서 모델, effort, thinking을 구분하며 지원 여부가 모델에 따라 달라진다. 이 비교에서 자동화의 범위와 프리셋의 구성은 별도로 확인해야 하는 속성으로 나타났다. [6–8]

## 5 Eco 메뉴 시안

## 6 두 과제로 확인한 화면 정보

워크스루에는 안내문에 있는 날짜, 장소, 준비물을 정리하는 과제와 일정, 가격, 마감, 예외 조건을 대조하는 과제를 사용했다. 두 과제의 예정 설정은 시나리오 규칙으로 정했다. 비교 단위는 각각의 시안에 표시되는 문구와 예정 설정이며, 동일한 자료를 두 메뉴에 적용했다.

**표 4 두 과제의 예시 설정**

| 과제 | Light를 직접 선택 | Eco 정책을 선택 |
| --- | --- | --- |
| 워크숍 안내에서 날짜, 장소, 준비물 정리 | Light | Light |
| 두 워크숍의 일정, 가격, 마감, 예외 조건 비교 | Light | High |

첫 사례에서는 Light와 Eco가 같은 예정 수준에 도달한다. 둘째 사례에서는 고정 Light가 유지되고 Eco에는 High가 배정된다. 따라서 ‘선택 모드’와 ‘이 과제의 예정 수준’을 구분해 기록하면, 표시된 수준이 같아도 어떤 규칙으로 그 값이 정해졌는지 확인할 수 있다.

**표 5 메뉴를 처음 열었을 때 제공되는 정보**

| 확인할 정보 | 일렬형 | 기능별 묶음형 |
| --- | --- | --- |
| Eco의 자동 조절과 상향 가능성 | Eco 설명에 표시 | Eco 설명에 표시 |
| Light의 고정 설정 | Light 설명에 표시 | Light 설명에 표시 |
| 자원 절약 목표 | Eco 목표 줄에 표시 | Eco 목표 줄에 표시 |

| 고정과 과제별 조절을 구분하는 제목 | 공통 메뉴 제목 | 두 기능별 제목 |
| 공통 설명을 여는 추가 메뉴 단계 | 0 | 0 |

두 시안에서 공통 문구를 읽는 데 추가 메뉴를 열 필요가 없었다. 묶음형이 더한 것은 항목 설명을 읽기 전에도 목록에서 제어 방식을 구분할 수 있도록 배치한 제목이다. 이 결과는 정적 시안에서 정보가 표시되는 위치와 단계에 관한 것이다. 읽는 순서나 해석의 차이는 사용자 자료로 확인할 질문이다.

## 7 논의

### 조절 대상과 결정 방식의 구분

Gemini의 Auto는 모델과 사고 수준을 모두 맡기는 사례이며, Work의 Power는 한 번에 여러 값을 정하는 직접 선택의 사례다. 이 둘의 차이는 Eco가 자동으로 정하는 범위를 설명할 필요를 보여 준다. 이 시안의 Eco는 선택 범위를 추론 수준으로 명시했다. 모델 변경도 허용하는 설계라면 모델이 자동 조절 대상임을 별도로 표시해야 한다. [6, 7]

### 선택한 모드와 과제별 설정의 구분

시안의 간단한 과제에서는 Eco와 Light가 같은 예정 수준을 가리켰다. 두 번째 과제에서는 차이가 생겼다. 설정값 하나만 표시하면 처음 고른 방식이 고정 수준인지 적응 정책인지 읽기 어렵다. ‘선택 모드 Eco’와 ‘이 과제의 예정 수준 Light’처럼 두 정보를 구분하면 한 과제에서 같았던 수준이 다음 과제에서도 유지되는지 판단할 수 있는 단서를 제공한다.

### 환경 목표와 검증 상태의 표시

Gemini와 Work 문서에는 효율, 응답 속도, 사용 한도, 비용이 서로 다른 문맥에서 나타난다 [6, 7]. Eco 시안에서는 그중 어느 지표를 뜻하는지 모호해지지 않도록 목표와 검증 상태를 나란히 표시했다. 이처럼 목표와 근거를 분리하는 기준은 모드 이름과 그룹 제목을 바꿔도 적용할 수 있다. 묶음형 제목은 조절 규칙을 분류한다. 절감을 검증한 서비스는 비교 기준, 측정 항목, 적용 범위를 별도 문구에 제시할 수 있다.

## 8 연구 범위와 결론

분석은 조사 시점의 공식 문서와 Gemini 캡처에 한정된다. 문서에서 설명한 기능은 요금제, 모델, 서비스 화면에 따라 달라질 수 있다. 두 시안의 예시 설정은 고정된 시나리오이며, 화면을 읽어 정보의 위치와 접근 단계를 확인했다. 사람들의 해석과 선택, 성능 차이를 받아들이는 정도에는 별도의 참가자 자료가 필요하다. 전력과 탄소의 변화는 실제 적용 환경에서 측정할 문제다.

두 시안의 비교에서 묶음 제목은 Eco가 과제별 추론 조절이라는 점을 목록 수준에서 드러냈다. 기능 설명과 검증 상태의 접근 단계는 일렬형과 같았다. Eco 메뉴를 설계할 때는 조절 대상과 결정 방식, 환경 목표와 검증 상태가 함께 드러나는지 각각 확인할 수 있다.

공개 자료 정리, 시안 검토와 초고 작성에 생성형 AI를 활용했다.
