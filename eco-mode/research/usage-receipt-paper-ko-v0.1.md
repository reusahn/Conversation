# 덜 요청하는 이유: 생성형 AI의 사용량 영수증과 작업 종료 선택
## Why Stop Asking? Usage Receipts, Revision, and Task Outcomes in Generative AI

**연구자:** Jonghoon Ahn  
**문서 상태:** 실험 전 한국어 논문 초안 v0.1 · 2026-10-29  
**작성 관점:** 가상 A HCI 교수의 편집 관점으로 구성한 연구 원고. 실제 교수의 검토·공저·승인을 뜻하지 않는다.

> 이 원고는 연구 질문과 제안 방법을 담는다. 참가자 모집, 실험, 통계 분석, 환경 실측은 수행되지 않았다. 결과 절은 보고 계획이며, 제출 가능한 완성 실증 논문이 아니다.

## 초록

생성형 AI 사용량을 줄이려는 인터페이스를 평가할 때, 요청 감소가 어떤 작업 결과와 함께 발생했는지 구분할 필요가 있다. 사용자는 충분한 답을 얻어 멈출 수도 있고, 부족함을 받아들여 제출하거나 작업을 포기할 수도 있다. 본 연구는 매 응답 후 제공되는 사용량 영수증이 이 선택과 작업 전체 토큰 사용량에 미치는 영향을 검증하는 무작위 실험을 제안한다. 참가자는 상용 언어모델 API를 연결한 연구용 채팅에서 명시적 조건을 충족하는 비교 과제를 수행하며, 영수증 표시 집단과 미표시 집단에 배정된다. 두 집단에는 같은 모델 설정과 조건 충족 피드백을 제공한다. 주요 결과는 최초 요청과 재요청을 포함한 제공자 보고 토큰이며, 완료 제출·미완성 제출·명시적 포기와 함께 해석한다. 종료 이유와 피드백 이해도는 별도로 수집한다. 본 연구는 품질 유지를 절감의 필수 성공 조건으로 두지 않되, 사용자에게 발생한 손실을 숨기지 않는 평가 방식을 제안한다. 토큰, 자기보고 환경 동기, 실제 환경 영향을 구분하며, 영수증의 행동 효과를 환경 절감의 증거로 확대하지 않는다.

**주제어:** 생성형 AI, 지속가능 HCI, 사용량 피드백, 작업 종료, 성능 수용, 토큰

## 1. 서론

생성형 AI와의 대화에서 사용자는 답변을 받은 뒤 다시 선택한다. 조건이 빠졌다면 수정을 요청할 수 있고, 현재 결과로 충분하다고 판단하면 제출할 수 있다. 더 이상 진행할 이유가 없다고 느끼면 작업을 중단할 수도 있다. 사용량을 눈에 보이게 만드는 인터페이스는 이러한 선택 시점에 새로운 판단 정보를 제공한다.

그러나 적게 요청했다는 사실만으로 바람직한 사용이 이루어졌다고 판단하기는 어렵다. 같은 요청 감소가 과제의 빠른 완성, 부족한 결과의 수용, 해결을 포기한 상태에서 각각 발생할 수 있기 때문이다. 본 연구는 이 세 결과를 구분하여 사용량 피드백의 효과를 평가하고자 한다.

환경을 위해 일부 성능을 양보하려는 사용자의 선택도 연구 가치가 있다. 이때 품질이 유지되어야만 연구가 성공했다고 정의하면, 사용자가 받아들이려는 교환 자체를 놓칠 수 있다. 반대로 품질을 측정하지 않으면 무엇을 양보했는지 설명할 수 없다. 따라서 본 연구는 사용량과 작업 결과를 함께 측정하고, 품질 저하를 배제 조건으로 사용하지 않는다.

첫 연구의 개입은 응답별 사용량 영수증으로 한정한다. Eco라는 명칭, 모델 선택, 추론 수준 변경을 동시에 조작하지 않는다. 이 범위는 영수증 표시가 만드는 행동 차이를 식별하기 위한 선택이다. 친환경 명칭의 효과와 실제 데이터센터 환경 영향은 후속 연구 문제로 남긴다.

## 2. 관련 연구와 연구의 위치

Ren 등[1]은 ChatGPT에서 추론 에너지와 탄소 배출 추정치를 보여주는 EcoChat을 연구했다. 4주간 52명이 참여한 현장 연구와 18건의 인터뷰에서 사용 패턴의 유의한 변화는 관찰되지 않았으나, 참가자들은 환경 영향에 대한 인식과 사용 가치에 대한 성찰을 보고했다. 연구는 수치의 불확실성과 해석의 어려움도 다루었다. 따라서 실시간 피드백을 제공한다는 사실 자체를 본 연구의 독창성으로 주장하지 않는다.

Klesel과 Messer[2]는 365명을 대상으로 에너지 정보 공개와 모델 선택, 이후 사용 행동 및 지각된 품질을 조사했다. 친환경 선택과 사용 경험의 평가가 서로 다른 방향으로 나타날 수 있다는 결과는 선택, 행동, 주관적 품질을 구별할 필요성을 뒷받침한다. 본 연구 역시 자기보고 만족도를 객관적 과제 충족 여부와 구분한다.

한편 Elsworth 등[3]의 운영 환경 측정은 가속기뿐 아니라 호스트, 유휴 용량, 데이터센터 부대 에너지까지 고려한다. 본 연구의 API 토큰 기록은 이러한 물리 계측을 제공하지 않는다. 그러므로 사용량 영수증에 보편적인 토큰당 탄소 계수를 적용하거나, 표시된 값으로 환경 훼손 방지량을 계산하지 않는다.

이 원고가 제안하는 기여는 **객관적 과제 피드백이 있는 상황에서, 영수증 표시의 전체 사용량 효과와 서로 다른 종료 상태를 함께 평가하는 실험**이다. 이는 검증할 기여 후보이며, 최초성이나 학술대회 채택을 확정하는 주장은 아니다. 제출 전에는 관련 문헌의 범위를 더 넓혀 비교해야 한다.

## 3. 연구 질문

**RQ1.** 매 응답 후 사용량 영수증을 표시하면, 작업 전체의 제공자 보고 토큰 사용량은 어떻게 달라지는가?

**RQ2.** 영수증 표시는 추가 수정의 빈도와 최종 상태인 완료 제출, 미완성 제출, 명시적 포기의 분포를 어떻게 바꾸는가?

**RQ3.** 참가자는 답변의 부족함을 얼마나 이해하며, 계속하거나 멈춘 이유를 어떻게 설명하는가?

효과의 방향은 사전에 단정하지 않는다. 영수증이 재요청을 줄일 수도 있지만, 참가자가 수치를 이해하려고 추가 요청을 하거나 더 효율적인 결과를 얻기 위해 수정을 반복할 수도 있다. 방향과 관계없이 RQ1을 주 분석, RQ2를 사전 지정된 보조 분석, RQ3를 탐색적 해석으로 다룬다.

## 4. 방법

### 4.1 설계와 참가자

참가자 간 2집단 무작위 실험을 제안한다. 각 참가자는 한 가지 과제를 수행하며, 과제 변형 안에서 두 조건에 1:1로 배정한다. 대상은 연구 언어로 과제를 이해할 수 있는 성인 생성형 AI 사용자로 제안한다. 구체적인 모집 범위와 언어는 파일럿 전에 확정한다.

사용성 파일럿은 과제 이해, 피드백 정확성, 표시 이해도와 기록 누락을 확인하는 데 사용한다. 파일럿 자료는 본실험에 합치지 않는다. 본실험 표본 수는 최소 관심 효과와 추정 정밀도를 정한 뒤, 사용량 분포와 중도 종료를 고려한 시뮬레이션으로 결정하고 사전등록한다. 현재 확정된 참가자 수는 없다.

### 4.2 과제와 채점

과제는 제공된 가상의 상품표를 읽고 예산, 무게, 기능, 배송 조건을 모두 충족하는 두 상품을 비교하는 것이다. 상품표와 조건은 연구자가 작성하며, 실제 구매를 요구하지 않는다. 동일한 구조의 과제 변형을 마련해 특정 상품 조합에만 결과가 의존하는지 확인한다.

답변은 두 상품의 식별자와 비교 설명을 포함한다. 수치·속성 조건은 고정된 규칙으로 판정하고, 설명의 사실 일치 여부는 별도 평가한다. 실험 전에 정답표와 판정 규칙을 고정한다. 참가자에게 제공하는 즉시 피드백은 검증 가능한 조건의 충족 여부만 표시한다. 설명 전체의 정확성을 보증하는 표시로 사용하지 않는다.

완료 제출은 네 가지 조건을 충족한 답의 명시적 제출로 정의하고, 하나 이상 미충족인 답의 제출은 미완성 제출로 정의한다. 설명의 사실 오류는 이 조건 충족 지표와 별도로 보고한다. 따라서 ‘완료’가 답변의 모든 측면에서 완벽함을 뜻하지는 않는다.

최종 설명은 가능하면 조건을 모르는 평가자가 검토한다. 자동 판정이 실패한 경우를 참가자 오답으로 처리하지 않고 별도 상태로 기록한다. 개발 과정에서는 모든 답이 항상 정답이거나 항상 실패하는 과제를 피하도록 난도를 점검하되, 본실험에서 나온 결과를 보고 과제를 교체하지 않는다.

### 4.3 실험 조건

| 항목 | 영수증 표시 | 영수증 미표시 |
| --- | --- | --- |
| 모델·버전·추론 설정 | 동일 | 동일 |
| 과제·시간·수정 기회 | 동일 | 동일 |
| 조건 충족 피드백 | 제공 | 제공 |
| 요청별·누적 토큰 | 표시 | 미표시 |
| 환경 절감 수치·칭찬 | 없음 | 없음 |

영수증은 모델이 작성한 문장이 아닌 화면 요소로 제공한다. 예시 문구는 “이번 요청: 입력 ○ / 출력 ○토큰 · 작업 누적: ○토큰”이다. 실제 화면에는 제공자 기록에서 계산한 값만 넣는다. 토큰은 모델이 텍스트를 처리하는 단위라는 설명을 제공하고, 표시값이 실제 전력·탄소 절감량을 뜻하지 않는다는 안내는 두 집단에 공통으로 제시한다.

누적값이 불완전하면 “확인된 사용량”과 누락 여부를 표시한다. 미확인 사용량을 0으로 표시하지 않는다. 색상 경고, 절감 목표, 순위, 금전 요금, 도덕적 칭찬은 개입에 포함하지 않는다. 참가자 보상은 토큰을 적게 쓰거나 빨리 포기할수록 늘어나도록 설계하지 않는다.

### 4.4 절차

참가자는 동의와 공통 안내를 읽고 과제를 시작한다. 모델 응답 뒤에는 조건 충족 피드백이 나타나며, 배정된 집단에 따라 영수증도 표시된다. 참가자는 추가 수정을 요청하거나, 현재 답변을 제출하거나, 작업을 중단할 수 있다.

첫 연구에서는 모델 전환과 답변의 직접 편집 기능을 제공하지 않는다. “현재 답 제출”은 제출된 결과를 확정하는 행동이고, “작업 중단”은 제출 없이 종료하는 행동으로 구별한다. 시간 만료, 브라우저 이탈, 기술 오류는 명시적 포기와 합치지 않는다.

최종 선택 뒤에는 충족되지 않은 조건을 어떻게 이해했는지, 왜 멈추거나 계속했는지 짧게 묻는다. 이유는 자유응답을 먼저 받고, 충분한 결과 확보, 시간, 피로, 환경 고려, 답변 불신 등을 복수 선택하게 한다. 피드백을 보여주었다는 사실만으로 실제 이해를 인정하지 않는다.

### 4.5 사용량과 행동 기록

분석 단위는 참가자의 전체 작업 세션이다. 최초 요청, 수정 요청, 자동 재시도, 실패 호출, 종료 뒤 보고된 해당 요청의 사용량을 가능한 범위에서 포함한다. 요청 식별자로 중복 기록을 제거하고, 재시도 정책은 두 조건에 동일하게 적용한다.

제공자의 공식 사용량 정의를 확인하여 입력·출력의 중복 없는 합계를 주지표로 고정하고, 구성 항목을 별도로 보고한다. 추론·캐시 세부 항목은 해당 제공자의 포함 관계에 따라 처리한다. 서로 다른 제공자나 모델의 토큰을 같은 물리적 작업량으로 합치지 않는다.

채점은 고정 규칙으로 수행하여 별도 평가용 모델 호출을 만들지 않는 구성을 우선한다. 로그 저장, 화면 렌더링 등 연구 시스템 운영의 물리적 비용은 토큰 지표에 포함되지 않는다. 이 측정 경계를 결과와 함께 명시한다.

## 5. 분석 계획

RQ1의 주 추정량은 영수증 표시 집단과 미표시 집단의 참가자당 평균 전체 토큰 차이이다. 음의 차이는 표시 집단의 기록된 사용량이 적음을 뜻한다. 평균 차이와 95% 신뢰구간을 보고하고, 무작위 배정 단위를 보존하는 재표집 및 배정 방식에 맞춘 검정을 사전등록한다. 평균에 큰 영향을 주는 긴 세션도 행동 결과이므로, 분포가 크다는 이유만으로 제거하지 않는다. 중앙값과 분포는 보조적으로 제시한다.

RQ2에서는 완료 제출, 미완성 제출, 명시적 포기, 시간 만료, 기술 오류·상태 불명의 비율과 집단 간 차이를 보고한다. 분모는 원칙적으로 무작위 배정된 전체 참가자이다. 여러 보조 비교의 다중성 처리도 사전등록한다. 완료자만의 사용량은 설명용 분석으로 명시하며, 전체 무작위 비교의 대체물로 사용하지 않는다.

영수증을 본 뒤 발생한 오류나 미완성 상태를 기준으로 참가자를 골라 비교하면 원래의 무작위성이 유지되지 않을 수 있다. 따라서 “실패한 사람 중 수용률”은 탐색적으로만 제시한다. 이 설계로 동일한 수준의 성능 손실에 대한 개인별 수용 한계까지 추정했다고 주장하지 않는다.

RQ3의 자유응답은 종료 동기의 범주를 개발하고, 상반된 사례와 중복 동기를 함께 제시하는 방식으로 분석한다. 환경 동기 응답과 행동의 관계는 관찰적 관계로 해석한다. 피드백 이해 여부에 따라 본 분석에서 참가자를 제외하지 않는다.

사용량이 누락된 세션에는 완전한 총량이 있다고 가정하지 않는다. 집단별 누락률과 확인된 합계를 보고하고, 근거 있는 범위가 있을 때 민감도 분석을 수행한다. 그렇지 않으면 전체 사용량 효과의 식별이 제한됨을 명시한다. 철회로 삭제된 자료 역시 보유한 것으로 계산하지 않는다.

## 6. 결과 절: 자료 수집 후의 보고 계획

**현재 보고할 실험 결과는 없다.** 실제 원고에는 다음 순서로 결과를 작성한다.

1. 배정·완료·포기·철회·누락의 흐름과 집단별 기록 완전성.
2. 전체 토큰의 집단별 분포, 평균 차이, 신뢰구간.
3. 각 종료 상태의 빈도와 비율 차이.
4. 추가 수정 횟수, 과제 충족 수준, 소요 시간.
5. 피드백 이해도와 종료 이유의 주제 및 반례.

결과를 해석할 때에는 아래 구분을 유지한다.

| 가능한 관찰 | 허용되는 해석 |
| --- | --- |
| 사용량 감소, 완료율의 추정 변화가 작음 | 관찰 범위에서 완료 손실이 작을 가능성. 정밀도가 낮으면 유지 확정 불가 |
| 사용량 감소, 미완성 제출 증가 | 낮은 사용량과 부족한 결과 제출이 함께 나타남 |
| 사용량 감소, 포기 증가 | 낮은 사용량과 작업 미완수가 함께 나타남 |
| 사용량 증가, 완료 증가 | 추가 사용과 더 높은 완수가 함께 나타남 |
| 차이 불명확, 넓은 신뢰구간 | 효과의 방향과 크기를 판단할 근거가 부족함 |

이 표는 예상 결과나 효과의 인과 경로를 확정한 것이 아니다. 특히 “포기가 토큰 감소를 매개했다”는 주장은 별도의 분석 가정 없이 하지 않는다.

## 7. 논의

### 7.1 적게 쓰는 행동의 평가

본 연구는 적은 사용량을 자동으로 성공으로 분류하지 않는다. 사용량 변화가 어떤 작업 상태와 함께 나타났는지를 제시함으로써, 사용자가 얻은 결과와 감수한 손실을 독자가 판단할 수 있게 한다. 품질 유지가 필수 성공 조건일 필요는 없지만, 품질 변화는 반드시 보고되어야 한다.

### 7.2 성능 수용과 환경 동기

미완성 답을 제출한 사람에게는 환경 고려, 피로, 시간 압박, 과제에 대한 낮은 관심이 동시에 작용할 수 있다. 따라서 미완성 제출을 곧바로 자발적인 친환경 희생으로 명명하지 않는다. 본 연구에서는 미완성 제출, 부족함의 이해에 대한 증거, 자기보고 환경 동기를 분리해 보고한다. 이 구분은 사용자의 선택을 존중하면서도 그 동기를 과장하지 않기 위한 것이다.

### 7.3 관측된 사용량과 환경 영향

토큰 감소는 이 연구에서 관측하는 인터페이스 사용 결과이다. 실제 전력·탄소·물 소비 변화나 넓은 생태적 편익을 직접 입증하지 않는다. 후속 연구에서 적절한 계측 접근권을 확보하면 이러한 결과를 연결할 수 있다. 현재 자료로 확인할 수 없는 환경 편익을 영수증에 먼저 표시하지 않는다.

### 7.4 적용 범위

연구용 API 채팅은 상용 소비자 앱 전체와 같지 않다. 하나의 조건 기반 비교 과제에서 얻는 결과를 코딩, 창작, 학습, 정서적 대화로 일반화할 수 없다. 객관적 조건 피드백도 일상 대화에는 흔하지 않을 수 있다. 또한 단기 실험은 장기 습관 변화나 다른 서비스로 옮겨간 사용량을 포착하지 못한다.

## 8. 연구윤리와 재현성

참가자 연구에 필요한 소속기관의 심의 또는 해당 여부 확인 절차를 완료한 후 모집과 사람 대상 파일럿을 진행한다. 현재 승인이나 면제 판정은 받았다고 주장하지 않는다. 참가자는 연구용 과제와 대화·사용량 기록 범위를 안내받으며, 실제 개인정보나 비공개 업무 자료의 입력을 요구받지 않는다.

과제표, 채점 규칙, 화면 문구, 무작위 배정 절차, 모델 및 API 버전, 사용량 정의, 분석 코드를 가능한 범위에서 공개할 계획이다. 참가자의 원문 대화는 동의와 비식별화 검토 없이 공개하지 않는다. 가상 페르소나는 설계 검토 도구이며 참가자, 실제 전문가, 데이터 또는 연구 저자로 취급하지 않는다.

## 9. 결론

본 원고는 생성형 AI의 응답별 사용량 영수증을 작업 전체의 소비와 종료 선택을 통해 평가하는 연구를 제안한다. 핵심은 요청 감소를 관찰하는 데서 한 걸음 더 나아가, 사용자가 과제를 완성했는지, 부족한 결과를 제출했는지, 작업을 포기했는지를 함께 밝히는 것이다. 이 접근은 성능 양보 가능성을 연구에 포함하면서도, 그 선택을 곧바로 환경적 편익으로 해석하지 않는 평가 틀을 제공한다. 실제 효과와 기여의 크기는 향후 실험 결과로 검증되어야 한다.
