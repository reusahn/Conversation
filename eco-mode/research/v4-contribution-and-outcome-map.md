# v4 기여·주장·결과 지도

2026-10-28. B의 새 공개 방법 제안이다. 실제 참가자나 장비 자료를 보고하는 논문이 아니며, 코딩을 최종 연구 분야로 확정하지 않는다. 고정 v4 평가기준과 연구 목표를 유지한다.

## 답하려는 질문

성능 저하 가능성을 같은 문구로 안내하고 실제 두 계산 설정을 사용할 수 있게 했을 때, 낮은 설정에 붙이는 **Eco라는 이름의 총효과**가 무엇인지 묻는다. 개발 분석에서는 Eco–Low의 전체 세션 보고 토큰과 J를 각각 추정하고 성과·완료·수용을 함께 해석한다. 두 자원이 모두 줄거나 성과가 유지되어야만 연구 결과를 보고할 수 있는 구조가 아니다.

‘안내를 받음’, ‘이해했다고 답함’, ‘환경 때문에 성능 손해를 받아들였다고 답함’, ‘실제로 성과가 낮아짐’은 같은 사건이 아니다. 이들 사후 응답으로 원배정 분석 표본을 걸러내지 않는다. 첫 선택 전 환경 질문으로 선택 자체를 바꾸지 않도록 기대 측정의 시점/독립 표본 여부를 최종 설계에서 명시한다.

## 원문 대조로 확인한 범위

이번 확인은 가까운 선행연구에 대한 표적 대조다. 분야 전체의 체계적 고찰이나 최초성 증명이 아니다.

| 직접 확인한 출처 | 확인한 내용 | 이번 질문에 남는 지식 후보 |
|---|---|---|
| Klesel & Messer, *Good for the Planet, Bad for Me?*, CHI 2026, [원문 §4.1·§4.3](https://arxiv.org/html/2603.23075v1) | 두 선택지 모두 같은 GPT-4o mini를 사용했고, 성능 별점과 에너지 등급을 제시했다. | 실제로 제어되는 두 예산을 사용했을 때, 이름의 총효과가 시도 전체의 소비와 객관적 성과에 남는지를 검증한다. 환경 표시·성능 기대·동일 backend 비교 자체를 새 발견이라고 하지 않는다. |
| [CHI 2027 공식 제출 안내](https://chi2027.acm.org/guide-to-a-successful-submission/), 기여·연구 품질·독창성·투명성 절 | 주장에 맞는 평가 근거, 기존 지식에 보태는 내용, 검토 가능한 방법/자료를 요구한다. | 기대한 절감 방향과 연구 품질을 혼동하지 않는다. 반대 또는 작은 효과도 구체적 지식을 줄 수 있으나 그런 결과 자체가 채택을 보장하지 않는다. |

자료를 더 모으면 관련 연구의 실제 작업·계측·사용 정책을 대조해 이 차별성 후보를 다시 확인해야 한다. ‘실제 두 예산 + 토큰 + J’를 함께 측정한다는 변수 나열만으로 충분한 학술 기여가 입증되지는 않는다.

## 주장마다 필요한 자료

| 주장 | 필요한 자료와 추정대상 | 현재 할 수 없는 확대 |
|---|---|---|
| 낮은/높은 설정이 실제 다른 작동을 한다 | 같은 시스템에서 설정 적용·종료 trace, 시도별 usage, 작업별 성과와 측정 경계 | 설정 이름이나 답변 길이 제한만으로 추론 계산량 차이를 증명 |
| Eco 명칭이 전체 소비를 바꾼다 | 무작위 원배정 집단의 공통 작업/운영정책 아래 참가자별 전체 세션 토큰 및 J | 참가자 없는 기술 벤치로 사람의 명칭 효과 추론 |
| 실제 자원 절감과 성과 비용이 함께 나타난다 | 전체 분모에서 자원 차이와 성공/실패/unknown·완료 결과를 나란히 보고 | 낮은 완료율의 소비 감소를 동일 성과의 효율 개선으로 해석 |
| 환경 기대와 측정 가능한 결과가 어긋난다 | 인식/자기보고 자료와 직접 측정/조건부 추정의 구별 | 설문 점수와 J를 같은 척도처럼 빼거나 동기 자체의 인과 매개로 판정 |
| 특정 맥락에서 효과가 실용적으로 작다 | 해당 맥락에서 사전 정의한 관심 효과/정밀도와 충분히 좁은 구간 | p≥.05만으로 무효과·동등성·모든 분야의 일반 법칙 선언 |

기술 자료만 확보한 단계에는 기술적 사용량·성과·계측 결과까지만 보고할 수 있다. 사람의 이름 선택 효과에는 사람의 실제 선택 자료가 필요하다. 둘을 한 번에 완료했다고 표시하지 않는다.

## 결과 보고 틀

결과 방향을 본 뒤 주 결과를 고르지 않도록 토큰과 J를 각각 고정된 자리에서 보고한다. 지금은 아래 칸에 넣을 실제 결과가 없다.

| 관측 결과 | 보고할 내용 | 피할 해석 |
|---|---|---|
| 토큰↓, J↓, 성과 유지/개선 | 그 작업·시스템·세션 경계에서 관측한 자원/성과 변화 | 품질 유지를 입증할 별도 설계 없이 비유의 차이를 ‘유지’로 명명 |
| 토큰↓, J↓, 성과↓ | 자원 감소와 실제 성과 비용을 함께 공개 | 성공 사례만 남기거나 성과 비용을 숨긴 환경 보증 |
| 토큰↓, J↑ | 지표의 방향 불일치와 시도·전환·실행 경계에 관한 관측 자료 | 토큰 절감이므로 전력도 절약되었다는 환산 |
| 토큰↓, J 미측정/무효 | 토큰 결과와 J의 추론 불가 사유를 별도로 공개 | J=0으로 채움 또는 ‘전력 변화 없음’ |
| J↓, 토큰 미측정/무효 | 검증된 J 결과와 토큰의 추론 불가 사유를 별도로 공개 | J를 이용해 누락된 reasoning 토큰을 복원 |
| 선택은 달라짐, 자원 차이는 넓은 구간 | 선택 효과와 아직 구별하지 못한 소비 변화 | 선택 증가를 절감의 증거로 대신 사용 |
| 관심 효과보다 작은 차이를 정밀하게 추정 | 사전 정한 관심 효과와 구간의 관계 | 근거 없는 ‘효과 없음’, 모든 주제·모델로 일반화 |
| 반대 효과 또는 불완전 자료 | 증가/반대의 근거 또는 미해결임을 투명하게 보고 | 불편한 결과·실패·포기·unknown의 제외 |

화살표는 이 문서의 시나리오 표기이며 실제 검정 결과가 아니다. ‘관측된 평균이 더 작음’과 ‘불확실성을 고려해 감소를 주장함’을 결과표에서 구별해야 한다.

## 개발 분석에서 구체화한 규칙

- 참가자가 분석 단위이고, 과제·요청·attempt 수가 독립 표본 수를 늘리지 않는다.
- 주 대비는 Eco–Low, 핵심 자원은 `reported_tokens`와 `energy_j` 두 개이다. Fast·선택/전환·성과/수용은 별도 보조 보고이다.
- 양측 Welch 평균차 계산은 현재 개발 구현의 선택이다. 본실험의 분포·누락·표본과 적합성 확인 전 확증적으로 사용하지 않는다.
- Holm 가족 크기는2로 유지한다. 계산할 수 없는 endpoint의 내부 보충 p=1은 관측 p가 아니며, 공개 결과는 p=null/추론 불가로 남긴다.
- Welch 95% 구간은 각 endpoint의 **개별 구간**이다. 두 결과에 대한 동시95% 구간이나 Holm 조정 구간으로 표시하지 않는다.
- 한 자원의 누락 때문에 다른 완전한 자원의 추론을 자동 차단하지 않는다. 성과 하락 또는 unknown도 자원 추론의 품질 통과조건이 아니다.
- Fast만 누락되었다는 이유로 Eco–Low의 완전한 주대비를 차단하지 않는다. 원배정 Fast 자료와 누락 현황 자체는 남긴다.

상세한 개발 입력·분모·범위는 [v4-analysis-contract.md](v4-analysis-contract.md)를 따른다. 개발 계산 규칙의 선택은 공개 사전등록·최종 작업·표본/정지 규칙 동결·실제 연구 효과의 인증이 아니다.

## 90점 초과를 위해 남는 실제 근거

B의 고정 기준은 논문/실행 준비도이며 아이디어의 호감도가 아니다. 새 문서와 합성 코드 검사만으로 실제 실행/타당화20점을 채울 수 없다. 나머지 항목을 전부 충족한다고 해도 이 항목이0이면80점이 상한이므로, 토론만 반복해서 B>90을 만드는 것은 불가능하다.

다음은 점수 보장이 아니라 준비 결손을 해결할 순서다.

1. 최종 작업·대상 사용자·운영정책을 좁히고, 실제 두 설정과 작업 성과 평가가 의도대로 작동하는 독립 자료를 확보한다. 코딩 이외 작업도 별도 타당화할 수 있으며 지금 분야를 확정하지 않는다.
2. 실제 usage·계측 원시값으로 token/J 결과의 의미와 누락/오차를 확인한다. 이는 환경 개선의 방향을 요구하는 검사가 아니다.
3. 실제 분포와 연구자가 구별할 가치가 있다고 정한 효과/정밀도에 맞춰 표본·모집/정지·누락·검정 가족·추론법을 결과 관측 전에 동결한다. 숫자를 임의로 채우지 않는다.
4. 사람 연구의 적용 절차와 독립 안내/사용성 확인을 마친 뒤, 허용된 범위에서 실제 자료와 분석의 재현 경로를 만든다.

점수를 높이기 위한 장비 구매·결제·참가자 모집을 여기서 실행하거나 사용자에게 즉시 요구하지 않는다. 실제 실행 경로를 선택할 때 필요한 근거를 명확히 남긴다.
