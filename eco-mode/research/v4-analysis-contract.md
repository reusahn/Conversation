# v4 개발 분석 계약

2026-10-28. A–B·A–D 공개 교차 검토에서 지금 정할 수 있는 비교·결과·분모를 선택한 개발 도구 계약이다. 중단 회차의 초안을 보존해 재검토했으며, 재개된 A–B·A–D·A–C 검토에서 관측 문항과 실행 경계를 보완했다. 사용자 요청에 맞춰 품질 유지를 자원 절감의 필수조건으로 되돌리지 않는다. 고정 v4 심사 기준을 바꾸지 않으며, 최종 연구 과제·표본·실용 효과 기준·기관 절차를 근거 없이 동결하지 않는다. 기존 `protocol-v4.md`의 ‘새 분석 미정’은 그 문서 검토 당시 상태다. 이 계약의 개발 규칙 선택과 실제 본실험 분석 동결은 다르다.

## 1. 이번에 선택한 분석 범위

| 항목 | 개발 도구에서 선택한 규칙 | 남은 실증 범위 |
|---|---|---|
| 주 대비 | Eco–Low | 실제 사용자·작업·정보·모드의 최종 동결과 무작위 배정 증거 |
| 핵심 결과 | 참가자 한 명의 전체 세션 `reported_tokens`, `energy_j` 두 개를 별도로 추정 | 실제 provider 정의·usage adapter·J 측정의 유효성 |
| 효과 방향 | Eco 평균 − Low 평균. 음수와 양수 모두 보고 | 실제 효과·최소 관심 효과·정밀도/검정력 |
| 주 가설 가족 | 위 두 결과의 Eco–Low 비교. 가족 크기2 유지, Welch 양측 검정과 Holm .05를 개발 계산 규칙으로 선택. 결과별 95% 구간은 다중성 미보정 marginal 구간이라고 표시 | 실제 모집/정지·분포·누락·추론법 적합성과 최종 사전등록 |
| 나머지 | Fast 대비, 최초 선택·전환·성과·완료율·수용은 보조 결과 | 확증 주장으로 추가하려면 효과 관측 전 가족·표본 설계를 별도 수정 |
| 품질 | 객관적 성과·실패·포기·unknown을 교환 비용으로 보고 | 최종 작업별 성공/오류 평가 계약·타당화 |

이 선택은 실행 가능한 개발 분석을 만들기 위한 구체화다. 공개 사전등록·연구 개시 승인·본실험 분석 동결이 아니다. 현 단계의 코딩 개발 예제를 최종 K/과제집으로 승격하지 않는다. 사람의 환경 동기 또는 자발적 수용을 실제 관측한 결과도 아니다.

## 2. 명칭 이외에 공통으로 제공할 작업 안내 초안

> 두 모드는 응답 생성에 허용되는 추론 계산량이 다릅니다. 낮은 계산 예산에서는 일부 과제의 답변이 부족하거나 오류가 늘 수 있습니다. 높은 계산 예산도 정답을 보장하지 않습니다. 작업 중 모드를 바꾸거나 다시 요청할 수 있습니다.

이 문구와 낮은/높은 설정의 연결, 기능·위치·색·가격·이용한도·기본 선택 없음은 집단 간 동일하게 제공한다. 바꾸는 것은 낮은 설정의 Low/Fast/Eco 표시 문자열 하나다. ‘환경을 보호합니다’, ‘항상 빠릅니다’라는 성과 보장이나 Eco만의 잎 아이콘·권장 기본값을 보태지 않는다.

실제 두 설정의 제어·과제별 동작이 이 설명을 뒷받침하는지, 참가자가 안내를 이해하는지, 최종 화면에서 같은 정보가 노출되는지는 아직 검증하지 않았다. 안내·동의·목적 설명의 실제 채택은 사람 연구 준비에서 검토한다. 안내를 받았다는 이유만으로 모든 참가자가 실제로 알고 환경을 위해 양보했다고 가정하지 않는다. 첫 선택 전 기대/환경 인식 설문을 새로 필수화하지 않는다.

## 3. 원배정 manifest와 분석 단위

canonical manifest는 각 참가자의 `participant_id`, 원배정 `arm`(Eco/Low/Fast), 배정된 `task_ids`를 가진다. 현재 개발 도구는 모두에게 같은 비어 있지 않은 고정 task 집합을 배정하고 같은 가중치로 성과를 계산하는 범위를 지원한다. 이것은 그 집합이 최종 인간 과제집이라는 뜻이 아니다.

분석 단위는 참가자 한 행이다. 같은 참가자가 여러 과제·재요청·backend attempt를 수행해도 독립 참가자 수를 늘리지 않는다. 동일 participant 중복·배정 충돌·manifest 밖 자료는 입력 오류로 검토한다. 자료 행이 없는 배정자도 제거하지 않고 두 자원 결과는 null, 모든 과제 성과는 unknown으로 복원한다.

주효과는 전체 원배정 참가자의 명칭 총효과다. 관측된 선택 모드·성능·완료·사후 이름 기억/수용에 따라 표본을 다시 선별하지 않는다. 사후 변수를 보정해 명칭 이후 생긴 재요청·포기의 실제 소비 차이를 지우지 않는다.

## 4. 두 자원 결과와 누락

`reported_tokens`는 실제 사용되는 고정 provider/schema의 의미가 확인된 보고 단위다. 입력·completion·reasoning·cached 포함관계가 확인되지 않았거나 authoritative usage가 누락되면 완전한 총토큰이라고 만들지 않는다. 토큰 수는 요금·물리 연산량·J와 같다고 가정하지 않는다.

`energy_j`는 기존 세션 경계의 J다. 명칭 노출 직전부터 입력/산출물 잠금 후 실제 backend-drained까지의 할당 소비이며 실패·재시도·전환·할당 유휴·취소 잔여 실행을 포함한다. 작업 중 공개 운영 피드백과 잠금 후 연구 채점은 구별하고 사후 연구 채점 비용은 별도 보고한다.

사후 연구 채점은 원 세션·실제 drain과 겹치지 않도록 실행한다. 실제 겹침이 있으면 원시값과 귀속 위반을 보존하고 J 유효성을 검토한다. 예상 채점 비용을 빼거나 토큰당 환산으로 조정해 유효한 직접 계측으로 복구했다고 하지 않는다. 입력에 J 숫자가 있다는 사실만으로 이 경계를 만족한 것은 아니다.

누락/무효성은 endpoint별로 처리한다. 토큰이 완전하고 J가 unknown이면 토큰 분석의 정보는 보존하고 J의 주 추론만 보류한다. 그 반대도 같다. 토큰으로 J를 채우거나 J로 내부 reasoning 토큰을 복원하지 않는다. 실제 없음·관측0과 unknown은 다르다.

한 endpoint의 주 대비 Eco/Low 전체 원배정 값이 완전하지 않으면, 해당 endpoint의 전체 배정 평균차를 complete-case 분석으로 대체하지 않는다. 관측 수·unknown 수와 그 범위를 보고하며 주 추론은 보류한다. 실제 근거 없이 유한 상한·평균·0을 넣지 않는다. 보조 Fast 집단의 누락 때문에 완전한 Eco–Low 주 대비를 막지 않는다.

한 결과의 검정을 할 수 없더라도 두 결과의 사전 가족을 줄이지 않는다. Holm 계산에서 보수적 내부 보충값을 사용하는 경우에도 해당 endpoint의 관측 p값·효과는 null/추론불가로 보고해야 한다. 내부 처리용 값이 실제 계산된 검정 결과인 것처럼 표시되면 안 된다.

개발 코드의 주 대비에서 각 arm의 관측 수가2 미만이거나 두 arm 모두 분산0으로 표준오차가0이면 Welch 추론을 보류한다. 한 arm만 분산0이고 다른 arm의 분산이 양수이면 계산은 가능하다. 계산이 가능하다는 사실은 실제 분포·표본·무작위 배정 또는 통계 가정을 확인한 결과가 아니다. 양측 p값과 미보정 95% 구간, 고정 두 결과 가족의 Holm 조정값을 구별한다. 두 구간을 동시95% 신뢰구간으로 부르거나 Holm 보정과 같은 판정이라고 하지 않는다.

## 5. 성과와 완료의 분모

각 배정 task의 최종 불변 산출물을 `success`, `failure`, `unknown`으로 구별한다. 건강한 채점에서의 오답과 확인된 포기/기한 만료/실제 미시작은 규칙에 맞는 관측 실패일 수 있지만, 산출물·로그·scorer/인프라 유실은 unknown이다. AI 호출이 없는 수동 완성은 공통 정책이 허용하면 성공일 수 있다.

모든 배정 과제를 같은 가중치로 보고한다. 성공/실패/unknown count, 알려진 실패를 바탕으로 한 실패율의 최선·최악 식별 범위, 완료/포기 등은 자원 변화 옆에 둔다. 이 범위를 통계적 신뢰구간으로 부르지 않는다. 품질이 낮거나 unknown이 있다고 토큰/J의 별도 유효한 결과를 자동 차단하지 않는다. 반대로 자원 감소만으로 동일 성과 효율 개선이나 사용 적합성을 보장하지 않는다.

## 6. 입력 일치와 진위 인증의 경계

집단 간 비교 전에 token metric 정의·단위·설정 버전, J의 source/device/scope/epoch 정책 등 필요한 비교 가능성을 확인해야 한다. 입력 metadata의 일치 검사는 실제 서버 설정 적용·센서 정확도·실제 참가자 무작위 배정·자료 진위를 인증하지 않는다.

개발 API는 `analyze(manifest, rows)`이며, 각 자료 행은 `participant_id`, `reported_tokens`, `energy_j`, `outcomes`, `token_definition_id`, `energy_scope_id`를 가진다. 각 endpoint는 Eco/Low에서 값과 그 endpoint의 정의ID가 모두 있고 동일하게 선언되어야 통계를 계산한다. 이 두 ID는 위에 열거한 실제 provider·장치·scope·단위 근거를 가리키는 선언이다. ID가 같은 문자열이라는 검사만으로 그 근거를 인증하지 않는다. token ID와 energy ID의 누락/충돌은 각각 처리한다.

현재 도우미 실행환경에서 GPU·전력계측 경로가 보이지 않는다는 읽기 결과는 그 환경에 관한 자료다. 사용자의 컴퓨터나 권한 있는 다른 서버가 없다는 증거로 확대하지 않는다. 현재 실제 모델·센서·사용자 자료는 없으며 합성 실행은 그렇게 표시한다.

`confirmatory_allowed=false`를 유지한다. 이 계약에 따른 개발 도구가 실행되어도 실제 연구 효과·표본/정지 규칙·계측 타당성이 자동 승인되지 않는다.

## 7. 안내·이해·수용·환경 기대의 최소 관측안

다음은 사람 연구 준비에서 검토할 문항/로그 초안이며, 타당화된 척도나 이미 수집한 참가자 응답이 아니다. 공통 안내와 실제 예산 설정이 맞는지 확인한 뒤 문구를 동결한다. 사전 기대가 필요하면 본실험 첫 선택과 분리된 독립 지각 표본을 사용한다는 후보를 유지한다. 본실험 첫 선택 직전에 환경 기대를 자세히 물어 환경을 떠올리게 하는 절차를 새로 넣지 않는다.

| 구분 | 제안한 관측 | 해석 경계 |
|---|---|---|
| 공통 안내 제공 | 안내 버전·배정 arm·렌더 시각·확인 버튼 시각 | 화면 노출/버튼 누름은 실제 읽음·이해의 증거와 다름 |
| 안내 이해 | 작업 뒤 낮은 예산에서 일부 답변이 부족할 수 있다는 설명을 어떻게 이해했는지 확인; ‘모르겠다’ 응답 허용 | 사후 응답으로 그 사람이 선택 당시 이해했다고 확정하지 않음 |
| 성능 손해 수용 | 작업 뒤 ‘답변 성과가 다소 낮아질 가능성을 받아들일 의향’과 실제 경험한 만족을 별도로 질문 | 일반 수용 의향과 실제 해당 선택의 동기, 객관 성과는 서로 다름 |
| 보고한 선택 이유 | 정확성·속도·사용량/비용·환경 가치·기타 이유를 구별하는 사후 응답 | 환경 동기의 인과 매개 증명이나 참가자 진정성 판정이 아님 |
| 전력 소비 인식 | 비교 대상·대조 조건·기간/계측 경계를 명시한 전력 소비 예상 방향(적음/비슷함/많음/모르겠음)과 응답 시점 | 실제 사전 믿음의 복원이 아니며 토큰·J와 같은 단위의 숫자가 아님 |
| 넓은 환경 이익 기대 | 탄소·물·기타 자연보호 중 무엇을 기대했는지 따로 기록 | 필요한 조건자료 없이 탄소·물 효과를 계산하거나 넓은 생태 효과를 직접 입증하지 않음 |
| 실제 성과·소비 | 최종 산출물의 성과·완료/포기·reported_tokens·측정 경계 내 J | 참가자의 보고한 동기나 자발적 수용을 자동 입증하지 않음 |

문항의 응답 선택지·순서·척도와 이해도는 독립 파일럿에서 확인해야 한다. 위 표 자체를 완성된 설문지나 검증된 측정도구로 표시하지 않는다. 단위가 다른 인식 점수와 J를 단순히 빼서 ‘인식–실제 오차’ 수치를 만들지 않는다. 방향상 일치/불일치를 기술하더라도 참가자 단위의 사후 인식과 집단 간 명칭 총효과를 혼동하지 않고 측정 시점·집계 수준·범위를 명시한다. J의 누락·무효 또는 넓은 불확실성이 있으면 환경 인식과 실측이 어긋났다고 확정하지 않고 ‘측정 미확인/불확실’로 남긴다. 유효한 방향 비교도 명시한 세션·GPU/시스템 범위에 한정한다. 사후 기억·이해·수용·이유 응답이나 무응답으로 자원 주분석 표본을 제외하지 않는다.

예를 들어 ‘내가 낮은 모드 대신 높은 모드를 썼다면 전력을 더 썼을 것이다’는 개인의 모드 반사실에 대한 기대다. 이것은 낮은 모드의 이름만 다른 Eco–Low 집단 평균차라는 주 추정대상과 다르다. 개인이 선택하지 않은 모드에서 썼을 실제 전력은 관측하지 않았으므로, 두 값을 비교해 그 사람의 인식이 정확하거나 틀렸다고 판정하지 않는다. 대상·대조·시간·범위·집계 수준이 맞지 않으면 기대와 실측은 각각 병렬 설명한다. 향후 인식 정확도 자체를 검정하려면 비교대상에 맞는 별도 설계와 사전 규칙이 필요하며, 이번 개발 도구에 그 검정을 추가하지 않는다.

## 8. 본실험 동결 전 남은 결정

| 결정 묶음 | 그때 확인할 근거 | 현재 상태 |
|---|---|---|
| 작업/사용자 범위 | 실제 사용 맥락, 최종 과제와 공통 시간·모드·재요청 정책, 결과물별 성공/실패 계약 | 미확정. 코딩은 개발 후보이며 최종 분야가 아님 |
| 실제 운영과 안내 | 두 예산의 실제 적용 trace, 화면 동일성, 안내 사실성·독립 이해도 확인 | 미검증 |
| 계측과 오류 | 실제 usage/센서 원자료, 완전한 attempt 분모, drain·중복·누락·불확실성 | 개발 계약과 합성 검사로 대체하지 않음 |
| 표본·정밀도 | 최종 단위와 분포의 독립 예비자료, 최소 관심 효과 또는 목표 구간 폭의 실질적 근거, 두 결과 가족을 반영한 계획 | 최종 N·모집/정지 규칙 없음. 임의 N이나 v3 NI 허용폭을 가져오지 않음 |
| 실행 중 정지/변경 | 효과 유의성에 따른 임의 중지 금지, 운영상 중단과 누락 처리, 변경 시점·이유 기록 | 본실험 시작 전에 구체화·동결해야 함 |
| 사람 단계 | 적용되는 절차와 동의·모집·운영, 데이터 처리와 비용/시간 범위 | 확인된 승인·참가자 자료 없음 |

독립 예비자료는 본실험 효과를 보고 유리한 작업·N·검정법을 고르는 수단이 아니다. 본실험에서 효과 방향·유의성을 확인한 뒤 계산 규칙을 확증 규칙으로 바꾸지 않는다. 준비 부족으로 중단한 연구는 그 중단과 불확실성을 보고하며, 유의하지 않다는 이유만으로 무효과·동등성이라고 결론내리지 않는다.
