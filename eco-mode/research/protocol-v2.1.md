# Eco 모드 연구 계획 v2.1

상태: 연구 설계와 합성 검사 단계. 참가자 모집·실제 모델 실행·장비 에너지 실측은 아직 수행하지 않았다.
이 문서는 가상 자문과 연구 준비용 초안이며 사전등록이나 제출된 논문이 아니다.

## 연구를 한 문장으로

같은 저추론 설정을 ‘Eco’라고 부르는 것이 사용자의 연산 선택을 바꾸고, 재시도·실패·고추론 전환까지 포함한 총에너지를 답변 품질을 유지하면서 줄이는지 검증한다.

## 제목 후보

**Eco라는 이름은 적절한 연산 선택을 돕는가? 추론 모드의 명명이 생성형 AI의 작업 성과와 총에너지 소비에 미치는 영향**

## 범위와 기여

주요 기여 후보는 동일한 실제 실행 설정에서 Low/Fast/Eco라는 이름의 무작위 배정 효과를 선택, 과제 품질, 전체 세션 에너지로 함께 검증하는 것이다.
단순한 친환경 선호, 환경 피드백, 과제당 총자원 집계 자체를 최초 기여라고 주장하지 않는다.
환경 영수증, 물 사용 환산, 장기 반동효과는 후속 연구 후보로 남긴다. 해커톤은 연구 범위에 포함하지 않는다.
현재 연구자는 혼자 준비하며, 참가자는 사람의 선택 효과를 검증할 단계에서 필요성을 다시 판단한다.

## 연구 질문

- RQ1: 같은 저예산 설정을 Low, Fast, Eco로 제시하면 최초 저예산 선택률과 이후 전환·재시도 패턴이 달라지는가?
- RQ2: Eco 명명은 재시도·실패·포기·고예산 전환을 포함한 전체 세션 에너지를 줄이면서 사전에 정한 품질 기준을 충족하는가?
- RQ3: 이러한 차이는 과제의 구조적 복잡도와 독립 벤치마크로 확인한 저예산 충분성에 따라 어떻게 달라지는가?

주된 인과 추정 대상은 무작위로 배정한 이름의 총효과이다. 이름의 효과만으로 환경 동기를 분리하거나, ‘이름→선택→에너지’의 인과 매개 경로를 입증했다고 주장하지 않는다.
Low 대비 Eco와 Fast 대비 Eco의 대비를 미리 정한다. 방향이 기대와 반대이거나 차이가 없어도 같은 질문에 대한 결과로 보고한다.

## 조건과 과제

참가자 간 세 집단을 무작위 배정한다. 한 사람은 저예산 선택지의 이름 하나만 본다.
낮은 설정의 표시만 Low/Fast/Eco로 바꾸고, 높은 설정은 공통 High로 둔다.
설명, 색, 아이콘, 가격 표시, 과제 순서 규칙과 서버 실행 설정은 같게 한다. 최초 선택은 사전 선택 없는 능동 선택이다.

같은 가중치·리비전·토크나이저·정밀도·서버·샘플링·시스템 프롬프트·캐시 정책을 사용한다.
저·고 예산의 실제 차이는 지원되는 제어값과 관측 로그로 확인한다. 조건 이름이 서버의 모델이나 예산을 추가로 바꿔서는 안 된다.

기술 후보는 Qwen/Qwen3-4B와 vLLM이다. 설치·장비 적합성·버전별 지원은 아직 확인하지 않았다.
검토할 후보 설정은 enable_thinking=true, thinking_token_budget=256/2048, 공통 max_tokens=8192, temperature=0.6, top_p=0.95이다.
필요한 reasoning parser와 실제 API 제어 지원을 먼저 확인하고, 예비 실행 후 설정을 고정한다.
max_tokens가 추론과 답변을 함께 제한하면 답변 길이 혼입이 생길 수 있다. 관측 추론 토큰, 강제 종료 표시, finish_reason, 잘림을 기록한다.
혼입을 제거하거나 해석할 수 없으면 백엔드 변경·범위 축소·중단 중 하나를 택하며 순수 추론 예산 효과라고 표현하지 않는다.

현재 준비한 네 JavaScript 과제는 엔지니어링 예제이다.
T01 유한 수 합계, T02 태그 정규화, T03 구간 병합, T04 보상 최대화이다.
각 과제의 참조 구현과 의도적으로 잘못된 구현에 대한 검사는 마련했지만 실제 LLM 출력이나 사람이 느끼는 난도를 측정하지 않았다.
구조적 복잡도, 사람의 난도, 낮은 예산의 성공률을 서로 같은 것으로 취급하지 않는다.
독립 예비 벤치마크로 최종 과제·숨김 테스트·충분성 분류 규칙을 고정한다. 경계가 불확실하면 미분류로 두고 RQ3는 탐색적으로 보고한다.
과제가 네 개로 제한되면 그 과제 집합을 넘는 일반화를 제한한다.

## 에너지와 품질

주 에너지 지표는 독립적으로 할당된 백엔드 세션의 시작·종료 누적 카운터 차이이다.
GPU 카운터를 쓰면 GPU 범위, 외부 입력 전력계를 쓰면 해당 시스템 입력 범위로만 부른다. 서로 다른 경계의 값을 섞지 않는다.
세션 중 서버가 해당 실험에 전용으로 할당되도록 하고, 동시 추론을 초기에는 직렬화한다.
세션 시작, 과제 시간 제한, 종료 후 잔여 실행 대기와 실제 백엔드 정지까지의 경계를 예비 단계에서 정한다.
유휴·워밍업 정책을 고정하고, 세션 총량과 활성 호출 합계·유휴/미귀속 잔차를 구분한다. 활성 호출 합계를 세션 총량에 다시 더하지 않는다.

최초 요청, 재질문, 재생성, 상향 전환, 실패, 취소 후 잔여 실행, 운영상 검증 호출을 포함한다.
연구용 사후 채점의 자원은 운영 중 검증과 구분해 별도 보고한다.
실패·포기한 과제도 전체 분석에 남긴다. 성공한 과제만의 에너지 절감으로 결론내리지 않는다.
실제로 호출하지 않은 과제의 호출 수·토큰은 0이다. 할당된 세션의 유휴 에너지가 있다면 주 지표에는 남는다.
시작되지 않은 과제의 품질/상태와 에너지 누락은 별도로 기록한다.

센서 미지원·누락·리셋·중첩·서로 다른 범위의 혼합은 0으로 치환하지 않는다.
원시값, 단위, 센서 갱신·해상도·정확도, monotonic 시각과 UTC 대응, 센서 호출 전후 시각을 남긴다.
반복 실행의 분산과 계측기의 체계적 오차를 구분한다. 반복만으로 편향이 제거된다고 가정하지 않는다.
취소 시 프런트엔드 응답이 끝나도 실제 실행이 끝날 때까지 계측한다.
누락이 있으면 사전 규정한 범위 민감도 분석을 하고, 에너지 효과를 식별하거나 불확실성보다 큰 차이를 검증할 수 없으면 확증적 절감 주장을 중단한다.

품질은 사전에 정한 객관적 테스트와 최종 과제 성공률로 평가한다.
‘품질 유지’는 유의한 차이가 없다는 뜻으로 판정하지 않는다.
허용 가능한 추가 실패폭 δ를 연구자가 실제 사용 맥락과 근거로, 라벨 효과를 보기 전에 정한다.
별도 예비자료의 분산·참가자/과제 상관으로 필요한 표본을 계산한다.
표본이 부족하면 δ를 느슨하게 바꾸지 않고 범위 또는 확증적 주장을 줄인다.
어려운 과제의 하락을 전체 평균으로 가리지 않도록 사전에 지정한 구간별 결과와 불확실성을 보고한다.

## 분석과 표본의 확정 관문

모든 무작위 배정 대상과 배정 과제를 포함하는 원칙을 따른다.
Eco–Low, Eco–Fast의 사전 대비에 다중 비교를 반영한다.
최초 선택률과 전체 세션 에너지의 효과 크기 및 신뢰구간, 품질 비열등성 기준을 각각 보고한다.
참가자 내 반복 과제와 과제 간 차이를 고려한 모형을 쓴다.
정확한 모형식, 분포·변환, 무작위 효과, 제외 규칙, 이상치 규칙, 누락 처리, 구간별 판단과 검정 순서는 독립 예비자료 이후 본실험 전에 고정한다.
현재 이 항목들은 확정되지 않았으며 완료된 사전등록으로 표현하지 않는다.

power-sensitivity.json은 최초 이항 선택에 대한 독립 표본 근사 시나리오이다.
기준 선택률 30%에서 40/45/50%를 가정하면 세 집단 총수는 각각 1296/591/339명이다.
이는 확정 표본 수가 아니고, 에너지 및 품질 비열등성의 검정력도 아니다.
현재 여건에 맞는 δ·변동·검정력을 확인하지 않고 임의로 ‘30명이면 충분’이라고 정하지 않는다.

## 단계와 통과 조건

| 단계 | 혼자 지금 가능한가 | 산출물 | 다음 단계 조건 |
|---|---|---|---|
| S0 기술·계측 예비실험 | 자원 확인 후 가능, 참가자 불필요 | 실제 환경표, 모델 예산 작동 로그, 원시 에너지·오차·반복 변동 | 예산 제어와 측정 해상도·경계가 목적에 적합 |
| S1 시스템 구현 | UI·로그·합성 검사는 가능 | UI→서버→원시 로그→집계→채점, 사건 재현 검사 | 설정 불변성·중복·실패·취소·시각 조정 검사 통과 |
| S2 사람 실험 준비 | 별도 단계 | 필요한 기관 절차 확인, 독립 예비자료, δ·검정력·분석 사전등록 | 자원·품질·표본·윤리 절차가 본실험을 뒷받침 |
| S3 본실험 | 필요 시 참가자 모집 | 무작위 배정된 실제 사람의 선택·품질·총에너지 결과 | 사전 규정대로 분석 및 한계 보고 |

장비·가용 자원·비용 상한을 확인하기 전에는 실제 모델 S0를 시작하지 않는다.
GPU/메모리/OS/센서 지원/시간 한도와 지출 상한을 연구자가 확정한 뒤 그 범위에서 반복 횟수를 산정한다.
상한 초과 예상 또는 센서 미지원이면 중단하거나 무지출 문헌·UI·fixture 준비로 축소한다.
사용자 확인 없는 유료 API·클라우드·장비 구매는 하지 않는다. 실측이 없으면 에너지 실증 본실험을 차단한다.
지금의 클라우드 실행환경이나 가상 자문이 연구자 소유 장비 또는 데이터센터 접근권을 뜻하지 않는다.

참가자 없는 기술 준비 자체를 실제 사람의 행동 효과로 해석하지 않는다.
사람 대상 연구는 해당 소속·활동에 적용되는 절차를 모집 전에 확인한다. UCSB의 절차 필요성과 구체적인 심의/면제 해당 여부를 이 초안만으로 확정하지 않는다.
독립 연구 및 단독 저자로 준비하는 것과 모든 연구 단계에 참가자가 없어도 된다는 것은 별개이다.

## 현재 확보된 증거와 미확인 사항

- 합성 엔지니어링 검사 42/42 통과: 함수 참조 예제, 의도적 오류 검출, 합성 에너지 집계·중복·누락·취소 처리의 제한된 검사이다.
- Node 실행 완료 보고가 있으며 결과 JSON을 보존했다. 다른 페르소나가 모두 독립 재실행한 것은 아니다.
- UI, 실제 모델, GPU/외부 전력계, 센서 시각 정렬, 프로덕션 설정 해시, 코드 격리 실행은 검증하지 않았다.
- 장비, 비용, δ, 최종 과제 구간, 표본 수, 확정 분석 모형은 미확인이다.
- 에너지 절감·품질 유지·행동 변화·논문 채택은 아직 결과가 없다.

## 환경에 대한 해석

에너지가 줄더라도 탄소·물·자연환경 파괴 방지를 직접 증명한 것은 아니다.
탄소와 물은 지역·시간의 전력 구성, 냉각 방식, PUE/WUE 등 추가 자료와 경계를 바탕으로 별도 추정해야 한다.
한 장비 또는 한 세션의 효과를 데이터센터 총전력·물·최대부하나 사회 전체 수요 감소로 일반화하지 않는다.
장기 사용량 증가와 반동효과는 후속 실험에서 검증할 질문이다.
