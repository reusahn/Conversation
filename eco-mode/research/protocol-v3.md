# Eco 모드 연구 계획 v3

2026-10-27. 연구 설계와 합성 도구 준비 단계이다. 실제 LLM 실행·센서 계측·사람 실험·효과 결과는 아직 없다.

## 연구를 한 문장으로

같은 저추론 설정을 ‘Eco’라고 부르는 것이 사용자의 연산 선택을 바꾸고, 실패·재시도·상향 전환을 포함한 전체 세션 에너지를 품질을 유지하면서 줄이는지 검증한다.

제목 후보: **Eco라는 이름은 실제 절약으로 이어지는가? LLM 추론 모드 명명이 선택·과제 품질·세션 에너지에 미치는 영향**

## 연구 질문과 기여

- RQ1: Low/Fast/Eco 명명이 최초로 제출이 확정된 저예산 선택률과 이후 전환·재시도에 영향을 주는가?
- RQ2: 명명의 총효과가 전체 세션 에너지 감소와 사전에 정한 품질 유지를 함께 충족하는가?
- RQ3: 이 차이는 과제의 구조적 복잡도와 독립 벤치마크로 확인한 저예산 충분성에 따라 어떻게 달라지는가?

기여 후보는 명명에 따른 선택 변화와 품질을 유지한 전체 세션 절감이 일치하거나 어긋나는 조건을 검증하는 것이다.
기존의 환경 라벨·피드백·전체 과제 자원 집계 자체를 최초 기여라고 주장하지 않는다.
명칭 무작위화의 총효과를 검증하며 환경 동기만의 효과나 선택의 인과 매개 경로를 입증했다고 하지 않는다.
차이가 없거나 에너지·실패가 증가해도 같은 질문의 결과로 보고한다.
해커톤은 제외한다. 영수증·물 환산·장기 반동효과는 후속 연구 후보이다.

## 조건과 과제

참가자 간 Low/Fast/Eco 세 집단에서 낮은 설정의 이름만 바꾼다. 높은 설정은 공통 High이다.
적용 기관 절차·설명동의·계측 준비 후 최초 명칭 노출 전에 참가자 단위1:1:1 서버 무작위배정을 계획한다. 한 사람은 한 저예산 이름만 보며 배정 manifest를 보존하고 모든 배정자를 분모에 남긴다. 사전 고정 과제순서 배정규칙도 공통으로 적용한다. 실제 배정 UI·모집·사람 검증은 아직 수행하지 않았다.
동일 설명·색·아이콘·가격·과제 배정 규칙을 쓰며 최초에 미리 선택된 기본값은 없다.
참가자 모두에게 최종 고정 K개 과제를 배정하고, 주 분석은 참가자 한 행으로 한다.
현재 개발용 과제 4개(T01 유한 수 합계, T02 태그 정규화, T03 구간 병합, T04 보상 최대화)는 객관 테스트를 갖춘 엔지니어링 예제이다.
실제 사람의 난도·모델 성능·저예산 충분성을 확인한 최종 과제집은 아니다.
구조 복잡도, 사람이 느끼는 난도, 저예산 성공률을 동일시하지 않는다.
독립 예비 벤치의 low 성공률 CI 하한이 사전 p_min을 충족하면 충분, 상한이 미달하면 불충분, 나머지는 미분류로 두는 분류안을 검토한다.
실제 p_min·숨김 테스트·seed·반복 횟수는 사용 맥락의 근거와 함께 라벨 효과를 보기 전에 동결한다.
미분류 과제도 전체 품질에서 빠지지 않는다. RQ3는 분류·표본 근거가 부족하면 탐색적으로 남긴다.
일반화는 선택한 고정 과제집으로 제한한다.

## 실제 모드 제어 관문

후보는 Qwen/Qwen3-4B+vLLM이며 설치·버전·장비 적합성은 미확인이다.
후보 의도 예산은 256/2048, 공통 max_tokens=8192, temperature=.6, top_p=.95이다. 실제 설정 확정·실행 결과가 아니다.
같은 가중치/리비전/토크나이저/정밀도/프롬프트/샘플링/캐시 정책/서버와 응답 스키마를 핀한다.
공통 설정과 전체 두 모드 표의 해시를 표시 조건 간 대조한다. 모드 차이는 사전에 허용한 추론 예산 필드만 가능하다.
이름을 서버 설정에 넣거나 이름에 따라 모델·모드 예산을 바꾸지 않는다.
해시와 서로 다른 의도 예산은 실제 백엔드의 설정 적용 증거가 아니다. intended/effective budget, 실제 토큰과 종료 trace가 필요하다.
독립적으로 고정한 긴 추론 진단 입력으로 두 제어 경로를 검증한다. 짧은 자연 종료는 제어 실패가 아니다.
토큰 집계 규칙·special-token overhead·반복 횟수는 핀한 구현의 근거로 S0 전에 확정하며 임의 여유치를 만들지 않는다.
natural_end/reasoning_budget_stop/total_cap_stop/cancelled/transport_failure/server_failure/unknown을 구분한다.
공유 출력 제한의 답변 영향이 해소되지 않으면 ‘순수 추론 예산 효과’ 주장을 차단한다. 고정된 두 운영모드의 명명 총효과라는 질문은 유지할 수 있다.
vLLM 문서처럼 응답 필드·구조가 바뀔 수 있으므로 response_schema_version을 핀하고 필드 누락을 토큰0으로 넣지 않는다.
현재 response_observation은 평탄한 합성 자료 helper이며 실제 vLLM 중첩 응답 adapter·강제 종료 검증은 미구현이다.

S0 통과를 ‘Low가 반드시 덜 소비한다’는 효과 부호로 정하지 않는다.
실제 예산 제어와 세션 수준의 측정 식별 가능성이 관문이다.
단일 호출 차이가 해상도보다 작아도 세션 누적 효과 검출 가능성은 별도로 판단한다.

## 결과 정의

최초 선택 L_i는 최초로 서버가 수락해 기록한 제출 모드가 low이면1, high 또는 실제 무선택이면0이다.
UI 토글 자체와 구분한다. 완전한 관측 기한에 제출이 없을 때만 none이다.
로그 유실·의미가 불일치하는 사건은 unknown이며 0으로 바꾸지 않는다. low/high/none/unknown 빈도를 각각 보고한다.

품질 F_i는 전체 배정 K개에서의 실패 비율이다.
관측 성공0, 관측 실패·포기·시간만료·실제 미시작1이다. 결과 유실은 [0,1] 불확실 구간으로 남긴다.
필수 overall 구간은 K 전체이다. 사전에 지정한 복잡도/충분성 구간도 평가하며 어려운 과제를 공동판정에서 빼지 않는다.
실용적으로 허용할 추가 실패율 δ_s를 절대비율로, 효과를 보기 전에 연구자가 근거와 함께 정한다.
표본 수에 맞춰 δ를 느슨하게 만들지 않는다. 실제 δ와 최종 표본 수는 아직 미확정이다.

에너지 E_i는 전용 백엔드 할당의 명칭 노출 직전부터, 최종 완료·확정 포기·공통 최대시간 중 먼저 온 종료 사건에서 신규 요청을 막고 실제 backend-drained까지의 누적 카운터 차이이다.
공통 최대시간은 독립 기술·사용성 예비자료에서 라벨 효과 전에 정한다.
조기 완료 뒤 남은 최대시간 유휴를 억지로 붙이지 않는다. 취소 요청 뒤 잔여 실행은 포함한다.
최초 호출·재질문·재생성·상향 전환·실패·포기·운영상 검증과 세션 유휴를 포함한다.
무호출 과제의 토큰/호출 수는0이지만 할당된 세션의 유휴 에너지는 남는다.
연구용 사후 채점은 운영상 검증과 나눠 별도 보고한다.

## 계측·기록 규칙

GPU 카운터는 GPU 범위, 외부 입력 전력계는 해당 시스템 입력 범위로만 부른다. 초기에는 전용 할당·직렬 실행으로 귀속을 통제한다.
원단위 정수 누적값에서 차를 계산한 뒤 J로 변환한다.
source/device/scope/epoch/unit, 읽기 bracket, 순서·포함성·리셋·누락을 감사한다.
API read bracket은 실제 센서 샘플 취득 시각이 아니다. sensor age·갱신 지연·reset 관측 근거가 없으면 미확인으로 남긴다.
epoch 문자열만으로 리셋이 없었다고 인증하지 않는다.
세션 총량은 주 지표, 활성 호출 합계와 잔차는 보조이다. 다시 더해 이중 집계하지 않는다.
identity·구간·순서 감사가 실패하면 활성 합계나 known floor를 믿을 수 있는 하한으로 남기지 않는다.
설정 해시·조건 불변성·사건 의미가 충돌하면 해당 프로토콜의 선택/품질 분석 필드를 unknown으로 격리하고 확증을 중단한다. 실제 관측을 지우거나 실패0으로 바꾸지 않도록 raw_first_submitted_mode와 reported_outcomes 및 원본 사건을 함께 보존한다. 모든 배정 행은 그대로 두고 원자료의 관측 결과와 프로토콜 일치 여부를 별도 보고한다.
끝점 raw 차와 전체 감사 통과를 구분하며, 누락·오류는0으로 치환하지 않는다.
가정된 ±오차·센서 주기·PUE/WUE를 실측값으로 만들어 넣지 않는다.
합성 자료는 measured_total_energy_j=null, synthetic_total_energy_j 별도 필드로 출력한다.
센서·manifest·해시의 입력 선언을 코드가 실제 장비/사람의 진위로 인증하지 않는다.
세션 내 epoch 일관성과 세션 간 드라이버 재시작은 별도 정책이다.
상세는 S0-metering-spec.md에 보존한다.

## 분석 준비 규칙

두 대비 Eco–Low, Eco–Fast에서 참가자 평균차를 구한다. 과제 수를 독립 표본 수로 세지 않는다.
명시적 가명 participant_id와 전체 사전배정 manifest를 대조해 모든 배정자가 한 행씩 남도록 한다.
동일 backend 해시와 측정 source/device/scope/unit을 조건 간 확인한다.
현재 코드는 manifest 일치만 확인하며 실제 모집·무작위 배정·독립성은 인증하지 않는다.

확증 주장 가족은4개이다: 두 대비의 최초 저예산 제출 차이2개, 두 대비의 ‘에너지 감소 AND 모든 사전 품질 기준 비열등’ 공동주장2개.
가족 α=.05를 Bonferroni로 나누어 주장당 α=.0125를 쓴다.
공동주장은 ΔE 단측상한<0 AND overall·모든 사전 품질구간 ΔF_s 단측상한<δ_s를 모두 요구한다(IUT).
개별 구성 구간을 동시신뢰구간이라고 부르지 않는다.

준비 코드의 선택·품질은 독립 참가자·[0,1] 결과를 전제로 보수적 Hoeffding 경계를 일관되게 쓴다.
선택은98.75% 양측, 품질은98.75% 단측이다. 누락의 최선·최악 식별 경계를 반영한다.
전원 성공/분산0이어도 불확실성을0으로 두어 자동 비열등 판정하지 않는다.
이 방법은 큰 표본이 필요할 수 있다. 실용 δ·독립 예비자료·비용·모집 가능성 확인 전 최종 표본/사전등록이 아니다.

에너지는 raw J 평균차의 Welch 단측 상한 준비 함수이다. 유한 표본에서 근사이며 왜도·꼬리·분산·독립성의 실제 예비 점검을 대신하지 않는다.
n<2·분산0·에너지 누락이면 판정하지 않는다. 완전 사례나 성공 사례만의 분석으로 확증을 통과시키지 않는다.
실제 근거의 누락 상한이 없으면 임의 상한·0·평균으로 채우지 않고 에너지 확증을 차단한다.
이상치 삭제·winsorization·유리한 변환을 결과를 보고 고르지 않는다. 사전 계측 오류만 원시 로그를 보존하고 null 처리한다.
로그/중앙값은 보조이다.

analysis_prepare.py는 어떤 입력에서든 confirmatory_allowed=false이다.
numeric_joint_rule은 입력 가정의 수학적 조건 점검이며 연구 효과 판정이 아니다.
analysis-appendix-v3.md에 수식·근거·가정을 보존한다.
과거 power-sensitivity.json은 v2의 이항 정규근사 시나리오이며 v3의 α 배분·품질 경계·에너지 검정력/최종N으로 재사용하지 않는다.

## 혼자 수행할 단계

| 단계 | 산출물 | 통과 조건 |
|---|---|---|
| 현재 무참가자 준비 | 문헌 대조, 사건·계측·분석 코드, 합성 반례 검사 | 설계와 구현의 일치·미구현 범위 보존 |
| S0 실제 기술·계측 예비실험 | 확인된 장비·버전·예산 작동, 원시 counter·오차·변동 | 자원 상한 안에서 예산 제어·측정 식별 가능 |
| S1 전체 시스템 연결 | UI→서버→로그→집계→채점 | 실제 설정 불변성·취소·끊김·누락 검증 |
| S2 사람 실험 준비 | 적용 기관 절차 확인, 독립 예비자료, δ/N/분석 사전등록 | 실제 자원·품질·모집/검정력 근거 |
| S3 본실험 | 무작위 배정된 실제 사람의 선택·품질·에너지 | 사전규칙에 따른 결과/한계 보고 |

장비·가용 시간·지출 상한 확인 전 실제 모델 S0를 시작하지 않는다.
상한 초과 또는 센서 미지원이면 중단하거나 무지출 문헌·코드 준비로 축소한다. 사용자 확인 없는 유료 API·클라우드·장비 구매는 하지 않는다.
