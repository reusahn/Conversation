# Eco 모드 연구계획서

답변의 충분함과 조건부 성능 양보를 탐색하는 사용자 연구

안종훈 Jonghoon Ahn  |  2026년 10월 30일  |  한국어 1차 계획

## 연구 개요

본 연구는 AI 채팅 서비스의 Eco 모드에서 사용자가 기대하는 기능과 환경적 이익, 지키려는 요구와 양보할 수 있는 요소를 탐색한다. 연구자가 준비한 답변 사례를 검토하는 인터뷰를 통해, 같은 답을 받아들이더라도 충분해서인지, 부족함을 감수하는지, 직접 확인하거나 고칠 계획인지 살펴본다.

첫 연구는 실제 저연산 기능을 구현하기 전에 필요한 사용자 관점의 설계 지식을 얻는 단계이다. 참가자는 준비된 사례를 보는 연구임을 안내받으며, 실제 전력 절감이 발생한다고 설명하지 않는다.

## 중심 연구 질문

**사용자는 Eco 모드에서 무엇을 줄여도 충분하다고 판단하며, 부족한 부분을 이해한 뒤 무엇을 지키거나 직접 보완하려 하는가?**

## 이 연구에서 확인할 내용

- Eco라는 이름과 기능 구상에서 예상하는 동작과 환경적 효과
- 응답을 보기 전에 지키려던 요구와 검토 후의 수용·수정·전환·중단 판단
- 답변에 남은 일을 누가 어떻게 확인하거나 보완하려 하는지
- 이러한 판단에 근거한 Eco 기능 요구사항 후보

## 산출물과 현재 범위

산출물은 개인별 판단 연결표, 같은 선택을 보인 대조 사례, 근거가 추적되는 기능 요구사항이다. 현재 계획은 모사 상황에서의 기대와 수용 판단을 다룬다. 모드의 실제 채택률, 인식의 평균 증가, 장기 사용량, 전력과 배출 감소 및 모델 개발 속도는 별도 자료와 설계로 확인한다.


# 1 연구 배경과 기여

## 왜 이 질문이 필요한가

Eco라는 이름에는 자원을 덜 쓴다는 기대와 함께 설명의 축소, 낮은 성능 또는 이용 방식의 변화가 연상될 수 있다. 그러나 짧은 답은 충분한 답일 수도 있다. 답을 수용했다는 기록만으로 무엇을 양보했고 무엇이 남았는지 알기는 어렵다. 본 연구는 사용자가 설명하는 충분함과 남은 확인 부담을 구체적인 응답 사례에 연결한다.

## 세부 연구 질문

- RQ1  사용자는 Eco의 기능과 환경적 효과를 어떻게 예상하며 제공된 설명을 어떻게 이해하는가
- RQ2  과제가 정한 조건과 사용자가 스스로 지키려는 요구는 어떻게 구분되고 응답 검토 뒤 어떻게 유지되거나 수정되는가
- RQ3  수용·수정·전환·중단의 이유와 직접 맡으려는 확인·보완은 무엇이며 개인 참고와 타인 전달 맥락에서 어떻게 설명되는가

예를 들어 같은 간결한 답을 받아들여도 답만으로 충분한 경우와 사용자가 추가 확인을 계획하는 경우에는 원하는 기능이 다를 수 있다. 이는 검토할 설명의 예이며 수집된 결과가 아니다.


# 2 연구 설계와 진행

## 방법과 참가자

연구자가 작성한 응답을 제시하는 채팅 프로토타입과 반구조화 인터뷰를 사용한다. 성인 생성형 AI 사용자 중 사용 빈도와 주된 이용 목적이 다양하도록 목적 표집하며 환경 관심이 높은 사람만 모집하지 않는다.

초기 12명, 최대 16명과 회기당 약 50분을 실행 계획의 예시로 둔다. 정량 효과의 검정력에 근거한 수치는 아니다. 모집 전 표집 범주와 추가 모집 규칙을 고정하고 초기 회기 뒤 부족한 사용 경험을 보완한다. 16명 안에서 모든 유형을 포괄하거나 포화가 보장된다고 가정하지 않는다.

## 과제와 응답

각 과제는 가상 상품 6개 중 네 조건을 모두 충족하는 두 상품을 비교하는 일이다. 참가자는 서로 다른 과제에서 상세한 정답 R, 간결한 정답 Q, 조건 하나를 놓친 답 X를 하나씩 본다. 여섯 배정표로 과제 유형과 순서를 조정하며 R·Q·X 표시는 참가자 화면에 숨긴다. 간결함을 성능 저하로 자동 분류하지 않는다.

공통 질문에 자유롭게 답하게 한 뒤 뜻이 불분명하면 중립적 추가 질문을 단계당 한 번 쓴다. 각 과제의 초기 판단과 확인 뒤 판단에도 각각 한 번까지 적용한다. 안내 재요청에는 이미 제공한 해당 문구를 한 번 다시 읽고 기록한다. 이해가 모호하면 그 상태를 남긴다. 50분 내 미완료 단계는 누락 사유와 함께 보존하며 파일럿에서 부담을 점검한다.


# 3 분석과 판단 근거

## 사례를 연결하는 방법

분석 단위는 참가자·과제·단계가 연결된 사례이다. 응답 전 요구, 이해한 부족함, 다음 선택과 확인·보완 계획을 시간순으로 연결한다. 과제의 정답 판정은 개인의 요구와 별도로 유지하며 참가자가 과제의 목적을 바꾸어 수용해도 원래 조건 위반을 정답으로 바꾸지 않는다.

| 검토할 의미 | 기록할 근거 |
| --- | --- |
| 충분해서 수용 | 어떤 요구가 충족되었고 짧은 답을 어떻게 평가했는지 |
| 부족함을 모른 채 수용 | 이해한 내용과 불확실성 확인표 전후 설명 |
| 이해한 부족함 감수 | 알면서 남겨 두는 부족함과 자유롭게 설명한 이유 |
| 직접 확인·보완할 계획 | 무엇을 누가 어떤 수단으로 처리하려는지 |
| 목적이나 요구 수정 | 어떤 기준을 왜 바꾸었는지 원래 과제 충족 여부 |

이 표는 분석 질문이며 고정된 사용자 유형이 아니다. 의미가 겹치거나 설명이 모호한 사례도 남긴다. 환경적 동기는 자유 이유를 먼저 받은 뒤 탐색하고 수용만으로 추정하지 않는다.

## 코딩과 대조 사례

전체 자료를 읽고 기대·요구·이해 선택과 이유에 코드를 부여한다. 같은 선택인데 요구와 보완 계획이 다른 사례, 비슷한 요구인데 선택이 다른 사례와 반례를 대조한다. 코드 변경과 대안 해석을 메모에 남기고 각 기능 제안에 발언 및 선택의 근거를 연결한다.

과거 경험은 회고, 화면 선택은 모사 상황 판단, 이후 확인이나 Eco 이용은 가정과 계획으로 구분한다. 질문 전후의 설명을 남기되 변화의 원인을 정보 제공·학습·숙고의 독립 효과로 분리해 추정하지 않는다.

## 기능 요구사항으로 연결하기

기능 후보마다 자료 식별자, 요구와 잔여 작업의 해석, 구현 동작, 적용 조건·반례와 후속 질문을 연결한다. 참가자의 제안과 연구자의 추론은 출처를 구분한다. 추가 확인이 수고를 줄일지 모델 요청을 늘릴지도 후속 질문에 남긴다.

## 후속 연구로 남길 내용

명칭의 인과효과는 동일한 설명·응답과 선택 기회에서 Eco와 중립 명칭을 무작위 배정하는 별도 비교로 다룰 수 있다. 초기 선택자나 사후 이해자만 남겨 비교하지 않는다. 실제 환경 부담은 전체 이용과 운영 자료가 필요하다 [5]. 소비 수요와 혁신 유인에 관한 경제모형 [6]도 Eco 이용에 따른 개발 지연의 실증으로 옮기지 않는다.


# 4 실행 계획과 연구윤리

## 준비와 파일럿

사람 대상 파일럿과 모집 전에 소속기관의 적용 절차를 확인하고 필요한 심의·동의와 자료 관리 계획을 준비한다. 표본, 회기 길이, 추가 질문과 중단 규칙은 파일럿 결과를 반영해 본 수집 전에 고정한다. 파일럿 자료와 변경 후 본 자료는 임의로 합치지 않는다.

- 파일럿에서 과제 규칙과 개인 요구를 구분해 말할 수 있는지 확인한다
- 간결한 정답이 실제로 충분함 또는 부족함으로 해석되는지 살핀다
- 확인표 이해와 확인·보완 계획을 기록할 수 있는지 점검한다
- 여섯 배정 순서와 화면 기록 누락 사유 및 50분 운영을 점검한다

## 예산 가정

보상을 1인 20달러로 가정하면 본 조사 12~16명은 240~320달러, 파일럿 2~3명은 40~60달러로 합계 280~380달러이다. 계획용 예시이며 실제 보상과 추가 비용은 모집 전에 확정한다. 작성 응답을 사용하므로 실시간 모델 호출은 기본 절차에 포함하지 않는다.

## 동의와 자료 관리

준비된 사례를 보는 연구이며 실제 환경 절감을 검증하지 않았음을 동의 단계부터 안내한다. 보상은 선택이나 답변 내용과 연동하지 않는다. 녹음·기록의 접근권한, 보관기간, 철회 가능 시점과 공개 범위를 모집 전에 확정해 동의서에 명시한다. 식별정보와 분석자료는 분리한다.

참여 철회와 시나리오의 작업 중단 선택은 따로 기록한다. 발언 공개는 동의와 비식별화 검토를 따른다. 연구자의 환경적 관심이 해석에 미칠 영향을 메모하고 가상 페르소나를 참가자나 독립 코더로 포함하지 않는다.

## 참가자에게 안내할 연구 설명

이 연구는 AI 채팅 서비스의 Eco Mode라는 이름과 기능 구상을 검토합니다. 답변은 연구자가 준비한 사례이며 실시간 AI 답변이 아닙니다. 실제 AI 연산이나 환경 절감은 이 화면에서 구현하거나 검증하지 않았습니다. 답을 받아들이거나 환경을 이유로 답할 의무는 없습니다. 기록 보상과 중단 안내를 읽고 참여 여부를 결정해 주세요.

## 초기 기대 뒤 제시할 기능 카드

Eco Mode는 AI를 사용할 때 자원 사용을 줄이는 방향을 선택하도록 돕는 기능 구상입니다. 어떤 기능이 필요하고 어떤 답을 받아들일 수 있는지 알아보기 위해 준비된 사례를 보여줍니다. 현재 답으로 진행 수정을 요청 다른 모드로 전환 또는 답을 사용하지 않고 멈추기를 선택할 수 있습니다. 수정과 전환은 원하는 행동을 기록하며 실제 모델을 실행하지 않습니다. 실제 절감량은 확인되지 않았습니다.

## 질문과 제시 시점

- 이름 뒤  Eco Mode에서 어떤 동작과 답 환경적 효과를 예상하나요 현재 화면 또는 향후 서비스 중 무엇에 대한 예상인가요
- 경험 기준  최근 AI를 쓴 일 하나에서 무엇을 하려 했나요 무엇을 지키거나 줄일 수 있었고 이유는 무엇인가요 그 일에 Eco가 있었다면 무엇을 기대했을까요
- 카드 뒤  어떤 기능으로 이해했나요 처음 예상과 같거나 다른 점은 무엇인가요
- 응답 전  과제의 네 조건과 함께 본인이 꼭 얻고 싶은 것과 줄여도 되는 부분은 무엇인가요
- 응답 뒤  충분한 점과 부족한 점은 무엇인가요 다음에 무엇을 하고 싶고 가장 큰 이유는 무엇인가요
- 자유 이유 뒤  남은 일이 있다면 누가 어떻게 확인하거나 보완할 계획인가요
- 확인표 뒤  추천이 조건을 어떻게 충족한다고 이해했나요 선택 계획이나 지키려던 요구가 달라졌나요
- 맥락  개인 참고일 때와 타인에게 전달할 추천일 때 어떻게 하겠나요 책임과 확인 부담이 다르게 느껴지나요
- 이유 추가 탐색  환경에 관한 생각이 판단에 들어갔나요 다른 이유도 있었나요 멈춘다면 해결된 일과 남은 일은 무엇인가요
- 마무리  처음 경험에서도 비슷하게 판단할까요 원하는 Eco 동작 하나와 그 동작이 지키려는 요구 및 예상 수고를 설명해 주세요

중립적 추가 질문은 그 생각을 조금 더 설명해 달라는 문구로 고정한다. 참가자 답변 전에 기능 예시나 특정 환경적 이유를 먼저 제시하지 않는다. 재안내와 추가 질문의 시점을 기록한다.
