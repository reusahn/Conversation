# D · 고정 v4 기준의 90점 초과 가능 조건

2026-10-28. D는 가상 환경·운영 검토 관점이다. 실제 데이터센터 운영자·시설 접근권·환경 인증 또는 외부 심사자의 권한이 아니다. 이번 사용자는 A–E가 토론 후 모두 90점을 넘기도록 요청했다. 고정 v4 기준과 기존 점수는 유지하고, 토론으로 해결한 설계와 실제로 필요한 근거를 구별한다.

검토 자료: `AGENTS.md`, `research/protocol-v4.md`, `reviews/2026-10-28-voluntary-tradeoff/rubric-v4.md`와 기존 D 검토문. 본인이 이 시점에 모델·센서·사람 실험을 수행한 것은 아니다.

## 현재 고정 기준에 따른 판단

|---|---:|---:|---|

| D2 인식/실제 구분 | 20 | 20 | 인식·선택·토큰·J·환경 추정의 구분을 유지함 |

이번에 문서·선언된 스키마·합성 입력의 처리를 보완하더라도 D1/D5의 실제 근거가 생기는 것은 아니다. **현재 근거만으로 D가 90점을 초과할 수는 없다.** 기준을 완화하거나 기록값을 실제 측정으로 바꾸어 점수를 채우지 않는다. 이는 연구 아이디어의 가치나 앞으로 관측될 효과가 낮다는 평가가 아니다.

총괄 도우미의 읽기 전용 환경 확인 보고는 GPU 장치·NVML 실행 도구·전력 카운터 경로·LLM 런타임이 현재 도우미 호스트에 없다는 범위다. D가 사용자 기기나 접근 가능한 외부 서버가 없다고 확인한 것은 아니다. 이 보고를 연구자 장비의 사실이나 실제 J 계측 근거로 이월하지 않는다.

## 90점 초과를 가능하게 하는 근거

D2/D3/D4가 지금처럼 65점이라고 할 때, 고정 0/50/75/100% 단계상 한 가능한 경로는 D1=18.75/25와 D5=7.5/10을 실제 자료로 충족하는 것이다. 합계는 91.25점이다. **이는 산술상 경로이며 해당 자료가 오면 자동으로 그 점수를 준다는 약속이 아니다.** 실제 자료의 타당성·범위·누락을 다시 검토해야 한다.

필요한 최소 자료 묶음은 다음과 같다.

1. **사용 허가가 확인된 계측 경로 한 곳:** 기기·서버·센서의 실제 접근과 기록 export 가능성, 사용할 수 있는 시간과 지출 상한. 이미 무료로 이용할 수 있다면 비용0의 확인 근거를 남길 수 있다. 자기 컴퓨터 구매나 유료 서버 이용이 필수라는 뜻은 아니다.
2. **그 경로에서 나온 세션 원시 계측과 귀속 자료:** measurement boundary·source/device·단위·counter epoch, 시작/끝 raw 값과 읽기 시간, 사용자 입력 잠금과 실제 backend-drained 근거, 유휴·취소 잔여·다른 작업 중첩, reset/staleness/누락 판정. 토큰이나 실행시간만으로 J를 만들지 않는다.
3. **비교 가능성·오차의 근거:** 실제 두 설정의 실행과 같은 경계/정책, 계측기 지원·해상도/정확도·갱신 특성, 워밍업과 반복/순서·변동을 검토할 자료. 반복 횟수를 임의 숫자로 정하거나 반복만으로 계통 오차가 사라진다고 가정하지 않는다.

현재 사용자에게 이 정보를 전부 묻거나 장비 구매·결제·모집을 요구하지 않는다. 실제 기술 실험 경로를 선택할 때 필요한 근거를 밝히는 것이다. token adapter나 분석 함수를 정상 실행한 사실은 이 세 묶음의 대체가 아니다.

## A와의 공개 교환

아래는 이번에 실제 전달한 공개 방법 논점의 텍스트다. 원래 메시지 시각은 제공되지 않았고 native 계정 export가 아니다. 비공개 추론·업무 배정은 포함하지 않는다.

**D → A · 라운드1**

> 고정 D 기준에서 현재 D1 12.5/25, D5 0/10이 실제 raw·접근권 결손이므로 문서/합성 개선만으로 D는 77.5를 넘길 수 없습니다. 새 분석 계약에서 token과 J의 완전성을 따로 두고, J 미확인을 토큰으로 채우지 않으며, 품질/완료율을 자원 검정의 gate로 만들지 않는 원칙에 동의하나요? 90 초과 최소 근거는 동일 범위의 실제 raw counter·drain·오차와 확인된 실행 접근/비용이어야 한다고 봅니다.

**A → D · 라운드1**

> 동의해. 개발 계약은 Eco–Low의 reported_tokens/J를 별도 추론하고 어느 endpoint의 unknown도 다른 값으로 채우지 않아. 품질·완료율·수용은 거래 결과이며 자원 검정의 통과조건이 아니야. 고정 준비도 기준에서 실제 근거 항목의 점수는 문서 증가로 채울 수 없다는 것도 동의해. A 역시 최종 작업/안내 이해도·실제 모드 근거/사람·표본 동결이 없어 90 초과를 보장할 수 없어.

**A → D · 라운드2**

> 이번 계약은 최종 산출물 잠금 뒤 늦은 모델 실행과 실제 drain을 J에 포함하되, 사후 연구 채점은 분리하려 해. B 분석에는 endpoint가 적법하다고 원자료로 인증하는 기능이 없으니 metadata의 measurement_scope_id/source/device/epoch_policy 값은 선언·동일성 검사에 한정하고 actual provenance는 별도라고 적는 게 맞을까? 센서 부재 조사도 도우미 환경에 관한 사실일 뿐 사용자 기기/실제 이용가능 서버 부재의 증거는 아니라고 명시할게.

**D → A · 라운드2**

> 맞습니다. scope/source/device/epoch_policy가 같다는 검사는 선언된 identity 일치일 뿐 실제 계측·독점 할당·동일 epoch의 물리적 유효성 인증이 아닙니다. 센서 age/reset/중첩/drain 및 raw 양끝 근거가 따로 있어야 J 귀속을 승인할 수 있습니다. 호스트 조사도 도우미 환경 한정이고 사용자/외부 서버의 부재를 뜻하지 않습니다. 사후 연구 채점은 원 세션과 겹치지 않게 분리하고, 겹쳤다면 예상값을 빼서 고치지 말고 raw·귀속 위반을 보존합시다.

## E와의 공개 교환

**D → E · 라운드1**

> 새 usage adapter가 token 감소/J unknown을 독립적으로 보존하는지 확인하고 싶습니다. token_complete와 energy_valid를 별도로 두고, usage 누락·실제 재시도·telemetry 재전송을 구별하며 J를 token으로 환산해 만들지 않아야 합니다. 코드 READY/API 알려주면 실제 읽기와 작은 반례를 실행하겠습니다. 고정 D1/D5는 실제 계측/접근권이 없으면 문서만으로 채울 수 없음을 유지합니다.

**E → D · 라운드1**

> adapter는 오직 declared reported_tokens 계측 계약 prototype로 두고 energy_j를 입력·생성하지 않겠습니다. session 결과의 token_complete와 별도 energy_valid=None 및 energy_measurement_performed=False를 명시할게요. manifest의 모든 실제 attempt를 포함하고 final usage 없는 시도는 unknown, event 재전송은 1번, 새 attempt는 합산하겠습니다. 완전한 token↓와 J unknown이 함께 존재하는 테스트를 넣고 READY 때 API를 전달하겠습니다.

**D → E · 라운드2**

> energy_valid=None과 energy_measurement_performed=False가 좋은 명세입니다. energy_unknown_reason='not_measured_by_usage_adapter'처럼 누락 원인도 분리해 주세요. token value가 0인 유효 응답과 final usage 미제공은 달라야 하고, 토큰 완전성은 declared attempt manifest에 대한 조건부임을 남겨야 합니다. manifest 자체에 실제 실행 하나가 빠졌는지는 adapter가 인증하지 못합니다. 이것이 D 검토에서 중요합니다.

E의 후속 답변·코드 검토와 실제 실행 범위는 완료 후 아래에 추가한다. 구현을 약속한 문장만으로 반영 완료나 코드 실행을 주장하지 않는다.

## 재개된 검토의 공개 토론 요약

2026-10-28. 앞부분은 중단 전 보존된 검토다. 아래는 재개 후 A·C·E와 실제 교환한 공개 논점의 요약이며, 메시지 원문 전사나 실제 인물의 발언이 아니다. 미완료 코드의 약속과 완료 후 확인을 구별한다.

### A와 두 라운드

- D는 `source/device/scope/epoch` 문자열의 동일성이 실제 센서·귀속 유효성을 인증하지 않는다고 반론했다. 사후 연구 채점이 세션 또는 backend drain과 겹쳤다면 예상 채점비를 빼서 유효 J로 복구하지 말고 원시값과 귀속 위반을 보존하도록 요청했다.
- A는 이 경계를 반영하고, 성능상 손해 수용·보고한 선택 이유·전력 감소 기대 방향·그 밖에 기대한 환경 이익을 별도 문항으로 둘 계획을 전달했다. 첫 선택 직전의 질문으로 선택을 바꾸지 않고, 사후 응답을 사전 신념으로 복원하지 않는 범위를 유지했다.
- D는 자기보고 척도와 J를 수치로 빼서 ‘인식 차이’를 계산하면 단위가 맞지 않는다고 지적했다. 방향 비교도 측정이 유효한 정해진 세션 범위에서만 가능하다. J가 누락되거나 무효이면 인식과 실측의 불일치를 확정하지 않고 측정 미확인으로 남겨야 한다.
- A의 수정 방향에 동의했다. 실제 수용·동기·성과·물리 소비는 각각 다른 관측이며, 자연환경 훼손 방지 전체의 판정으로 확대하지 않는다. 최종 계약의 실제 문구는 아래 완료 검토에서 확인한다.

### C와 두 라운드

- C는 선언된 usage 스키마와 attempt manifest의 완전성이 실제 provider·모델 실행·J 계측을 인증하지 않는다는 경계를 제시했다. D는 실제 raw와 접근권의 결손을 합성 검사로 채울 수 없다는 기존 77.5점 판단을 유지했다.
- D는 세 반례를 요청했다. 유효한 `reported_tokens=0`에서도 J는 미측정 상태여야 한다. 토큰이 unknown이어도 별도로 유효한 J 결과는 보존해야 한다. 같은 metadata 또는 `measured` 문자열을 입력했다고 진위 인증 상태가 true가 되어서는 안 된다.
- C는 반례를 독립 검사에 반영하겠다고 답했다. D는 소비 감소·성과 악화가 함께 나올 때 동일 성과 효율 개선이나 자연 훼손 방지 결론이 자동 생성되지 않는지도 확인하도록 요청했다. 검사 완료 여부는 약속과 별도로 기록한다.

### E와 두 라운드

- E는 선언된 token usage 프로토타입만 구현하며 J는 입력·생성하지 않는다고 설명했다. `energy_valid=null`, `energy_unknown_reason=not_measured_by_usage_adapter`, 실제 모델·계측 검증 false를 유지하고 token 완전성은 선언 attempt manifest에 대한 조건부로 표시할 계획을 전달했다.
- D는 유효 final의 토큰0과 final usage 미제공을 구별하고, manifest 밖 사건이나 충돌하는 session 참조를 조용히 버리지 않도록 요청했다.
- E는 manifest 밖 사건·중복 attempt manifest·충돌 session 참조를 오류로 처리하고, `manifest_completeness_authenticated=false`를 출력할 계획이라고 답했다. attempt가 전혀 없는 세션은 이번 adapter만으로 생성할 수 없다는 한계도 밝혔다.
- D는 0attempt 세션의 분모는 후속 원배정 participant/session manifest가 책임져야 하며, adapter 출력이 없다는 이유만으로 토큰0을 넣어서는 안 된다고 확인했다. 실제 무호출0의 확인과 누락을 구별해야 한다.

### 기존 S0 명세와의 일치

D가 `research/S0-metering-spec.md`를 직접 읽었다. 이 명세는 실제 원시값·epoch 연속성·drain·시각/센서 오차를 요구하며, 낮은 예산에서 반드시 에너지가 줄어야 통과하는 부호 선별을 금지한다. 이 경계는 v4에서도 유지된다. 실행 가능성의 근거는 계측과 예산 제어의 타당성이며, 사용자가 기대한 절감 방향의 사전 성공이 아니다.
