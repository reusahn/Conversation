# D 라운드 4 최종 v3 검토

2026-10-27. 가상 데이터센터 운영 자문이다. 실제 시설 접근권·장비 계측·외부 학술 심사를 뜻하지 않는다.
고정 D1–D5 기준은 바꾸지 않았다.

## 결과

v3는 **73/100점**이다. v2의 70점, v2.1의 71점에서 문서·합성 구현의 검증이 개선되었다.
실제 장비를 요구하는 점수를 문서 요구로 바꿔 만점을 만들지 않았다.

| 항목 | v2.1→v3 | 근거와 남은 점 |
|---|---:|---|
| D1 실행 경로와 경계 | 12→12/25 | 전용 백엔드 서비스의 세션 총에너지라는 경계는 명확하다. 실제 연구 장비·센서 지원은 미확인이다. |
| D2 전체 에너지와 품질 | 18→19/20 | 사건 재현·취소 드레인·누락·중복과 합성 집계의 독립 실행을 확인했다. 실제 두 예산의 백엔드 적용과 에너지 측정은 없다. |
| D3 효과 검출 가능성 | 13→14/25 | 읽기 bracket과 취득시각의 구분, epoch 증거, 하한 감사·효과 부호 선별 방지를 구체화했다. 실제 해상도·정확도·갱신 지연·편향·변동은 없다. |
| D4 에너지·탄소·물 해석 | 15→15/15 | 범위를 유지했다. 환경 개선이 입증된 것은 아니다. |
| D5 자원과 실행 가능성 | 13→13/15 | 자원 상한·중단·축소 관문은 충분하다. 실제 연구자의 시간·장비·비용 사실은 미확인이다. |

## 실제로 한 코드 검토

1. 처음 제공된 40검사 버전에서 다른 장치/범위의 활성 에너지를 known floor로 남기는 오류를 독립 재현했다.
2. 종료 후 제출을 최초 low 선택으로 세는 오류를 독립 재현했다.
3. 잘못된 t_ns가 명시적 스키마 오류 대신 TypeError로 끝나는 사례를 독립 재현했다.
4. E와 같은 반례를 대조했고 C도 혼합 scope 문제를 재현했다. 사회자가 수정했다.
5. 수정 후 현행 소스를 독립 실행해 **57/57 검사 통과**를 확인했다. 실행 전후 네 소스 SHA-256이 같았다.

소스별 해시와 실행 결과는 [D-independent-run.json](D-independent-run.json)에 보존했다.
숫자 17 J·22 J 등은 합성 값이다. 실제 GPU나 외부 전력계 관측이 아니다.
기존 40개 통과 기록은 그때의 검사 범위만 뜻하며 새 반례까지 이미 검사했다는 뜻으로 소급하지 않는다.

## 채택된 토론 결과

- 세션은 명칭 노출 직전부터 공통 최대시간/최종 완료/확정 포기 중 먼저 발생한 종료 사건 후 실제 backend-drained까지다.
- 생각시간 유휴를 포함하는 전용 서비스 할당의 총효과다. 일반 데이터센터의 한계 에너지나 순수 연산 효율로 확대하지 않는다.
- S0는 실제 제어와 계측 가능성을 확인한다. low의 절감 부호가 양수여야 통과하는 결과 선별을 하지 않는다.
- 단일 요청의 작은 차이와 세션 누적 효과의 검출 가능성을 구분한다.
- 에너지를 식별할 수 없으면 감소/동등의 확증 주장을 차단하고 선택·품질 및 에너지 불확실성을 보고한다.
- 단일 로그와 선언된 해시/epoch는 장비·배타 할당·무작위 배정의 진위 인증이 아니다.
- counter identity·구간·순서 감사 실패가 있는 값을 유효한 하한으로 사용하지 않는다.
- API read bracket과 실제 sensor age, 동일 epoch 문자열과 실제 reset 감시 증거를 구분한다.

## 실제로 하지 않은 것

사용자의 OS/GPU·센서 지원을 확인하지 않았고 실제 LLM 두 예산·전력계·누적 카운터를 실행하지 않았다.
사람의 선택 효과, 품질 유지, 에너지 절감, 탄소·물·자연환경 보호는 확인하지 않았다.
δ·최종 과제·시간 제한·표본 수는 아직 실제 근거로 확정되지 않았다.
따라서 문서와 합성 검사를 더 반복하는 것만으로 D의 잔여 실측 항목을 100점으로 올릴 수 없다.

## 다음 심사에 필요한 증거

확인된 연구 자원, 실제 두 예산의 적용·종료/잘림 로그, 원시 에너지·reset·갱신/시각 근거,
계측 불확실성과 반복 변동, 고정된 서비스 정책의 식별 가능성을 제시하면 같은 기준으로 재심사한다.
