## 독립 반례와 실제 수정 확인

초기40검사 버전에서 E는 다음 반례를 별도 실행으로 확인했다.

1. 한 시도의 시작·끝을 모두 다른 측정 scope로 바꾸면 전체 에너지는 무효인데 활성 합계17 J를 known floor로 남겼다.
2. 종료 요청 뒤 제출을 추가하면 무효 사건임에도 최초 선택 low가 남았다.
3. 첫 제출의 session_id를 다른 세션으로 바꾸면 최초 선택·과제 성과를 정상값으로 남겼다.
4. 누적 카운터가 있는 사건의 t_ns를 문자열로 바꾸면 불명확한 TypeError가 발생했다.
5. 낮음·높음 예산을 동일하게 바꾸고 해시를 다시 계산하면 감사가 통과했다.
6. 모든 session_id를 빈 문자열로 바꾸어도 감사가 통과했다.

54검사 수정 버전에서 위6개를 직접 다시 실행했다. 각각 하한 null, 분석값 unknown, 또는 명시적 ValueError로 차단되는 것을 확인했다.
이후 모드 설정 해시 불일치가 선택·품질에 정상값을 남기는 추가 문제를 보고했다.
최종57검사 버전에서 모드 해시, 공통 백엔드 해시, 서버 설정 속 표시 이름의 세 반례를 직접 실행했다.
세 경우 모두 분석용 선택·품질이 unknown으로 격리되고 원래 관측값은 raw_first_submitted_mode·reported_outcomes로 보존됨을 확인했다.
확증 잠금은 false로 유지되었다. 배정 참가자 행을 삭제하거나 미관측을0으로 바꾸지 않는다.

전체 공개 교차 메시지 원문과 단계별 출력은 [E-dialogue.md](E-dialogue.md)에 보존했다.

## 해석 제한과 다음 최소 증거

- 해시는 입력 설정의 동일성을 비교한다. 실제 서버가 그 설정을 적용했는지, 같은 모델이 실행됐는지 인증하지 않는다.
- measurement_kind와 센서 정보는 입력 선언이다. 코드가 실제 장비나 참가자의 진위를 인증하지 않는다.
- read bracket은 센서 샘플 취득 시각을 보장하지 않는다. 실제 staleness·reset 근거가 필요하다.
- response_observation은 평탄한 합성 자료 검사 helper이다. 실제 vLLM 중첩 응답과 answer/total tokens·finish reason·강제 종료 adapter는 아직 아니다.
- additional_requests는 세션 전체에서 첫 요청 이후의 수이다. 다른 과제의 최초 요청까지 포함될 수 있으므로 과제별 재시도 수와 동일한 뜻으로 보고하지 않는다.
- 현재 participant_id·manifest·해시 검사는 입력 대조이다. 실제 무작위 배정·독립성·배타적 서버 할당은 별도 근거가 필요하다.
- 실제 연구자 환경, 두 예산 실행 trace, 센서 원시 로그와 오차·갱신·시각, 전체 시스템 연결 결과가 다음 최소 증거이다.
- 현재 에너지 절감·품질 유지·사람의 선택 변화·자연환경 보호를 입증한 결과는 없다.
