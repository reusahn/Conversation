다른 페르소나의 실행 증거 요구 기준과 점수는 그대로 존중한다.

## 독립 코드 검토

C는 session_replay.py, analysis_prepare.py, synthetic_fixture.py, test_research_tools.py를 직접 열람했다.
첫 40개 검사, 수정된 54개 검사, 최종 수정된 57개 검사를 독립 재실행해 각각 모두 통과했다.
54개 및 57개 실행 전후 각각 네 파일의 SHA256은 같았다. [54개 독립 실행 기록](C-independent-run-54.json)과 [57개 최종 독립 실행 기록](C-independent-run-57.json)을 보존했다.
이 기록은 실제 모델, 실제 센서, 사람 실험 실행이 아니다.

C가 제기한 결함·해석 문제:
- 평탄 합성 응답의 response_observation을 실제 vLLM 중첩 응답 adapter나 강제 종료 검증으로 부르면 안 됨.
- 최초 선택은 실제 코드와 맞춰 최초 확정·서버 제출 모드로 정의해야 함. UI 토글 자체는 별도 질문임.
- 서로 다른 scope의 활성 에너지를 합쳐 known_floor로 남기는 반례가 있었음. 부모에게 전달했고 수정된 버전에서는 identity/귀속 오류의 하한을 차단하도록 보완함.

v3 문서는 위 helper·최초 제출·하한의 경계를 명시했다.
최종 57개 버전은 해시·프로토콜 사건 의미의 충돌 시 분석 필드를 unknown으로 격리하되 원래 제출 모드·보고 결과·사건을 남긴다. 최초 노출 전 서버 무작위 배정과 전체 배정 manifest를 문서에 구체화했다.
추가 수정/검사 버전은 별도 실행 기록으로 구분하며, C가 실행하지 않은 검사를 통과했다고 표현하지 않는다.

## 점수가 보장하지 않는 것

실제 모델의 두 예산 작동, GPU/시스템 에너지 계측, 실용적 δ·p_min·최종 과제·시간한도·표본 수 확정,
사람의 명명 반응, 에너지 감소·품질 유지, 탄소·물·자연환경 보호, 논문 채택은 아직 입증되지 않았다.
지원 문서·해시·합성 검사는 이 증거를 대신하지 않는다.
