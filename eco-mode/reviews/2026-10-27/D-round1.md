# D 라운드 4 1차 검토

가상 운영 자문이다. 실제 데이터센터 접근권·장비 실측·외부 심사를 뜻하지 않는다.

고정 D1–D5 기준으로 v2.1은 **71/100점**이다. v2의 70점에서 자원 상한·중단 관문 보완만 반영했다. 아래 제안은 아직 v3 채택·구현 재검토 전이므로 추가 점수를 부여하지 않았다.

## 직접 토론으로 정한 보완

A·B와 전용 백엔드 할당 세션 총량을 서비스 정책 추정 대상으로 한정했다. 생각시간의 유휴를 포함하되 조건 노출 전부터 완료·확정 포기·공통 최대시간 중 먼저 온 사건 후 실제 backend-drained까지 측정한다. 공통 최대시간 뒤까지 무조건 유휴를 붙이는 방식과 구분했다.

C와 S0 통과를 저예산의 양의 절감 검출에 의존시키지 않기로 했다. 실제 제어와 계측 가능성이 관문이며 효과 부호는 결과다. 단일 호출 차이가 해상도 이하라도 세션 누적 차이는 검출할 수 있으므로 세션 경계에서 판단한다. 에너지 미식별이면 선택·품질 연구를 모두 막지 않고 에너지 확증만 차단한다.

E와 같은 누적 카운터·epoch·경계의 정수 원단위를 보존하고 음의 잔차를 임의 tolerance로 면책하지 않기로 했다. 원시 총량의 유효성과 활성 귀속의 감사를 별도로 표시한다. API 읽기 bracket은 실제 센서 취득시각의 보장이 아니며 동일 epoch 문자열도 실제 리셋 감시 증거가 아니다.

## 작성 산출물

[계측 명세](../../research/S0-metering-spec.md)에 추정 대상, 실제 장비 관문, 필수 원시 필드, 시작·종료·취소드레인, 총량·잔차 검산, 누락·리셋·중첩 규칙, 계측 불확실성과 검출 가능성을 작성했다.

## 100점에 필요한 남은 증거

확인된 연구 장비·시간·비용, 실제 모델의 두 예산 및 종료/잘림 로그, 실제 누적 에너지와 리셋·갱신·시각 근거, 반복 변동·계측 오차, 최종 세션 정책에서의 식별 가능성이 필요하다. 문서와 합성 수치만으로 이 요구를 충족한 것으로 처리하지 않는다.

현재 연구자의 장비와 모델·센서 결과는 없다. 도우미 호스트의 Linux 정보나 nvidia-smi 부재는 연구자 장비에 대한 결론이 아니다.
