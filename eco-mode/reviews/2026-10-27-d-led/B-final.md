## D 주도 토론이 바꾼 논문 문장

이 절의 구현 상태는 위 57개 소스 시점이다. 이후 실제 최소 수정과 독립 확인은 아래 후속 절에 따로 기록했다.

기여 후보는 “같은 저·고 운영 설정에서 Eco라는 이름이 저예산 선택을 늘리는 것과, 객관적 품질을 유지하면서 실패·재시도·포기·생각시간 유휴를 포함한 전체 할당 세션 에너지를 줄이는 것 사이의 일치·불일치를 검증한다”이다. 실제 사람 결과가 나올 때까지 후보로 남는다.

측정 주장은 고정된 운영정책 아래 세션마다 전용 할당한 서비스 자원의 GPU 또는 시스템 입력 범위로 한정한다. 센터 시설 접근이 이 연구의 출발 요건은 아니다. 공유 서비스·센터 전체 전력/최대부하·냉각·탄소·물·사회 전체 수요로 일반화하려면 각각 추가 자료가 필요하다.

재시도·전환·활성/유휴 분해는 설명용 결과이며 명명의 인과 매개 경로를 입증하지 않는다. 현재 `additional_requests`는 첫 제출 이후의 세션 추가 제출 수이고, `mode_switches`는 인접 제출 간 모드변경 수이다. 개발 fixture의 T01-low→T02-high도 1회로 세므로 이를 같은 과제 재시도나 같은 과제 상향 전환이라고 보고하면 안 된다. E와 과제별 재제출·기술 재시도·같은 과제 low→high를 별도 정의해야 한다는 데 합의했다. 현재 도구에서 그 분해를 이미 구현했다고 하지 않는다.

## 원래 사람 효과 질문으로 가는 다음 경로

1. **지금 혼자:** 문헌 대조·사건/분석 명세·합성 반례·UI/서버 연결 준비를 한다. 사람의 Eco 반응을 가상 사용자나 검사 통과로 대체하지 않는다.
2. **자원이 확인되면:** 확인한 시간/지출 상한 안에서 실제 두 운영 설정의 적용과 세션 계측을 기술 예비실험으로 검증한다. Low의 절감 부호를 S0 통과 조건으로 삼지 않는다. 독립 예비근거로 최종 과제·품질 기준·분석/표본 계획의 수행 가능성을 판단한다.
3. **원래 질문에 답하려면:** 적용 절차와 모집/분석 계획을 갖춘 실제 사람 무작위실험이 필요하다. 현재 참가자를 동원할 필요는 없지만 앞의 두 단계만으로 명명의 사람 효과에 답했다고 쓸 수 없다.

δ·p_min·최종 N은 현재 미확정이다. 연구자가 효과를 보기 전에 사용 맥락과 독립 근거로 정해야 하며, 지금 사용자에게 근거 없는 숫자를 고르도록 요구할 사안이 아니다. 우선 필요한 정보는 실제 사용 가능한 기기/접근권, 시간/지출 상한, 대상 사용자·과제 맥락이다.

Eco 선택이 늘어도 세션 J가 증가할 수 있고, 선택 차이가 작거나 불확실할 수도 있다. 이 결과들을 허용하되 비유의성을 동등성이나 품질 유지로 바꾸지 않는다. 각 Eco–Low/Eco–Fast 대비의 ‘품질을 지킨 절감’은 에너지 단측 상한<0 AND 전체/모든 사전 품질구간의 실패차이 단측 상한<각 사전 δ를 모두 만족할 때만 주장한다. 에너지가 누락되거나 δ가 미확정이면 통과 판정을 내리지 않는다.

공개 교차 발언은 [B-dialogue.md](B-dialogue.md)에 보존했다.

## 후속 최소 수정의 독립 확인 — 점수 자동 상향 없음

위 재심사 이후 E가 기존 지표의 해석 혼동을 바로잡는 최소 구현을 추가했다. 논리 제출은 기존 request_id, 배정 과제는 task_id, 실행 시도는 request_id에 연결된 attempt_id로 명시했다. 세션 인접 모드변경, 같은 과제 내 모드변경/low→high/추가제출, 같은 논리 제출의 추가 attempt를 나눈다. 의미 감사 실패 시 새 유효 지표 5개는 null이며 감사 전 계수와 기존 필드는 보존한다. 실패 원인·사용자 의도는 이 구조적 계수로 추정하지 않는다.

E의 전체 실행 결과 파일은 수정 후 **62/62**를 보고한다. B는 새 결과 파일·변경 helper/출력·README 정의를 직접 읽고, 실제 변경 범위에 해당하는 다음 **8개만 독립 실행하여 8/8**을 확인했다. 실패·오류·건너뜀은 모두 0이다. 수정된 62개 전체를 B가 다시 독립 실행했다고 하지 않는다.

| 독립 확인한 사례 | 확인한 의미 |
|---|---|
| T01-low→T02-high | 세션 모드변경 1, 같은 과제 상향 0 |
| T01-low→T02-high→T01-high | 다른 과제를 건너뛰고 같은 과제 상향 1 |
| 같은 과제 low→low | 추가제출 1, 모드변경/상향 0 |
| 같은 request의 두 attempt | 새 제출 0, 추가 attempt 1 |
| mode hash 충돌 | 새 유효 지표 null, 원시 계수 보존 |
| 기존 최초 제출 기준 | 최초 low와 기존 계수 호환 |
| 완전한 무호출 세션 | 유효 행동 계수 0, 유휴 에너지 유지 |
| 동일 사건 중복 | 기존과 같은 중복 제거 결과 |

`ReplayInvariants`의 위 8개 테스트만 TestSuite에 명시하여 실행했다. 전체 결과 파일은 덮어쓰지 않았다. 실행 전후 Python 소스 해시는 같았고 E가 보고한 최신 파일과 일치했다.

| 변경 파일 | 후속 확인 전후 동일한 SHA256 |
|---|---|
| session_replay.py | `cb488f6336d0d0cd9990b118d8c12d64de9c94cc275e19898a60852465395f21` |
| test_research_tools.py | `2c91fec229eca8a412c4d541c1a273f58f112878d999a0803a72961ec548af80` |

나머지 세 Python 파일은 앞 표의 해시를 유지했다. 기존 fixture는 mode_switches=1, session_adjacent_mode_changes=1, 과제 내 세 지표와 추가 attempt=0으로 바르게 구분된다. 합성 총량 22J·실측 null·confirmatory_ready=false가 유지된다. 실제 모델·센서·사람은 실행하지 않았다.

이 수정은 준비 도구의 표현과 집계 단위를 바로잡았다. 실제 자원·UI/서버·최종 과제·δ/N·사람 효과의 공백을 채운 것은 아니다. 위 v3 완료 평가 **62.5점과 항목별 점수는 유지**하며, 새 검사 수 때문에 점수를 자동 상향하지 않는다.
