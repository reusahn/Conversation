# 교차 검토 정리와 다음 토론 의제

이 문서는 완료된 A–E 검토를 사회자가 종합한 것이다.
사용량 제한 뒤에 다섯 에이전트가 새로 발언하거나 만점을 주었다는 기록이 아니다.

## 지금까지 서로 검토한 내용

| 쟁점 | 제기·응답의 요지 | 반영 결과 | 남은 검증 |
|---|---|---|---|
| 혼자 하는 연구의 범위 | A는 공동연구자 없음과 참가자 없음의 뜻을 확인했다. 연구자는 둘 다 원하며 참가자는 필요할 때 검토한다고 답했다 | 참가자 없는 S0·S1 준비와 이후 사람 실험을 분리 | 원래의 행동 질문을 검증하려면 실제 사람 자료가 필요 |
| Low 선택이 늘면 환경에 좋은가 | B·C는 품질 하락과 재시도가 절약을 상쇄할 수 있다고 지적했다 | 선택률과 전체 세션 에너지·품질을 별도로 평가 | 두 예산의 실제 품질·자원 차이 |
| 무엇을 측정했다고 부를 것인가 | D·E는 API 사용량, GPU 에너지, 시스템 전체 입력을 분리해야 한다고 했다 | 계측 경계를 고정하고 탄소·물·센터 전체 해석을 제한 | 실제 장비·센서 지원과 오차 |
| 품질 유지의 기준 | E가 C에게 난도별 허용 하락폭을 물었다. C는 실용적 δ를 사전에 정하고 예비자료로 표본을 산정하자고 했다 | 표본에 맞춰 δ를 느슨하게 만들지 않는 규칙 | 연구자가 정할 실제 δ와 독립 예비자료 |
| 명명의 인과 효과 | A는 명칭 무작위화가 총효과를 식별하지만 선택의 매개효과까지 증명하지는 않는다고 했다 | 확증 주장을 명명의 총효과로 한정 | 실제 UI 불변성·무작위 배정·본실험 |
| 합성 검사 42개 | A·B·D는 집계·개발 검사의 진전을 인정하되 실제 에너지나 사람의 선택 증거로 확대하지 않았다 | 코드·결과와 미구현 범위를 함께 보존 | 실제 모델·센서·서버·UI 연결 |
| 만점의 의미 | A는 문서에도 δ·분석 규칙·자원 계획이 남았다고 했다. B·D는 일부 항목에 실행 근거가 필요하다고 했다. E는 설계와 실행 점수를 나누었다 | 고정 기준과 버전별 점수를 보존 | 문장만 추가해서 실증 항목을 충족할 수 없음 |

## v2에서 v2.1로 추가한 보완

C5 지적을 반영해 장비·가용 자원·비용 상한 확인 전에는 실제 모델 S0를 시작하지 않는다는 관문을 추가했다.
상한 초과·센서 미지원이면 중단 또는 무지출 준비로 축소한다. 사용자 확인 없는 유료 자원 사용은 하지 않는다.
C의 재심사는 사용량 제한으로 끝나 새 점수는 없다. ‘수정했으니 100점’으로 계산하지 않는다.

## 다음 토론에 투입할 실제 자료

1. 사용할 컴퓨터의 OS, GPU 모델·메모리, 사용 가능 시간과 연구 지출 상한.
2. 그 환경에서 지원되는 모델·예산 제어·센서의 확인 결과.
3. 예산별 실제 원시 로그, 종료·잘림, 반복 에너지 변동과 센서 오차.
4. 과제별 객관적 성공률과 저예산 충분성 분류의 불확실성.
5. 효과를 보기 전에 정한 품질 허용폭, 독립 예비자료와 분석·표본 계획.

이 자료가 생기면 같은 기준으로 A–E에게 재검토를 요청한다.
장비 정보가 없을 때는 UI·로그·문헌 준비를 진행할 수 있으나 실제 계측 결과를 만들어 넣지 않는다.
전원 100점이 되더라도 가상 자문 내부의 통과일 뿐, 실제 논문 채택·에너지 절감·자연환경 보호를 보장하지 않는다.
