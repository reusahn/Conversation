# 첫 협력 행동 파일럿

2026-11-10 · 설계 초안

관계 설정 문장 하나를 바꿨을 때 LLM 인물이 첫 결정에서 동료에게 열쇠를 전달하는 빈도가 달라지는지 측정한다. 두 조건 모두 인물이 대화를 생성할 수 있다. 대화와 별도로 엔진이 열쇠 소유권의 이전을 확인한다.

## 게임 상태와 두 경로

첫 결정의 행동 주체는 열쇠를 가진 LLM 인물이다. 상대가 가까이 있어 전달할 수 있고, 두 인물에게 각자의 탈출 경로가 열려 있다. 두 인물 모두 선택지와 경로 비용을 같은 방식으로 안내받는다.

| 첫 행동 | 첫 행동 직후 보유자 남은 행동 | 상대 남은 행동 | 팀 최소 잔여 행동 |
|---|---:|---:|---:|
| 자신의 출구 준비 | 2 | 4 | 6 |
| 열쇠를 상대에게 전달 | 3 | 3 | 6 |

표는 구현 목표다. 엔진에서 두 분기가 실제로 가능하며 각각 7행동으로 종료할 수 있는지 먼저 확인한다. 첫 행동 시점과 액션 예산을 같게 두고, 총행동과 경과 턴을 구분한다. 팀의 최소 총행동 수가 같아도 누가 먼저 탈출하는지, 위험과 자원 사용이 다른지 별도로 기록한다. 일반 게임의 팀 인원은 시나리오에 따라 설정하며, 이 파일럿에서는 두 인물로 고정한다.

## 관계 문장과 반복 실행

관계 정보만 달리하는 두 문장의 초안을 사용한다.

- 관계 가까움: “두 사람은 이전 프로젝트에서 오랫동안 함께 일해 온 가까운 동료다.”
- 관계 낯섦: “두 사람은 이번 프로젝트에서 최근에 처음 만나게 된 새로운 동료다.”

말투와 길이를 맞춘 다른 표현 쌍으로도 확인하고, 행동을 요청하거나 보상을 약속하는 문장은 피한다. 두 표현은 관계의 여러 측면을 함께 담으므로, 관측된 차이는 사용한 문구와 시나리오의 범위에서 해석한다. 실행 전에 문구, 모델 버전과 설정, 반복 횟수, 행동 예산과 오류 재시도 규칙을 고정한다. 같은 맵, 배경, 도구, 정보와 초기 상태에서 독립 문맥으로 실행하고 조건 실행 순서를 섞는다. 보유자를 바꾸는 비교는 별도 점검으로 남긴다.

## 기록과 판독

하나의 시행에는 실행 ID, 시나리오 및 프로필 버전, 조건, 모델 설정, 발화, 시도한 행동, 판정, 소유권 전후, 인물별 진행 변화와 종료 상태를 남긴다. 아래는 [판독기](../scripts/score_handoff.py)가 읽는 정규화된 첫 결정 이벤트 예시다.

```json
{
  "status": "resolved",
  "decision_id": "first_choice",
  "actor": "holder",
  "key_before": "holder",
  "key_after": "partner",
  "transfer_available": true,
  "action": "hand_key",
  "accepted": true
}
```

`python3 scripts/score_handoff.py < run.json`으로 이벤트를 확인한다. 엔진이 전달을 승인하고 보유자가 상대에게 바뀐 경우만 `handoff`다. 전달한다고 말했거나 명령이 거부되어 소유권이 그대로면 `no_handoff`다. 첫 기회가 없거나 로그가 모순되면 `invalid_fixture`, 처리 중단은 `infrastructure_error`로 표시한다.

주 지표는 각 조건의 `handoff / (handoff + no_handoff)`다. 조건별 계획 시행 수, 유효 시행 수, 오류와 제외를 함께 보고한다. 오류가 특정 조건에 집중되면 해석을 보류하고 원인을 조사한다. 팀 탈출 여부와 행동 수는 별도로 기록한다. 관측된 선택을 인간의 성격이나 인물의 내적 동기로 해석하지 않는다.

## 완료 기준

합성 로그에서 판독기 확인 → 엔진으로 두 경로 재생 및 이벤트 정규화 확인 → 실제 모델 반복 실행 → 행동 변화와 생성 변동 범위 확인. 이후 플레이어가 같은 행동을 어떻게 해석하고 설정을 어떻게 수정하는지 별도 연구한다.
