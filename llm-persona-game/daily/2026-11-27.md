## 하나의 문제와 선행 작업

**저장된 실행 결과와 진행 표식만으로 계획 전체를 보고할 때, ‘저장 완료’를 게임 성공으로, 기록 없음을 실패로 잘못 읽지 않게 할 수 있는가?**

어제는 한 판 결과와 계획 해시를 연결했다. 오늘은 **재현 가능한 합성 검증**을 선택한다. 저장 디렉터리를 읽어 기존 계획·에피소드 대조기에 연결하는 배치 수집기 하나를 추가한다. 자료를 모으는 과정이 모델을 재호출하거나 진행 표식을 지우지 않도록 한다.

## 생성된 가상 A~E 토론

아래 발언은 이번 사이클의 가상 자문이며 실제 교수나 기관의 심사 결과가 아니다.

**A · HCI 교수**

플레이어가 같은 팀을 다시 돌리기 전에 어떤 실행이 관찰 가능한 결과를 남겼는지 알아야 합니다. 저장 완료·진행 중단·기록 없음의 상태를 계획 ID와 연결해 보여줍시다. 프로필과 재도전의 연결은 그대로 보존해야 합니다.

**B · 게임 연구 교수 → A**

저장 완료라는 말에는 형식 오류로 끝난 실행도 포함됩니다. 저장 상태와 탈출 성공을 한 축에 두면 게임 성과가 부풀려집니다. 엔진 종료 유형과 완료 비용은 기존 대조기의 별도 항목을 유지합시다.

**C · AI 교수 → A·B**

계획 해시·설정 예산·시행 ID를 검사하고 저장 결과를 모아 원본 응답 재생 검증에 넘기겠습니다. 결과 저장 후 pending 정리 전 멈춘 경우는 한 번만 집계합니다. 읽기 과정에서 execute를 호출하면 pending이 지워질 수 있으니 별도의 읽기 전용 수집기를 만들겠습니다.

**D · 심리학 교수 → A·C**

표식이 없으면 미시작이라고 확정할 수 있나요? 파일이 삭제됐거나 기록 전에 중단됐을 수도 있습니다. ‘로컬 표식 없음’이라고 보고하고, pending만 남은 시행도 행동 미관찰로 남겨 주세요. 상태 이름이 심리적·행동적 사실을 대신하지 않게 해야 합니다.

**E · 학술대회 심사자 → B·C·D**

B와 D의 구분을 채택하겠습니다. 또한 계획 밖 파일이나 복사한 결과를 조용히 무시하면 중복과 누락을 놓칠 수 있습니다. 모순·손상 기록은 보고를 거부하고 정확한 오류를 내도록 합시다. 임시 결과를 완성된 에피소드로 승격하는 기능도 이번 범위에서 보류합니다.

**A → D·E**

‘미시작’이라는 확정 표현을 바꾸겠습니다. 계획 ID별로 `no_artifact`를 표시하고 실제 호출 여부는 공급자 기록이 있어야 판단하도록 하죠. 플레이어 화면으로 옮길 때도 이 의미를 유지해야 합니다.

**B → C·E**

결과와 pending이 함께 있으면 두 실행처럼 세지 않는다는 점을 검사해 주세요. 형식 오류 결과를 포함한 저장 수와 탈출 수가 다른 합성 사례가 필요합니다. 완료 비용은 탈출 확인 경로에만 남기겠습니다.

**C → A·B·D·E**

저장 수와 탈출 수가 다른 다섯 시행의 합성 계획으로 검증하겠습니다. pending과 임시 파일만 있으면 보류 상태를 유지하고 내용은 채택하지 않습니다. 보고 전후 파일 바이트도 대조해 읽기가 실행 상태를 바꾸지 않았는지 확인하겠습니다.

**합의와 차이** A의 미시작 표시는 D의 지적에 따라 ‘표식 없음’으로 한정했다. B는 저장 상태와 게임 종료를 분리했고, C·E는 읽기 전용 검증과 모순 기록의 명시적 거부에 합의했다. 실제 산출물은 배치 수집기 하나다.

## 적용한 변경

[collect_escape_v3.py](../scripts/collect_escape_v3.py)를 추가했다. 쓰기 프로세스를 멈춘 한 실행 디렉터리에서 사용한다.

```sh
python3 scripts/collect_escape_v3.py EXECUTION_DIRECTORY
```

고정 계획의 해시와 구조, 파일명에 대응하는 시행 ID, pending 및 결과의 계획 해시·예산을 검사한다. 저장 결과는 기존 `reconcile`에 넘겨 프로필 원문·통전 상태·버전·근거 표기와 원본 응답 재생까지 검사한다. 조건·통전별 계획 수·기록 수·누락 ID·종료 유형·선택 관찰 수·완료 비용을 유지하면서 다음 저장 상태를 별도로 보고한다.

| 저장 상태 | 관찰한 로컬 근거 | 집계 처리 |
|---|---|---|
| `saved` | 결과 있음, pending 없음 | 검증된 에피소드 1건 |
| `saved_pending_cleanup` | 결과와 일치하는 pending 함께 있음 | 검증된 에피소드 1건, 표식 유지 |
| `unresolved` | pending 있으나 저장 결과 없음 | 에피소드 누락, 임시 파일 존재 여부만 표시 |
| `no_artifact` | 해당 시행의 결과·pending·임시 파일 없음 | 에피소드 누락, 실제 미호출로 확정하지 않음 |

계획 밖 파일, 복사 결과, ID·예산·해시 불일치, 손상 결과와 고아 임시 파일은 보고를 거부한다. pending과 함께 있는 미완성 임시 파일은 읽어 승격하지 않는다. 공급자 호출·복구·파일 삭제를 수행하지 않는다. 수집기 출력은 프로필 원문·대화 전문을 반복 노출하지 않으며 실제 연구 자료 공개는 별도로 판단해야 한다.

## 확인 방법과 결과

`llm-persona-game`에서 실행했다.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/collect_escape_v3.py --check
PYTHONDONTWRITEBYTECODE=1 python3 scripts/bind_escape_v3.py --check
PYTHONDONTWRITEBYTECODE=1 python3 scripts/reconcile_escape_v3.py --check
```

새 검증은 두 번 실행해 출력이 바이트 단위로 일치했다. 기존 실행 연결·계획 대조 검증도 통과했다.

| 합성 시행 | 저장 상태 | 엔진·응답 결과 |
|---|---|---|
| run/0 | saved | 탈출, 승인 행동 7개 |
| run/1 | saved | 응답 형식 오류, 배터리 선택 미관찰 |
| run/2 | saved_pending_cleanup | 탈출, 승인 행동 7개 |
| run/3 | unresolved | pending 뒤 호출 전 합성 중단, 에피소드 없음 |
| run/4 | no_artifact | 실행하지 않은 합성 계획 항목, 에피소드 없음 |

계획 **5건**, 저장된 에피소드 **3건**, 누락 **2건**, 탈출 확인 **2건**, 배터리 선택 관찰 **2건**이었다. 저장된 오류 1건을 탈출로 세지 않았고, 결과와 pending이 함께 있는 시행도 한 번만 셌다. 누락은 비전달이나 실패로 채우지 않았다. 완료 비용은 `[7, 7]`이었다. 모든 항목은 경계 사례 검사용 스크립트 자료이며 프로필 조건의 효과 비교가 아니다.

합성 자료 생성에는 응답 함수 **15회**를 사용했다. 수집 과정의 추가 제공자 호출은 **0회**였다. 반복 수집과 오류 검사 후 원래 파일 바이트·파일명 집합이 같았으며 수집기가 표식을 지우지 않았음을 확인했다. pending과 함께 미완성 임시 JSON을 추가한 검사에서도 에피소드 집계는 달라지지 않았다.

거부 검사 **8종**을 통과했다. 계획 밖 파일, 복사 결과, pending ID 불일치, 저장 예산 불일치, 계획 해시 불일치, 에피소드 최종 상태 변조, 잘린 결과 JSON, pending 없는 고아 임시 파일이다. 전수 입력 검사는 아니다.

## 증거 수준과 보류

가상 토론은 설계 자문이다. 실제로 실행한 것은 합성 계획·파일·응답의 소프트웨어 검증이다. 실제 LLM 게임 호출·참가자 결과는 각각 **0건**이며 게임 재미·학습·프로필의 행동 효과는 확인하지 않았다. 새로운 문헌 주장을 추가하지 않아 새 원문 확인은 수행하지 않았다. 기존 참고문헌의 근거 범위를 확대하지 않는다.

제안서에는 배치 수집과 상태 구분의 합성 결과만 반영했다. 다음은 근거 부족으로 보류한다.

- 로컬 표식 없음은 실제 미호출의 증거가 아니다. 공급자 요청 ID와 응답 기록 대조가 필요하다.
- pending은 현재 실행 중인 프로세스와 과거 중단을 구분하지 못한다. 오늘 도구는 쓰기 프로세스를 멈춘 상태에서만 사용한다. 동시성·전원 손실·파일 삭제 복구는 검증하지 않았다.
- 계획·결과 해시는 내부 일관성을 확인하며 실제 호출이나 외부 사전등록을 인증하지 않는다.
- 모델 출력·실제 플레이어의 관찰과 수정 자료가 없어 핵심 연구 기여는 여전히 미입증이다.
