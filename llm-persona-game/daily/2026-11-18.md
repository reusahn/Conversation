# 2026-11-18 · 사이클 09

## 쟁점

[직전 사이클](2026-11-17.md)에서 정리한 실행기를 사용하기 전에, 비교 조건의 이름이 실험 문장 외의 통로로 모델에 전달될 가능성을 줄일 수 있는가?

## 가상 A~E 토론

- **A · HCI 교수** — 플레이어가 작성한 관계 문장과 실험자가 붙인 조건 이름을 분리합시다. 테스트 중 문장은 모델이 읽어야 하지만 조건 이름은 집계용입니다.
- **B · 게임 연구 교수 → A** — 동의합니다. 행동 선택지의 순서는 게임 정보이므로 메시지 속 순서를 지켜야 합니다. 다만 선택지 순서를 기록한 별도 필드까지 넘길 필요는 없습니다.
- **C · AI 교수 → A·B** — 현재 어댑터에 전체 계획 행이 들어갑니다. 실행 ID와 원래 메시지만 넘기고 조건·블록·순서 필드는 계획에 남깁시다. 모델 요청 본문에는 메시지만 넣고, ID는 로컬 대조용으로 쓰도록 어댑터 규약에 명시하겠습니다.
- **D · 심리학 교수 → C** — 어댑터 입력이 줄어도 관계 문구 자체의 정서 차이는 남습니다. 누락 검사와 문구별 해석을 유지합시다. 다른 입력 규약에서 시작한 원장도 새 규약으로 이어 쓰면 안 됩니다.
- **E · 심사자 → C·D** — 80개 요청 전체를 가로채 메시지와 식별자가 그대로인지 확인하고, 구버전 원장이 거절되는지 검증합시다. 실제 제공자에 어떤 본문이 갔는지는 후속 연결 시험에서 확인해야 합니다.

**합의와 의견 차이.** A와 B는 모델이 읽을 내용을, C는 어댑터 경계와 판정의 추적성을, D와 E는 해석 및 버전의 일관성을 우선했다. 실험용 이름은 집계 쪽에 보관하고 원래 메시지를 보존하는 실행기 수정에 합의했다. 첫 탈출 과제의 비교에 국한하며, 일반 게임에서는 시나리오별 최대 인원 안에서 플레이어가 직업·성향·관계를 자유롭게 작성하고 대화·행동을 관찰해 수정·재도전한다.

## 변경과 검증

[실행기](../scripts/run_handoff_pilot.py)의 어댑터 입력에서 조건, 블록, 블록 내 위치, 별도 선택지 순서와 프로토콜 필드를 제거했다. 입력 규약 버전을 원장 매니페스트에 추가해 기존 규약으로 시작한 원장을 새 규약으로 재개하지 않도록 했다.

합성 어댑터가 받은 80개 입력을 원 계획과 비교했다. 메시지·실행 ID가 80/80 일치했고 제거 대상 필드는 전달되지 않았다. 조건별 40건이 기존 함수로 집계됐고 완료 원장을 재실행해도 추가 호출이 없었다. 구버전 매니페스트도 호출 없이 거절됐다. 기존 생성기·집계기 검사도 통과했다. 가상 토론과 합성 검증이며 실제 모델 호출 0건, 참가자 시행 0건이다. 재미·학습·행동 효과 자료는 없다. 새 문헌 주장은 추가하지 않았다.
