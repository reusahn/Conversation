## 생성된 가상 A~E 토론

실제 전문가 발언이나 외부 심사 결과가 아닌 이번 사이클의 가상 자문이다.

**A · HCI 교수**

플레이어의 수정이 어느 실행에 반영됐는지 확인하려면 프로필 원문이 계획과 결과에 연결돼야 합니다. 재개 시 변경된 프로필을 받아들이지 말고 새 실행으로 다루도록 합시다. 줄바꿈과 공백도 원문으로 보존해야 합니다.

**B · 게임 연구 교수 → A**

새 계획을 만드는 기준에 동의합니다. 다만 중단 때마다 한 판을 처음부터 자동으로 다시 돌리면 같은 결과 중 유리한 것만 남을 수 있습니다. 저장된 완결 결과는 돌려주고, 저장되지 않은 실행은 어떻게 처리할지 정해야 합니다.

**C · AI 교수 → A·B**

호출 전에 pending을 쓰고, 원본 응답과 엔진 사건을 포함한 결과를 저장하겠습니다. 결과 저장 뒤 중단되면 추가 호출 없이 복구합니다. 결과가 없는 pending은 모델이 어디까지 처리했는지 모르므로 자동 재호출을 보류하겠습니다. 계획 전체의 정규화 해시와 실제 설정 예산을 결과 바깥 봉투에 기록하고, 내부 에피소드는 기존 재생 검사로 확인합니다.

**D · 심리학 교수 → C**

호출 전 중단이 확실해도 pending이면 보류하나요? 그렇게 하면 불필요한 미완료가 늘 수 있습니다. 동시에 중단 후 재시도가 원래 시행의 관찰인 것처럼 섞여서도 안 됩니다. 이번 단계에서 안전하게 구분할 수 있는 범위를 명시해 주세요.

**E · 학술대회 심사자 → A~D**

현재 공급자 기록이 없으니 D가 제안한 자동 구분을 구현했다고 주장할 수 없습니다. C의 보수적 보류를 채택하되, 로컬 파일과 해시는 외부 사전등록이나 실제 모델 호출의 증명이 아니라는 한계를 남깁시다. 점수는 계속 미검증 경험적 기여를 기준으로 감점해야 합니다.

**A → D·E**

보류를 인정합니다. 프로필을 수정하면 새 실행 디렉터리를 사용하게 하고, 같은 계획의 저장된 결과를 읽는 행위와 플레이어의 새로운 재도전을 구분하겠습니다.

**B → C·D**

저장된 결과의 재사용은 같은 판을 다시 생성하지 않는다는 장점이 있습니다. 이번에는 턴 도중 이어 하기보다 한 판 전체 결과의 복구부터 확인하죠. 합성 성공을 게임 재미나 관계의 협력 효과로 해석하지 않겠습니다.

**C → D·E**

pending만으로는 확실한 미호출과 처리 여부 불명을 구분하지 않습니다. 둘 다 추가 호출을 멈춥니다. 단일 쓰기 프로세스와 프로세스 예외를 가정하며 동시 실행·전원 손실 복구는 별도 검증이 필요합니다.

**D → C·E**

그 범위라면 동의합니다. 보류된 실행을 성공·실패로 채우지 않고 공급자 확인 대상으로 남겨 주세요. 관계 문구의 심리적 조작이나 사람의 수정 판단은 여전히 후속 검증입니다.

**합의와 차이** D는 확실한 미호출의 자동 재시도를 검토했지만 C·E는 호출 근거 부족을 이유로 pending 보류를 선택했다. 저장 결과 복구, 원문 보존, 변경된 계획의 재개 거부에 합의했다. 실제 산출물은 아래 실행 연결 도구 하나다.

## 적용한 변경

[bind_escape_v3.py](../scripts/bind_escape_v3.py)를 추가했다.

- `freeze(root, plan)`은 기존 대조기로 계획 구조를 검사하고, 정렬된 JSON의 SHA-256과 계획 원문을 로컬에 먼저 저장한다. 객체 키 순서 변경은 같은 해시를 만들고 프로필 문자열은 정규화하지 않는다.
- `execute(root, plan, run_id, provider)`는 고정된 계획과 비교한 뒤 pending을 기록한다. 기존 한 판 실행기를 사용하고, 실제 설정한 응답 예산·계획 해시·시행 ID와 에피소드를 함께 저장한다.
- 저장 결과가 있으면 원본 재생·계획 대조를 다시 통과한 결과를 반환한다. 결과 저장 뒤 pending 정리 전 중단도 추가 호출 없이 복구한다.
- 결과 없이 pending만 있으면 자동 재실행을 보류한다. 프로필·예산·통전 상태·버전 변경, 저장된 예산 불일치와 해시 불일치를 거부한다.

계획 파일을 재작성해 새 연구 조건을 몰래 적용하지 않는다. 새 인물 설정·재도전은 새 실행 디렉터리와 식별자를 사용해야 한다. 제공자는 메시지를 받아 원본 JSON 응답을 반환하는 기존 인터페이스이며, 오늘 실제 외부 모델 어댑터는 추가하지 않았다.

## 확인 방법과 결과

`llm-persona-game`에서 실행했다.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/bind_escape_v3.py --check
PYTHONDONTWRITEBYTECODE=1 python3 scripts/reconcile_escape_v3.py --check
PYTHONDONTWRITEBYTECODE=1 python3 scripts/report_escape_v3.py --check
```

새 검증을 두 번 실행했고 출력은 바이트 단위로 같았다. 기존 두 도구의 합성 검사도 통과했다.

| 검사 | 결과 |
|---|---|
| 저장된 완결 결과 재조회 | 7개 합성 응답으로 완결 후 재조회 시 추가 응답 호출 0 |
| 프로필·예산·버전·통전 변경 | 네 변경 각각 계획 재저장과 재개를 거부, 추가 호출 0 |
| 호출 전 pending 기록 후 중단 | 최초 호출 0, 재개도 보류하며 추가 호출 0 |
| 한 판 실행 후 결과 저장 전 중단 | 최초 합성 응답 7개, 재개 보류, 추가 호출 0 |
| 결과 저장 후 pending 정리 전 중단 | 최초 합성 응답 7개, 결과 복구, 추가 호출 0 |
| 저장된 예산·고정 계획 해시 변조 | 두 불일치 모두 거부 |

검사 요약 항목 **10개**를 통과했다. 한 번의 검증 명령에서 스크립트 응답 함수 호출은 총 **21회**이며 실제 모델 호출은 **0회**다. 한 경로의 중단·복구를 검증하는 자료로, 새롭게 모든 엔진 경로를 전수 재생한 결과는 아니다. 계획의 키 순서 불변성과 다국어·줄바꿈·말미 공백을 포함한 프로필 보존, 설정 예산 11회의 저장도 확인했다.

## 증거 수준과 보류

가상 토론은 설계 자문, 위 실행은 합성 소프트웨어 검사다. 실제 LLM 게임 실행과 참가자 결과는 각각 0건이다. 게임 재미·학습·프로필의 행동 효과를 입증하지 않았다. 문헌에 관한 새 주장을 추가하지 않아 새 원문 확인은 수행하지 않았다. 기존 참고문헌의 효력을 확대하지 않는다.

제안서에는 계획·결과 연결과 합성 중단 처리 결과만 반영했다. 다음 주장은 근거 부족으로 보류한다.

- 로컬 해시는 변경 감지를 돕지만 파일 전체를 재작성할 수 있는 주체에 대한 인증이나 외부 사전등록 시각 증명은 제공하지 않는다.
- 에피소드 봉투에 설정 예산이 남지만 `model` 표기만으로 실제 공급자 호출·설정을 인증하지 않는다.
- 이번 구현은 단일 쓰기 프로세스에서 예외를 주입한 검사다. 동시 실행, 디렉터리 기록의 전원 손실 내구성, 부분 파일 손상 복구는 검증하지 않았다. 읽을 수 없는 기록은 자동 재호출하지 않고 오류를 낸다.
- 턴 중간의 자동 재개는 구현하지 않았다. pending만 남은 시행은 공급자 기록 대조 전 보류한다.
