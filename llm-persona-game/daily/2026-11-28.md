**B · 게임 연구 교수 → A**

같은 에피소드 안에서도 응답 형식 오류는 모델 응답을 받은 사건입니다. 오류 응답을 기록에서 빼면 게임 엔진이 왜 멈췄는지 사라집니다. 성공한 행동과 응답을 받은 호출을 구분해 남겨 주세요.

**C · AI 교수 → A·B**

계획에 공급자·모델 스냅샷·생성 설정을 선언하고, 턴별 요청 해시·요청 ID·응답 ID·원본 응답·보고된 모델·사용량을 연결하겠습니다. 반환된 형식 오류도 그대로 대조합니다. 기록 누락, 턴 중복, 재사용된 공급자 식별자, 모델·설정 불일치를 거부하겠습니다.

**D · 심리학 교수 → C**

시간 초과가 나면 공급자가 처리하지 않았다고 확정할 수 없습니다. 요청 ID도 없을 수 있고 사용량을 0으로 채우면 실제 자원 사용을 왜곡합니다. 처리 여부가 불명확한 상태와 실제 보고된 사용량을 구분해 주세요. 이 수치로 인간 성향이나 협력 효과까지 설명하지 맙시다.

**E · 학술대회 심사자 → A~D**

D의 지적에 동의합니다. 로컬에 만든 호출 기록은 공급자의 독립 증빙이 아닙니다. 이번에는 내부 일관성 검사를 구현하고, 실제 모델 실행으로 승격하지 않아야 합니다. 또한 기록 도구만 계속 늘어나는 한계가 있습니다. 자유 저작·관찰·수정의 핵심 경험이 미검증이라는 감점은 유지하겠습니다.

**A → D·E**

해시의 역할을 내용 연결로 한정하겠습니다. 실제로 전송됐다는 증거는 향후 어댑터와 공급자 기록을 함께 확인해야 합니다. 관찰 화면이나 수정 판단의 연구 근거가 생겼다고 주장하지 않겠습니다.

**B → C·D**

형식 오류를 포함한 반환 8건과 시간 초과 1건을 합성 사례로 만들죠. 시간 초과를 게임의 비협력 행동이나 탈출 실패로 코딩하지 않고 기존 전송 오류 종료와 연결합시다.

**C → D·E**

시간 초과는 `unknown`으로 두고 응답·응답 ID를 만들어 넣지 않겠습니다. 사용량이 하나라도 미상이면 알려진 소계만 보고하고 전체 합계는 null로 둡니다. 실제 공급자의 모델·식별자·사용량 필드를 규약에 매핑하는 일은 후속 어댑터 검증으로 남깁니다.

**합의와 차이** C의 필수 식별자 제안은 D의 반론을 받아 응답을 받지 못한 호출에서 null을 허용하는 것으로 조정했다. B는 형식 오류도 응답 수신으로 보존하도록 요구했다. E는 내용 대조와 실제 호출 인증의 경계를 강조했다. 추가 산출물은 호출 기록 대조기 하나이며, 점수 상승에는 합의하지 않았다.

## 적용한 변경

[audit_provider_calls_v3.py](../scripts/audit_provider_calls_v3.py)를 추가했다. 입력 JSON 묶음은 `plan`, `episodes`, `receipts`를 포함한다.

```sh
python3 scripts/audit_provider_calls_v3.py bundle.json
```

계획에는 `provider_config`로 공급자 이름, 요청할 모델 스냅샷, 생성 설정을 선언한다. 이 설정까지 포함한 계획 해시를 사용해야 하므로 새 규약 적용은 기존 고정 실행 디렉터리를 수정하는 대신 새 계획으로 시작한다. 대조기는 기존 에피소드 재생·계획 검사를 먼저 수행한다.

| 호출 기록 항목 | 대조 기준 |
|---|---|
| `turn_id`, `evidence`, `plan_sha256` | 기록된 턴과 일대일 대응, 계획 근거 수준·전체 내용 일치 |
| `request_sha256` | 해당 턴 메시지와 선언한 생성 설정의 결합 해시 |
| `provider_request_id`, `response_id` | 반환 응답에는 필수, 같은 묶음에서 재사용 거부. 전송 오류에는 null 허용 |
| `outcome`, `raw_response` | 반환·처리 불명 상태를 구분하고 엔진에 전달된 원본과 일치 |
| `reported_model` | 반환 응답에는 요청한 스냅샷과 일치. 어댑터가 확인해야 할 계약 |
| `usage` | 보고된 입력·출력 토큰 수 또는 null. 음수·불리언 카운터 거부 |

요청 해시는 실제 공급자 요청 본문을 캡처했다는 뜻이 아니다. 이번 검사에서는 에피소드 메시지와 선언한 설정을 대조한다. 실제 전송 본문과의 일치 확인, 공급자 원본 응답 봉투 보존과 진위 확인은 후속 작업이다. 규약은 기존 실행기·수집기에 자동 저장되도록 통합하지 않았으며 별도 JSON 묶음을 검사한다.

순서를 뒤집은 호출 기록도 동일하게 집계됐다. 시간 초과 에피소드와 그 호출 기록을 함께 제외한 검사에서는 계획상 누락 시행이 남았으며, 남은 8개 알려진 카운터의 합계만 계산됐다.
