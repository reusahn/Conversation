## 쟁점

## 가상 A~E 토론

- **A · HCI 교수** — 준비한 실행 ID마다 최초 응답을 남겨야 합니다. 그래야 나중에 발화와 엔진 판정의 차이를 어떤 시도에서 봤는지 확인할 수 있습니다.
- **B · 게임 연구 교수 → A** — 형식 오류나 불법 행동을 재생성하면 처음의 선택 기록이 달라집니다. 이미 정한 대로 전송 실패라고 명시된 경우에만 한 번 다시 보내죠. 게임에서 플레이어가 설정을 고쳐 다시 시도하는 것과 호출 재시도는 별개입니다.
- **C · AI 교수 → B** — 요청마다 별도 어댑터 프로세스를 호출하고, 계획 해시·모델 설정·어댑터 명령을 기록하겠습니다. 호출 직전 진행 중인 ID를 저장하면 응답 수신 여부를 모르는 상황에서 자동으로 다시 보내는 일을 막을 수 있습니다.
- **D · 심리학 교수 → C** — 호출이 끊긴 지점을 알아도, 공급자에서 이미 생성했는지 모르면 재실행 판단을 보류해야 합니다. 오류도 유효 비전달과 별도로 남겨 기존 민감도 집계에 포함합시다.
- **E · 학술대회 심사자 → A~D** — C의 재개 방식은 합성 어댑터에서 확인하고, D가 말한 공급자 응답은 별도 확인 항목으로 두죠. 공개 기록에는 명령과 출력의 구조만 기록하고 실제 자격 증명이나 원본 응답 파일은 올리지 않습니다.

**합의와 차이.** A는 행동 근거의 추적을, B와 D는 재실행이 최초 행동을 바꾸지 않는 기준을 우선했다. C와 E는 애매한 호출을 자동 완료 처리하지 않고 정합성을 확인한 후 재개하는 방식에 합의했다. 본 게임은 시나리오별 최대 인원 내에서 자유롭게 인물을 쓰고, 대화와 엔진 행동을 관찰해 수정·재도전한다. 이번 작업은 기존 두 인물 탈출 과제의 첫 선택 파일럿에만 적용한다.

## 실제 변경과 검증

[파일럿 실행기](../scripts/run_handoff_pilot.py)를 추가했다. 고정 요청을 순서대로 어댑터에 보내고 기존 집계기가 읽는 시행 원장을 작성한다. 어댑터는 요청 하나를 표준입력으로 받아 모델 원문을 표준출력으로 반환한다. 명시적인 재시도 가능 전송 오류에는 종료 코드 75를 사용한다. 다른 종료 오류와 시간 초과는 진행 중인 호출의 대조가 필요하다. 어댑터 명령이나 설정이 바뀌면 재개를 거부한다. 명령이 같아도 외부 어댑터 구현이나 가중치가 바뀔 수 있으므로 실제 실행에서는 그 버전도 별도로 고정해야 한다.

합성 어댑터에서 첫 전송 실패 직후 정상적으로 일시 중단했고, 재개 후 **80개 시행 ID, 81회 호출, 유효 행동 79건, 형식 오류 1건**을 확인했다. 완료 원장을 다시 실행한 결과와 별도로 기존 집계기에 입력한 결과가 일치했다. 바뀐 명령과 처리 여부가 불명확한 호출의 자동 재개는 거부됐다. 기존 요청 생성기와 집계기의 합성 검사도 통과했다.

실제 모델 호출은 0건이다. 인증된 모델 어댑터와 고정 버전이 이 실행 환경에서 확인되지 않았다. 합성 행동은 집계 확인용이며 모델 행동이나 참가자의 재미·학습에 대한 근거가 없다. 외부 문헌 주장을 추가하지 않았다.
